# Lesson 5.2: The packages pages in the administration

**Setup** > **Packages** shows every package of every repository, explains what each carries and protects the
packages new installations are built from. This lesson is a guided tour: the overview, the repositories, the search,
a package's page and its actions. Nothing in the tour changes the site until a button is pressed, and the exercise
presses only safe ones.

## Learning objectives

After this lesson, learners can:

- read the overview figures and the repository tiles of **Packages**;
- find packages by search, repository, type and state, and bookmark the result;
- read a package's page: details, what it carries, its files;
- explain why a package is marked **Installer source**;
- explain that removing a package deletes its directory and does not uninstall it.

## Trainer's notes

### How to present it

Source: [Packages: what they carry, where they live, and how to handle them safely](../../../../guides/packages.md).
The labels below are those of the admin4 design.

1. **The list** (5 minutes). **Setup** > **Packages** (`/package/list`): the page intro, the **Overview** (packages,
   installed, not installed, imported only, installer sources, total size and files, unreadable), the
   **Repositories** tiles (the installer's repository is marked "Setup wizard's repository"), **Find packages** and
   **All packages**. **Apply** turns the search into the page address, so it can be bookmarked.
2. **Installer sources** (3 minutes). A package is an installer source when it is in the setup wizard's repository,
   when it is a site package, or when an installer source requires it. Removing one needs an extra confirmation box.
3. **A package's page** (5 minutes). Open `sevenx_multisite`: the title row (version, type, state, **Installer
   source**), the actions (here **Download**, **Download as JSON**, **Validate**, **Remove**), the notice that a site
   package with the install type "import" has nothing to install on its own, **Details**, **What it carries**,
   **Changelog** and **Package contents**, a paged file browser where each file can be viewed or downloaded.
4. **Removing** (2 minutes). The confirmation lists what goes. The directory is deleted with everything in it; what
   the package installed stays. Each removal is recorded in the audit trail as `system.package.remove`. Download a
   package first to keep a copy.

### Common questions

**Who may see and use these pages?** Each action has its policy: `package/list`, `package/read`, `package/export`,
`package/import`, `package/install`, `package/remove` and `package/create`, most of them limited by type. Buttons
your role does not allow are greyed out or not shown.

**What does Validate check?** The same as an upload: each document well formed, the JSON documents against their
schema and the checksums of a JSON package. It shows what was checked, or every problem.

**What is "N directories without a package definition"?** Leftovers of exports or wizards that ended early; nothing
reads them, and the list does not show them.

**Why is a package missing from the list?** Its `package.xml` cannot be read, or names another package than its
directory; a warning above the list names the directory.

### Pitfalls

- **Pressing Remove to "clean up".** Never on an installer source, and never on a shared training server. The
  exercise does not remove anything.
- **Expecting Install on a site package.** There is none; the page explains why.
- **Large packages.** The file browser pages its list; use the type filter and the path search.

## Hands-on exercise

Use your training installation and an administrator account. Do not press **Remove** or **Install** in this lesson.

1. Open **Setup** > **Packages**. Note the figures under **Overview**.
2. Under **Repositories**, find the tile marked "Setup wizard's repository" and note its counts and installer
   sources.
3. Under **Find packages**, choose the **Repository** `7x` and press **Apply**. Copy the page address: it carries
   the choice.
4. Change **Type** to `site` (or search `site`) and press **Apply**. Which package remains?
5. Open the card of `sevenx_multisite` with **View**.
6. Read **Details**: license, maintainers, requirements (**Requires**), **Required by** and the Exponential version it
   was made for.
7. Read the notice about the install type and the three reasons it is an installer source.
8. In **What it carries**, open **Settings files** and compare with lesson 5.1, step 4.
9. In **Package contents**, set **Type** to "Package definition" and **View** `package.xml`.
10. Press **Validate** and read the result.
11. Press **Download** and save the `.ezpkg` file. Note its name and size.

## Expected result

- Step 3: the address ends in the repository, for example `/package/list/7x`, and lists only that repository.
- Step 4: `sevenx_multisite` (and any other site package of the repository).
- Step 7: in the setup wizard's repository; a site package the setup wizard offers; and, where applicable, required by
  another installer source.
- Step 10: the validation passes and lists what was checked.
- Step 11: a file `sevenx_multisite-<version>.ezpkg`; the package itself was only read.
- The trainer checks step 10 on the projector.

## Quiz

1. Name the three reasons a package is an installer source.
2. You remove a package that was installed. What happens to the classes it created?
   A. They are removed B. They stay C. They are hidden D. They move to the trash
3. Which policy lets a user download a package?
4. Why does `sevenx_multisite` have no **Install** button?
5. Where is a package removal recorded?

<details>
<summary>Answers</summary>

1. It is in the setup wizard's repository (`7x`); it is a site package the setup wizard offers; an installer source
   requires it ([Packages, 4. Installer sources](../../../../guides/packages.md#4-installer-sources)).
2. **B.** Removing deletes the package's directory; what it installed stays.
3. `package/export`.
4. Its install type is "import": a site package is imported by the setup wizard with the packages it requires and is
   not installed on its own.
5. In the audit trail, as `system.package.remove`.

</details>
