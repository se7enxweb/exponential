# Lesson 6.3: Collecting feedback

A course gets better each time it is run, if the trainer asks and listens. Good feedback needs only three questions
and no personal data. This lesson shows how to collect it and how to turn it into changes, including fixes to the
help pages themselves.

## Learning objectives

After this lesson, learners can:

- collect feedback with three questions and no personal data;
- sort feedback into course changes, help fixes and product reports;
- send a help fix or a report to the right place;
- close the loop by telling the next group what changed.

## Trainer's notes

### How to present it

1. The three questions (3 minutes): what worked, what was hard, what next. The advocates' workshop notes use the same
   three.
2. Anonymous by default (2 minutes): paper slips or a form without names.
3. Sorting (5 minutes): "the exercise was too long" is a course change; "the help page is wrong" is a help fix
   (lesson 3.5); "the button does not work" is a product report (the **Report an error** page).

### Common questions

**Should I ask for a rating?** A rating says little. Free text answers to the three questions say more.

**How do I handle harsh feedback?** Look for the fact in it; thank the group.

### Pitfalls

- **Collecting names.** Not needed.
- **Collecting and doing nothing.** Pick at least one change per course.

## Hands-on exercise

1. Write a feedback slip with the three questions.
2. Use these invented answers and sort each into course change, help fix or product report:
   - "Lesson 2.3 took twice as long as planned."
   - "A help page called a button **Save**, but my screen showed **Store draft**."
   - "The page showed an error reference after I uploaded an image."
3. For the help fix, write the one-sentence description you would put into a pull request.
4. For the product report, list what you would include (version, steps, expected, actual, reference).
5. Write the sentence you will say at the start of the next course about what changed.

## Expected result

- A three-question slip without names.
- The three answers sorted correctly (course change, help fix, product report).
- A pull request description and a report outline.

## Quiz

1. Name the three feedback questions.
2. Is "the help names the wrong button" a course change, a help fix or a product report?
3. Why collect feedback without names?
4. What closes the feedback loop?

<details>
<summary>Answers</summary>

1. What worked, what was hard, what next ([Hands-on workshop outline](../../../advocates/hands-on-workshop-outline.md)).
2. A help fix.
3. Names are not needed, and anonymous answers are more honest.
4. Telling the next group what changed because of feedback.

</details>
