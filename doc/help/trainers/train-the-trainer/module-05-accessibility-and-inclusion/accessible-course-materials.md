# Lesson 5.1: Accessible course materials

A course is only as accessible as its handouts. A learner with a screen reader cannot read a screenshot of a
command; a learner with low vision cannot read grey text on a light slide. This lesson applies simple rules to
slides, handouts and exercises, and shows which material Exponential already provides in accessible form.

## Learning objectives

After this lesson, learners can:

- apply five rules to slides: real text, contrast, large fonts, alt text, no meaning by color alone;
- write commands and code as text, never as pictures;
- use help pages and their PDFs as handouts with headings and selectable text;
- check a handout with a screen reader or the document's outline.

## Trainer's notes

### How to present it

1. Walk through [Accessible slides and visuals](../../../advocates/accessible-slides-and-visuals.md) (8 minutes):
   slides, images and screenshots, code on slides, diagrams and charts, the checklist.
2. Show the help as a handout (4 minutes): every help page has headings, a table of contents, and **Download as
   PDF**; with a TrueType font the PDF's text can be selected and searched, and headings become links.
3. Mention the standard (3 minutes): [Accessibility standards](../../../../standards/accessibility.md) lists how
   Exponential measures up against WCAG 2.2 AA and names its gaps honestly.

### Common questions

**Are screenshots forbidden?** No. Add alt text that says what matters in the picture, and never put a command only
in a screenshot.

**Is the administration accessible?** The Admin 4 design was built and tested against WCAG 2.2 AA criteria; the
standards page lists what is partly compliant and what is unverified. Teach in Admin 4 where you can.

### Pitfalls

- **Pictures of text.** Commands in images cannot be copied or read aloud.
- **Color only.** "Click the red button" fails for color-blind learners; use the label.
- **Tiny code.** Code on slides needs a large monospace font.

## Hands-on exercise

1. Take one lesson of this course and make a two-page handout from it.
2. Check: every command is text; every image has alt text; headings are real headings; contrast is high.
3. Download the same lesson with **Download as PDF** in the Help center and compare: does the PDF have headings,
   selectable text and the license notice?
4. Read your handout with a screen reader (or your system's read-aloud feature) for one minute. Note anything that
   was skipped or confusing.
5. Fix what you found.

## Expected result

- A two-page handout where every command is text, every image has alt text and the heading outline makes sense.
- Notes from the read-aloud test with fixes applied.

## Quiz

1. Why must commands never appear only in a screenshot?
2. Which WCAG version and level does the Admin 4 design target?
3. What does a good alt text for a screenshot say?
4. Name one problem with "click the green button".

<details>
<summary>Answers</summary>

1. They cannot be copied or read by a screen reader.
2. WCAG 2.2, level AA ([Accessibility standards](../../../../standards/accessibility.md)).
3. What matters in the picture for the task, not every pixel.
4. It relies on color alone; use the button's label.

</details>
