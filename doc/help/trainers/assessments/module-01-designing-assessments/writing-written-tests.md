# Lesson 1.2: Writing written tests with a sourced answer key

A written test checks what a learner knows and understands. In these courses every answer in the key names the help
page that proves it, so a learner who disagrees can look it up, and the trainer can show where the answer comes from.
This lesson shows how to write such a test, and how the tests in Modules 2 to 5 are built.

> **Note**
> The tests in this course are the trainer's own material, not an official certification. Adapt them to the version
> and the site package you teach.

## Learning objectives

After this lesson, learners can:

- write a multiple choice question with one correct answer and plausible wrong answers;
- write a short answer question with a clear expected answer and acceptable variants;
- cite, for every answer, the help page (and where possible the section) that proves it;
- put the answer key in the folded **Answers** block of a help page, or on a separate sheet for a printed test.

## Trainer's notes

### How to present it

1. **Question types** (4 minutes).
   - **Multiple choice**, four options A to D, one correct. Fast to score, good for facts and distinctions.
   - **Short answer**, one sentence or a command. Good for "why" and "what happens when".
   - **True or false** only with a reason ("True or false, and why?"), or a guess earns half the points.
2. **Good wrong answers** (4 minutes). Each wrong option is a real misunderstanding seen in class: "Discard draft
   deletes the article" is a better distractor than a joke. Keep options the same length and form.
3. **The source** (4 minutes). Write the answer, then the page that proves it. If you cannot find a page, the question
   tests your memory, not the documentation: rewrite it or cut it. Prefer a link to the section
   (`editing-content.md#when-someone-else-is-editing`) over the whole page.
4. **Layout** (3 minutes). On a help page, the key goes in the folded block, as in every lesson of these courses. On
   paper, give the questions on one sheet and keep the key on another. Show the key only after collecting the tests.

### Common questions

**How many questions?** Ten to fifteen for a course of one to four days, about one minute per multiple choice
question and two to three minutes per short answer. The tests in this course have twelve to fourteen questions.

**Can learners use the help during the test?** Decide it in the rules ([Lesson 1.1](designing-fair-assessments.md)).
If they can, ask for understanding: "Why does approved content stay unpublished?" rather than "What is the setting
called?".

**What about other languages?** Write simple sentences, avoid idioms, and allow a dictionary. See
[Lesson 1.4](accommodations-in-assessment.md).

### Pitfalls

- **Negative questions** ("Which is NOT ..."). If you need one, put NOT in bold.
- **"All of the above".** It rewards partial knowledge. Avoid it.
- **Answers from memory of the class.** "What did the trainer show first?" is not a skill.
- **Version drift.** A key written for one release can be wrong for the next. Check every cited page again before
  each course.

## Hands-on exercise

Write four questions on the lesson [Publishing, versions and the trash](../../../publishing-and-versions.md).

1. Read the page once, fully.
2. Write one multiple choice question about the four version states (**Draft**, **Pending**, **Published**,
   **Archived**), with three wrong answers taken from real misunderstandings.
3. Write one short answer question about what happens to a removed item.
4. Write one "true or false, and why" question about **Discard draft**.
5. Write one question that needs two facts together, for example removing an item that has two locations.
6. Write the key: for each answer, one sentence and a link to the section that proves it.
7. Give your four questions, without the key, to a neighbor. Time how long they need.
8. Compare their answers with your key. Where they gave a different answer that is also right, improve the question.

## Expected result

- Four questions of three types and a key in which each answer cites a section of the page.
- At least one question was improved after the neighbor's attempt.
- The trainer collects one set and reads one distractor aloud: the group says which misunderstanding it targets.

## Quiz

1. What should every answer in the key contain besides the answer itself?
2. Which wrong option is better for a question on **Discard draft**? A. "It sends the item to a printer" B. "It
   deletes the published item" C. "It does nothing" D. "It changes the language"
3. Why should a true or false question also ask for a reason?
4. Where do you keep the key of a printed test while learners write?
5. What do you do with a question for which you cannot find a page in the help?

<details>
<summary>Answers</summary>

1. A citation of the help page, ideally the section, that proves it
   ([Quizzes and practical tasks](../../train-the-trainer/module-06-assessment-and-follow-up/quizzes-and-practical-tasks.md)).
2. **B.** It is a real misunderstanding; the draft is thrown away and the published version stays
   ([Publishing, versions and the trash](../../../publishing-and-versions.md#publish)).
3. A guess is right half of the time; the reason shows understanding.
4. On a separate sheet, shown only after the tests are collected.
5. Rewrite it so that it tests something documented, or cut it.

</details>
