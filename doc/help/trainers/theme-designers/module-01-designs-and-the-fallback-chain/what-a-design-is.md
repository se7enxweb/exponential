# Lesson 1.1: What a design is and where it lives

Everything a visitor sees comes out of a **design**: a directory of templates, stylesheets, scripts and images. Before
learners change a single line, they need to know what a design looks like on disk, where Exponential looks for it, and
which designs they must never edit. This lesson is the map for the whole course.

> **Note** Use a training installation, never a live site. Every exercise in this course writes files.

## Learning objectives

After this lesson, learners can:

- name the five folders of a design and what each holds;
- list the design directories of an installation, in `design/` and in extensions;
- explain how an extension declares that it carries a design (`DesignExtensions[]`);
- explain why the `standard` design and shipped themes are never edited in place.

## Trainer's notes

### How to present it

Source: [Templates and design, part 1](../../../../guides/templates-and-design.md#1-how-a-template-is-found) and
[Designs, siteaccesses and the design fallback chain](../../../creators/website-creators/designs-and-the-fallback-chain.md).

1. **One sentence first** (2 minutes). A design is a directory; a siteaccess uses a chain of designs; the first file
   found in the chain wins. Write it on the board and come back to it in every lesson of this module.
2. **The five folders** (5 minutes). Open `design/admin4/` on the projector. A design can hold:

   | Folder | Holds |
   |---|---|
   | `templates/` | the `.tpl` files, for example `pagelayout.tpl` and `node/view/full.tpl` |
   | `override/templates/` | templates that replace others when an `override.ini` rule matches |
   | `stylesheets/` | CSS files |
   | `javascript/` | script files |
   | `images/` | images that templates find with `ezimage` |

   Not every design has all five, and some have more (several designs carry a `fonts/` folder). `design/plain/` has
   only `images/` and `templates/`, and `design/standard/` has no `override/` folder: a design only holds what it
   needs or what differs from the designs behind it.
3. **Two places** (5 minutes). Designs live in `design/<name>/` of the installation, and in
   `extension/<ext>/design/<name>/`. An extension's design folder is only searched when the extension says so in its
   `settings/design.ini.append.php`:

   ```ini
   [ExtensionSettings]
   DesignExtensions[]=<ext>
   ```

   The same design name may exist in several places; the chain decides which file wins (lesson 1.2).
4. **What you never edit** (4 minutes). `design/standard/` is the last fallback; its pagelayout starts with
   `{* DO NOT EDIT THIS FILE! Use an override template instead. *}`. A theme shipped as an extension is updated by
   its maintainers; a change made in place is lost at the next update. Learners will build their own design
   extension in module 2.
5. **The admin side** (4 minutes). Point at `design/admin`, `design/admin3`, `design/admin4` and `design/admin4l`:
   designs of the administration, not of the public site. Lesson 1.4 covers them.

### Common questions

**Is a "theme" the same as a "design"?** In this course a *theme* is a design packaged for others, usually as an
extension with settings, images and documentation. The kernel only knows designs.

**Why are templates split between `templates/` and `override/templates/`?** A file in `templates/` replaces the file
of the same path further down the chain, for every page. A file in `override/templates/` is used only when a rule in
`override.ini` matches (a class, a node, a section ...). Lesson 2.3 covers overrides.

**Can a design hold PHP?** No. Template operators and other PHP belong in the extension around it (`autoloads/`,
`classes/`), not in the design folder.

### Pitfalls

- **Learners edit `design/standard/`.** It works, until the next upgrade. Stop it in the first hour; the exercise
  below only reads.
- **A design folder that is never searched.** An extension that has a `design/` folder but no `DesignExtensions[]`
  entry contributes nothing. Learners meet this again in module 7.
- **Confusing the admin designs with site designs.** Ask learners to name, for each folder they find, whether it is
  for visitors or for editors.

## Hands-on exercise

Use your own training installation (for example installed with `php bin/php/console exp:install`, see
[7. The console install](../../../../install/07-console-install.md)). Work in the installation root, the directory
that holds `index.php`. Nothing in this exercise changes a file.

1. List the designs of the installation: `ls design/`.
2. For `design/standard/`, `design/plain/` and `design/admin4/`, list the top folders (`ls design/standard/`).
   Note which of the five folders each one has.
3. Open `design/standard/templates/pagelayout.tpl` in an editor and read the first line.
4. Find the extensions that carry a design folder: `ls -d extension/*/design/*`.
5. Pick one of them and open its `settings/design.ini.append.php`. Find the `DesignExtensions[]` line.
6. List every file that declares a design extension, as the installation sees it for one siteaccess (replace
   `<site>` with a folder name from `settings/siteaccess/`):

   ```bash
   php bin/php/console exp:ini where design/ExtensionSettings/DesignExtensions <site>
   ```

7. Count the entries in the output and compare with step 4.
8. On a sheet, draw two columns, "for visitors" and "for the administration", and sort every design name you found
   into one of them.

## Expected result

- Step 2: `design/admin4/` has all five folders (and `fonts/`), `design/standard/` every one except `override/`,
  `design/plain/` only `images/` and `templates/`.
- Step 3: the line is `{* DO NOT EDIT THIS FILE! Use an override template instead. *}`.
- Step 6: the output lists `settings/design.ini` first (`DesignExtensions[]`, the empty reset line), then one
  `extension/<ext>/settings/design.ini.append.php` per design extension, each with `scope extension:<ext>`.
- The trainer checks the sheet: `admin`, `admin3`, `admin4`, `admin4l` and `editor` are on the administration side;
  `standard`, `base` and `plain` on the visitor side, `standard` marked as the fallback for both.

## Quiz

1. Which folder of a design holds templates used only when a rule in `override.ini` matches?
   A. `templates/` B. `override/templates/` C. `stylesheets/` D. `javascript/`
2. What does an extension need so that its `design/` folder is searched?
3. True or false: every design must contain all five folders.
4. Why do you not edit `design/standard/templates/pagelayout.tpl`?
5. Where does an image found with `{'logo.png'|ezimage}` live?

<details>
<summary>Answers</summary>

1. **B.** `override/templates/` is read when an `override.ini` rule matches
   ([Templates and design](../../../../guides/templates-and-design.md#4-make-a-change-with-an-override)).
2. A `DesignExtensions[]=<ext>` line in its `settings/design.ini.append.php`.
3. **False.** A design holds only what it needs; `design/plain/` has two folders, `design/standard/` no `override/`.
4. It is the last fallback of every siteaccess and is replaced on upgrade; the file itself says to use an override.
5. In the `images/` folder of a design in the siteaccess's chain.

</details>
