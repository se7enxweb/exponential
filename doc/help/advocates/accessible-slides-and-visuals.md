# Accessible slides and visuals

This page is for advocates who make slides, diagrams, screenshots and social media images. Exponential's administration
is built and tested for accessibility ([Talking points: accessibility](talking-points-accessibility.md)); material
about it should meet the same bar. Accessible material also works better for everyone: in bright rooms, on small
phones and for people reading in a second language.

## Slides

- **Large text**: about 24 points or more for body text; one idea per slide.
- **Contrast**: dark text on a light background or the reverse; the administration's own rule for text is a contrast of
  at least 4.5:1 ([Styling the administration](../../bc/6.0/admin4-styling.md)), a good target for slides too.
- **Fonts**: plain sans-serif fonts; no text over busy photos.
- **Do not rely on color**: "the red one" means nothing to a color-blind viewer; add a label.
- **Slide titles**: every slide has a real title; screen readers and outlines use it.
- **Reading order**: if you share the file, check that a screen reader reads the slide in the right order.
- **Motion**: avoid flashing and fast animations.
- **Share the slides** as an accessible file (tagged PDF or the source) and the speaker notes as text.

## Images and screenshots

- **Alternative text** for every image that carries information: what it shows and why it matters, for example
  "The layouts editor with a Title block being dragged into the main zone".
- **Decorative images** get empty alternative text where the tool allows it.
- **Crop** to what matters; enlarge the part you talk about.
- **No personal data**: invented names and content only ([Protecting people's privacy](protecting-peoples-privacy.md)).
- **No secrets**: no keys, passwords, server addresses or settings files ([Live demo safety](live-demo-safety.md)).
- **Light and dark**: if you show both modes, label them.
- **Say the version** in the caption: "Exponential 6.0.15, admin4 design".

## Code on slides

- At most about 10 lines, large monospace font, high contrast.
- Highlight the important line in a way that does not depend on color only (an arrow, bold, a box).
- Put the full, copyable code in a linked page or the speaker notes; nobody can copy from a projector.
- Make it real: commands that exist, like those in [Install in one command](../../features/6.0/install-in-one-command.md).

## Diagrams and charts

- Label every box and arrow with words.
- Describe the diagram in one or two sentences in the alternative text or below it.
- Charts: only with real, sourced numbers, with the date and the source on the slide
  ([Claims you must not make](claims-you-must-not-make.md)).

## Social media images

- Put the essential text in the post, not only in the image.
- Add alternative text where the platform allows it.
- Use the product names correctly ([Naming rules quick card](naming-rules-quick-card.md)).
- Do not use logos in ways the owners have not allowed; the sources set no logo rules for third parties
  ([Brand and naming rules, What the sources do not decide](../business/brand-and-naming-rules.md#what-the-sources-do-not-decide)).

## Checklist

```text
[ ] Body text large enough; one idea per slide; every slide has a title
[ ] Contrast checked; nothing depends on color alone
[ ] Every informative image has alternative text; decorative ones are marked
[ ] Screenshots: invented data only, no secrets, version in the caption
[ ] Code: short, large, real; full version linked
[ ] Diagrams labeled and described
[ ] No flashing; animations optional
[ ] Shared file is accessible (titles, reading order); notes available as text
[ ] Videos captioned, with a transcript
```
