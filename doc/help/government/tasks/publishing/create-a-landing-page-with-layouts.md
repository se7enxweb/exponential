# Create a landing page with layouts

This page is for editors who build a landing page for a campaign, a topic or a program with **Exponential Layouts**.
A layout decides what a page is made of; content items still hold the text and images. The **Layouts** tab is shown
only to roles that may work with layouts ([The layouts editor](../../../layouts-editor.md)).

## Contents

1. [Before you start](#before-you-start)
2. [Steps](#steps)
3. [Check the result](#check-the-result)

## Before you start

- You see the **Layouts** tab; if not, ask an administrator.
- The page the layout is for exists (for example a folder "Clean air campaign").
- Texts and images are ready, images with alternative text.
- Mappings decide which pages use a layout; if you may not change them, a site builder adds the mapping.

## Steps

1. **Layouts** opens the **Layouts Dashboard**. Press **New layout**.
2. Choose a **Layout type** (for example *1 column* or *Hero + 3 columns*), give a **Name** ("Clean air campaign"),
   press **Create layout**. The editor opens with the empty zones.
3. Press **Add a block** (the plus button) and drag blocks into the zones: a **Title**, a **Text** or **Rich text**, an
   **Image**, a **Listing** block that shows the latest items of a folder, a **Button / Link** to the main action.
4. Select each block; fill its **Content** tab (texts, which items a list shows, how many) and its **Design** tab
   (view type, style).
5. **Publish layout** (or **Save draft and close** to continue later).
6. Mapping: on the dashboard, **Rules**, **New mapping**: the layout, the target (the page's location), enabled. Or
   ask the site builder.
7. If the editor asks whether to clear caches, choose **Clear caches**.

## Check the result

- [ ] Signed out, the page shows the layout.
- [ ] Headings come in order (one main heading, then sub-headings); the page works with a keyboard.
- [ ] On a phone width, blocks stack in a sensible order.
- [ ] Lists show the expected items.

## Pitfalls

| Pitfall | Avoid it |
|---|---|
| Text typed only in blocks, not in content items | search may not find block text as it finds content; keep key text in the page's own content too |
| A mapping that matches more pages than intended | targets and conditions decide; the first enabled mapping by priority wins |
| Many large images | slow pages; use a few, well chosen |
| Editing a shared layout (header, footer) by mistake | it changes every page that links to it |
