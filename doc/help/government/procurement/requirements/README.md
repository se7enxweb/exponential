# Requirements for a public-sector CMS

This section is for procurement officers, project managers and subject experts who write the requirements of a
tender for a web content management system. Each page gives requirement wording you can adapt, explains what makes
it verifiable, and names the Exponential documentation that answers it, with the status words of the
[standards pages](../../../../standards/README.md) and the gaps they list. The clause texts that go into the contract
itself are in the [tender templates](../tender-templates/README.md).

## Reading order

1. Start with [How to write verifiable requirements](how-to-write-verifiable-requirements.md).
2. Write the functional requirements, then the quality areas: accessibility, security, privacy, languages.
3. Add the service areas: hosting, operations, support, records.
4. Finish with licensing and exit, which protect you for the whole life of the contract.
5. Before publishing the tender, check every requirement against
   [Mapping requirements to evidence](mapping-requirements-to-evidence.md) and
   [What Exponential can and cannot evidence](what-exponential-can-and-cannot-evidence.md), so that no "must" excludes
   every honest bidder.

## Conventions on these pages

- Requirement identifiers (`ACC-01`, `SEC-03` ...) are examples; renumber them for your tender.
- Values in angle brackets (`<time>`, `<country>`) are yours to fill. This help never suggests figures.
- Status words (Complies, Partly complies, Unverified, Does not comply) are copied from the standards pages and must
  not be upgraded.
