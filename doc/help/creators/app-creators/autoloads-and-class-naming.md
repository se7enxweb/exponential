# Autoloads and class naming

This page is for application creators who add PHP classes. Exponential finds classes through generated class maps;
a class that is not in the map does not exist as far as the application is concerned.

## The class maps

| Map | Covers | Made by |
|---|---|---|
| `autoload/ezp_kernel.php` | kernel classes | shipped; regenerated by kernel developers |
| `autoload/ezp_extension.php` | classes of every extension | `php bin/php/ezpgenerateautoloads.php -e` |
| Composer's autoloader | `vendor/` libraries | `composer install` |

The generator scans the extension directories (including `AdditionalExtensionDirectories[]`) for PHP files and lists
each class with its file ([10.7 Class autoloads](../../../install/10-after-installing.md#107-class-autoloads)).

## Regenerating

```bash
php bin/php/ezpgenerateautoloads.php -e
```

Run it after adding, renaming or moving a class. Under Velocity, workers keep the map they started with: restart them
(`exp:velocity deploy` regenerates and restarts in order). A new class that settings name (a handler, a datatype) must be
deployed before the setting that uses it goes live.

## Naming

- New classes start with `exp` and the extension's name: `expDemoList`, `expDemoListService`.
- One class per file; file name in lower case: `classes/expdemolist.php`.
- Never reuse a kernel name (`eZ...`) for a new class; never rename an existing kernel identifier.

See [Layering and naming](../../../standards/architecture/layering-and-naming.md) and
[Coding standards](../../../standards/coding-standards.md).

## Namespaced classes

Runnable classes (commands, cronjob parts, module views) use namespaces: `Exponential\Command\Extension\<Ext>\<Name>`,
`Exponential\Cronjob\Extension\<Ext>\<Name>`, `Exponential\View\Extension\<Ext>\<Module>\<View>`, in
`extension/<ext>/classes/runnable/...` ([Commands, cronjob parts and module views as classes](../../../bc/6.0/cli_cronjob_view_abstractions.md)).
The generator maps them like any class.

## Composer libraries

An extension that needs a library declares it in its own `composer.json`; the installation's Composer installs it into
`vendor/`. Do not ship `vendor/` inside the extension (Composer packages and Packagist).

## When a class is not found

| Symptom | Cause | Fix |
|---|---|---|
| `Class "expDemoList" not found` | map not regenerated | `ezpgenerateautoloads.php -e` |
| Works under Apache, fails under Velocity | workers started before the class existed | `exp:velocity restart` |
| A setting names a class and the site breaks | the class was deployed after the setting | deploy code first; guard with `class_exists()` where a missing class must not break pages |
| The generator warns about a duplicate | two files declare the same class | rename one |
