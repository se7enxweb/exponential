# site.ini [SiteAccessRules]

The block `[SiteAccessRules]` of `settings/site.ini`, with 2 setting(s).

> If you disable some modules or part of a module you can use the  
> SiteAccessRules group, this defines a list of rules which are  
> run in order.  
>
> The following is an example of how to disable content/search  
> and the rss module  

Never edit `settings/site.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/site.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/site.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/site.ini.append.php` in an extension (read when the extension is active).

## Rules

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[SiteAccessRules]
# an empty "Rules[]" first replaces the shipped list; without it the items are added
Rules[]
*/ ?>
```

## DisabledModuleResult

> What a module switched off by the rules answers: notfound (the page of a  
> module that does not exist, 404, so nothing tells that it is there) or  
> disabled (the "disabled" page, error 22).  

Default: `notfound`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[SiteAccessRules]
DisabledModuleResult=notfound
*/ ?>
```
