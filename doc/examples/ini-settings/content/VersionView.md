# content.ini [VersionView]

The block `[VersionView]` of `settings/content.ini`, with 2 setting(s).

Never edit `settings/content.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/content.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/content.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/content.ini.append.php` in an extension (read when the extension is active).

## AvailableSiteDesignList

> OBSOLETE: Use AvailableSiteDesignList instead  
> Specify all available site designs  
> AvailableSiteDesigns=standard;user;admin;demo  
> OBSOLETE: A list of designs the site can use  

Default: a list of 1: `admin`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/content.ini.append.php
[VersionView]
# an empty "AvailableSiteDesignList[]" first replaces the shipped list; without it the items are added
AvailableSiteDesignList[]
AvailableSiteDesignList[]=admin
*/ ?>
```

## ViewModes

> AvailableSiteDesignList\[\]=base  
> The view modes a version can be shown in, content/versionview/<object>/<version>/(view\_mode)/<mode>  
> (node/view/<mode>.tpl); another one is not available. Without the parameter it is full.  
> With more than one listed, the View control box of the preview in the admin offers them.  
> design/standard has node/view/print.tpl as an example of a print layout.  

Default: a list of 1: `full`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/content.ini.append.php
[VersionView]
# an empty "ViewModes[]" first replaces the shipped list; without it the items are added
ViewModes[]
ViewModes[]=full
*/ ?>
```
