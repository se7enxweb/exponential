# Verhaltensänderungen vom 1. und 2. Oktober 2026 (Linie 6.0.15): was Sie beim Upgrade prüfen sollten

Lesen Sie diese Seite, bevor Sie eine Installation auf die Änderungen vom 1. und 2. Oktober 2026 aktualisieren. Sie ist
eine Checkliste für Betreiber und Autoren von Erweiterungen: Jeder Punkt sagt, was sich geändert hat, wie Sie es prüfen
und was zu tun ist. Die Funktionen sind auf den verlinkten Seiten beschrieben; die Geschichte des Monats steht in der
[Chronik vom Oktober 2026](../../../eng-us/history/2026/2026-10.md).

## Reihenfolge beim Bereitstellen

PHP-Klassen, INI-Dateien und Template-Pfade haben sich alle geändert. Führen Sie nach dem Übernehmen der Änderungen
Folgendes in dieser Reihenfolge aus:

```bash
php bin/php/ezpgenerateautoloads.php -e
php bin/php/ezpgenerateautoloads.php -k
php bin/php/ezcache.php --clear-all --allow-root-user
```

`-k` durchläuft die ganze Installation. Halten Sie Arbeitskopien der Installation darin, führen Sie sie in
`.autoloadignore` auf oder übergeben Sie `--exclude=<dir>`, sonst wird jede Kernel-Klasse der Kopie zugeordnet.

Dann:

1. Laden Sie das PHP-FPM neu, das die Website ausliefert.
2. Starten Sie Exponential Velocity neu, wenn Sie es verwenden. Seine Worker behalten die Klassen, die sie beim
   Vorwärmen geladen haben.
3. Leeren Sie zuletzt den Cache der Inhaltsansichten und den Antwort-Cache von Velocity.

## Audit-Protokoll

Das [Audit-Protokoll](../../../eng-us/features/6.0/audit-trail.md) ist in jeder Installation **standardmäßig
eingeschaltet** (in 4.x war es aus).

- Die Einträge gehen nach `var/<site>/log/audit/`.
- Legen Sie in einer bestehenden Installation einmal die Index-Tabellen an:
  `php update/common/scripts/6.0/createaudittables.php`
- Führen Sie die Cronjob-Gruppe `frequent` aus.
- Alte Aufrufe von `eZAudit::writeAudit()` funktionieren weiter.
- Nur die Rolle Administrator besitzt `audit/read` und `audit/manage`.

Details: [Upgrade des Audit-Protokolls](audit.md).

## Struktur des Codes

Jeder Befehl des Kernels, jeder Cronjob-Teil und jede Modul-View ist jetzt eine Klasse
([Spezifikation](../../spezifikationen/6.0/ausfuehrbare-befehle-cronjobs-ansichten.md)). Die Einstiegspunkte behalten
ihre Pfade.

- Code, der die alten Dateien wegen ihrer Logik gelesen hat, muss in `kernel/private/classes/` suchen.
- Eine Erweiterung kann eine Klasse durch eine eigene Unterklasse ersetzen:
  `site.ini [RunnableSettings] Implementation[<class>]=<subclass>`.
- `checkAccess()` von `eZContentObject`, `eZContentObjectTreeNode` und `eZContentObjectVersion` nimmt den zu
  prüfenden Benutzer als sechstes Argument an, `$userID = false` (hinzugefügt am 6. Oktober 2026). Eine Klasse, die eine
  davon überschreibt, muss es annehmen, sonst bricht PHP 8 beim Laden der Klasse mit einem fatalen Fehler ab.

## Fehlende Bibliotheken

Ein fehlendes Verzeichnis `vendor/` zeigt jetzt eine Seite mit einem Reparaturverfahren statt der rohen
Fehlerausgabe von PHP. Siehe [Reparatur aus dem Browser](../../../eng-us/features/6.0/repair-from-the-browser.md) und
[das Upgrade der Reparaturseite](reparatur.md).

Seit dem 9. Oktober 2026 lehnt `eZSOAPClient` einen Aufruf über HTTPS ab, wenn die PHP-Erweiterung curl nicht geladen
ist: `send()` gibt `0` zurück, `ErrorString` sagt, dass HTTPS die PHP-Erweiterung curl braucht, und das
Fehlerprotokoll enthält „No SOAP call to <server>: HTTPS needs the PHP extension curl, which is not loaded“. Bisher ging
ein solcher Aufruf als Klartext an den TLS-Port, den kein HTTPS-Server mit einer SOAP-Antwort beantwortet. Prüfen Sie mit
`php -m | grep curl` (und im PHP des Webservers), dass curl überall geladen ist, wo SOAP-Aufrufe über HTTPS gemacht
werden. Aufrufe über HTTP sind unverändert. Siehe [SOAP-Aufrufe über HTTPS](../../../eng-us/features/6.0/soap-client-tls.md).
