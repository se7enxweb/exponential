# Januar 2024, erste Hälfte (1. bis 15. Januar)

Was sich im Januar 2024 (1. bis 15. Januar) an Exponential geändert hat, warum es wichtig ist und wo Sie mehr lesen. Lesen Sie die Seite, wenn Sie eine Website über diesen Zeitraum hinweg aktualisieren oder wissen wollen, woher eine Funktion stammt; der [Leitfaden zur Geschichte](../README.md) erklärt, wie die Monatsseiten, das Änderungsverzeichnis und die Seite zur Abdeckung zusammenhängen.

## Kurz gesagt

- 6.0.0 wurde am 1. Januar 2024 stabil.
- SQLite kam am 7. Januar: ein Datenbanktreiber, ein Schema-Handler und eine fertige Demonstrationsdatenbank.
- Der Test mit einer zweiten Engine deckte viele Fehler mit ungeprüften Daten auf, die behoben wurden; die Liste im Papierkorb wurde sortierbar.

Die erste Januarhälfte gehört SQLite, einer Datenbank, die keinen Server braucht. Allein am 7. Januar:

- erhielt der Kernel einen Datenbanktreiber und einen Schema-Handler (`6a2e04a54d`, `5d11b34ef7`);
- kamen eine Reihe von SQL-Dateien für SQLite und eine vorgefertigte Demonstrationsdatenbank hinzu (`70b815b0d0`);
- wurde fast jede Abfrage des Kernels, die MySQL voraussetzte, so umgebaut, dass sie auf beiden Engines läuft (`6ad5d5708d`, `2a86e3c354`, `d1aa934a60`, `80532e07df`, `d74e31a30b` und die Zeilen unten);
- lernte der Setup-Assistent, SQLite anzubieten, die PHP-Erweiterung zu prüfen und zu erklären, was fehlt (`b2f295129c`, `430a12c816`, `7b4703bda9`, `3bb983581a`, `e4d54e58dc`, `e451fcb2e1`).

So nutzen Sie es: [Unterstützung für SQLite-Datenbanken](../../funktionen/6.0/sqlite-datenbank.md). So funktioniert es: die [Spezifikation des Treibers](../../spezifikationen/6.0/sqlite3-datenbanktreiber.md).

## 6.0.0 wird stabil

Am 1. Januar änderte `835ea80c81` den Versionsstatus von Beta auf stabil: **Exponential 6.0.0** ist veröffentlicht (siehe [Changelog 6.0.0](../../../changelogs/6.0/6.0.0.md)). Aus `INSTALL` wurde `INSTALL.md` mit Anleitungen für die Installation mit Composer (`7b358c1a1d`), und die Sprachangabe für GitHub lässt das Repository als PHP statt als JavaScript erscheinen (`6310558dcd`). Die nächsten Versionen wurden in derselben Woche gesetzt (`3e2e373d33`).

## Korrekturen aus den Tests mit SQLite

Die Tests auf einer zweiten Datenbank-Engine fanden Stellen, an denen der Kernel seine Daten nicht prüfte: `count()` auf Werten, die nicht zählbar waren (`6f7f898de5`, `378bfc8d5e`, `8964f26dfa`), uneinheitliche Prüfungen von Daten vor der Verwendung (`d3d3b2e157`, `d374cdd7ae`, `40b13ea95c`) und eine Funktion, die ohne Parameter aufgerufen wurde (`c73eed6cb8`). Alles sind fatale Fehler unter PHP 8, die nur darauf warteten aufzutreten; sie sind also einmal für jede Engine behoben. Siehe [Unterstützung für PHP 8](../../bc/6.0/php8.md).

## Zusammengeführte Upstream-Änderungen

Die Liste im Papierkorb mit einem sortierbaren Datum des Löschens kam mit dem Upstream-Pull-Request #31 (`fa42a6e960`, `75361f4bea`); siehe [Papierkorb](../../bc/6.0/papierkorb.md).

## Pakete und Dokumentation

Composer installiert jetzt `bcgooglesitemaps` (`d47662a8bd`), `swark`, `owsimpleoperator` und `bcwebsitestatistics`, und `ezmultiupload` wurde auf ein Release mit wichtigen Korrekturen angehoben ([Distribution](../../funktionen/6.0/standard-extension-auslieferung.md)). Die README wurde neu gegliedert und erweitert, um Neulingen zu erklären, was das Projekt ist und wie sie mitmachen (`7908cc84e7`), mit einem neuen Produktlogo (`72db74b6ea`).
