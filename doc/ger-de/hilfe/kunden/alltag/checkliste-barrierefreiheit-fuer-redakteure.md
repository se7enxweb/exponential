# Checkliste zur Barrierefreiheit für Redakteure

Diese Seite ist eine **Checkliste** für jeden Redakteur, die vor dem Klick auf **Zur Veröffentlichung schicken**
durchzugehen ist. Sie behandelt, was Redakteure beeinflussen können; die Seite der Templates ist Aufgabe Ihres
Partners ([Barrierefreiheit pflegen](barrierefreiheit-pflegen.md)). Die Regeln stammen aus
[Barrierefreiheit für Website-Ersteller](../../ersteller/website-ersteller/barrierefreiheit-fuer-website-ersteller.md) und den
Seiten der Hilfe für Redakteure.

## Bilder

- [ ] Jedes Bild, das Information trägt, hat einen **Alternativtext**, der sagt, was es zeigt
      ([Bilder, Medien und Uploads](../../medien-und-uploads.md#bewährte-vorgehensweise)).
- [ ] Der Text beginnt nicht mit „Bild von“; Screenreader sagen bereits, dass es ein Bild ist.
- [ ] Rein dekorative Bilder haben einen leeren Alternativtext, wenn Ihre Website das erlaubt.
- [ ] Text in einem Bild (ein Plakat, ein Diagramm) steht auch auf der Seite.
- [ ] Diagramme haben einen Satz, der die wichtigste Aussage nennt.

## Überschriften und Struktur

- [ ] Eine Hauptüberschrift: der Name der Seite.
- [ ] Überschriften in der richtigen Reihenfolge, ohne eine Ebene zu überspringen; für die Struktur verwendet, nicht für die Schriftgröße.
- [ ] Keine fett gesetzten Absätze, die so tun, als wären sie Überschriften
      ([Die Website an die Redaktion übergeben](../../ersteller/website-ersteller/die-website-an-die-redaktion-uebergeben.md)).
- [ ] Kurze Absätze; je ein Gedanke.

## Links

- [ ] Linktexte sagen, wohin sie führen: „Öffnungszeiten“, nicht „hier klicken“ oder „weiterlesen“.
- [ ] Ein Link auf eine Datei sagt das: „Jahresbericht (PDF)“.
- [ ] Links, die etwas Ungewöhnliches öffnen (einen Download, eine andere Website), werden im Text so benannt.
- [ ] Links auf andere Seiten der Website werden mit dem Link-Werkzeug des Editors gesetzt, nicht von Hand eingetippt.

## Listen und Tabellen

- [ ] Listen verwenden die Listen-Schaltflächen des Editors, keine eingetippten Bindestriche.
- [ ] Tabellen sind für Daten da, mit einer Kopfzeile; nie für das Layout.
- [ ] Vor einer Tabelle steht eine kurze Beschriftung oder ein Satz, der sagt, was sie zeigt.

## Sprache

- [ ] Die Seite ist in der Sprache des Siteaccess, in dem sie angezeigt wird; eine Übersetzung ist eine Übersetzung
      des Elements, kein zweites Element ([Sprachen](../../sprachen.md)).
- [ ] Wörter oder Zitate in einer anderen Sprache sind als solche gekennzeichnet, wenn Ihr Editor das anbietet.

## Dokumente, Audio und Video

- [ ] Informationen stehen auf der Seite, nicht nur in einem PDF.
- [ ] Videos haben Untertitel; Audio hat ein Transkript.
- [ ] Nichts spielt von selbst Ton ab.

## Formulierungen

- [ ] Einfache Sprache; erklären Sie Abkürzungen beim ersten Vorkommen.
- [ ] Anleitungen hängen nicht allein von Farbe oder Position ab („die rote Schaltfläche“, „rechts“).
- [ ] Daten und Uhrzeiten sind eindeutig ausgeschrieben.

## Beispiele

| Element | Schlecht | Besser |
|---|---|---|
| Alternativtext | `IMG_4031.jpg` | Freiwillige sortieren Spenden im Lager |
| Linktext | Hier klicken | Zum Tag der offenen Tür anmelden |
| Überschrift | **Unsere Preise** als fett gesetzter Absatz | „Unsere Preise“ als Überschrift der nächsten Ebene |
| Dateilink | Download | Preisliste 2026 (PDF) |
| Anleitung | Drücken Sie die grüne Schaltfläche | Drücken Sie **Zur Veröffentlichung schicken** |

> **Tipp**
> Drucken Sie diese Seite aus und legen Sie sie in den ersten Wochen neben den Bildschirm. Die meisten Redakteure
> kennen sie nach einem Monat auswendig.
