# Arbeitsblatt für die Wachstums-Roadmap

Diese Seite ist eine **Vorlage** für den Betreiber und das Leitungsteam. Füllen Sie sie einmal im Jahr oder vor einer
Budgetrunde aus, mit Ihrem Partner am Tisch. Sie hilft Ihnen, die wenigen nächsten Schritte auszuwählen, die Ihren
Zielen dienen, und die Routinearbeit zu sehen, die jeder davon für Ihr Team mit sich bringt. Die Zahlen, die Sie
eintragen, sind Ihre eigenen Schätzungen; die Seite gibt keine vor.

## Teil 3: Bewertung

**Beispielannahmen: Ersetzen Sie sie durch Ihre eigenen.** Bewerten Sie jede verbleibende Möglichkeit von 1 (niedrig)
bis 5 (hoch). Die Spalte Nutzen gibt an, wie sehr sie Ihren Zielen dient; die anderen Spalten sind Kosten, eine hohe
Zahl dort ist also schlechter.

| Möglichkeit | Nutzen für die Ziele | Aufwand des Partners | Zusätzliche Routine für das Team | Risiko (Daten, Recht, Ruf) | Summe (Nutzen x 2 minus den Rest) |
|---|---|---|---|---|---|
| | | | | | |
| | | | | | |
| | | | | | |

„Zusätzliche Routine für das Team“ ist am wichtigsten und wird am häufigsten vergessen: Ein Newsletter ist jeden Monat
eine Ausgabe, eine Sprache ist eine Übersetzung jeder neuen Seite, ein Mitgliederbereich ist ein monatliches Aufräumen
der Konten. Jede der oben genannten Seiten für Betreiber beschreibt ihre Routine.

## Teil 4: Zwölfmonatsplan

| Q1 | | | | | |

Vor jedem Schritt:

- [ ] Die Grundlagen sind vorhanden: Rollen, Freigaben wo nötig, die wöchentliche Routine
      ([Ihre Website im Alltag betreiben](../alltag/README.md)).
- [ ] Der Schritt steht im [Redaktionskalender](../alltag/redaktionskalender.md).
- [ ] Ihr Partner weiß, wann das nächste Upgrade geplant ist, damit sich beides nicht überschneidet
      ([Release- und Upgrade-Planung](../../fuehrung/release-und-upgrade-planung.md)).
