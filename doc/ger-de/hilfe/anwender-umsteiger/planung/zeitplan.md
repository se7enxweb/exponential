# Der Zeitplan der Einführung

Das Projekt veröffentlicht keine Zeiträume für eine Einführung oder eine Migration. Bauen Sie den Zeitplan aus Ihren
eigenen Messungen auf.

## Inhalt

1. [Die Phasen](#die-phasen)
2. [Erst messen, dann planen](#erst-messen-dann-planen)
3. [Feste Termine und Puffer](#feste-termine-und-puffer)
4. [Eine Vorlage](#eine-vorlage)

## Die Phasen

| Phase | Hängt ab von |
|---|---|
| Inhaltsmodellierung | Zahl der Inhaltstypen und wie sehr sie sich von heute unterscheiden |
| Design und Templates | Zahl der Seitentypen; ob ein Theme wiederverwendet wird |
| Individuelle Erweiterungen | Anforderungen, die die Standardfunktionen nicht abdecken |
| Migration und Proben | Menge der Inhalte und Dateien; Regeln für URLs ([Umziehen](../umziehen/README.md)) |
| Schulung | Zahl der Redakteure und Rollen |
| Start und intensive Betreuung | Größe der Website und Verkehr |

## Erst messen, dann planen

"Measure the duration in a rehearsal and plan from the measurement, as the installation book advises", also: Messen
Sie die Dauer in einer Probe und planen Sie von der Messung aus, wie es das Installationsbuch rät
([Zu Exponential wechseln](../../unternehmen/auswahl/zu-exponential-wechseln.md)). Messen Sie insbesondere:

- den vollständigen Migrationslauf auf einer Staging-Kopie, von Anfang bis Ende;
- die Neuindizierung der Suche;
- den Neuaufbau der URL-Aliase für jede Sprache;
- die Zeit, die ein Redakteur für eine typische Aufgabe auf der neuen Website braucht.

## Feste Termine und Puffer

- Legen Sie keinen Starttermin fest, bevor die erste Probe gelaufen ist.
- Vermeiden Sie einen Start in Ihrer geschäftigsten Zeit ([Planung für Lastspitzen](../../unternehmen/zuverlaessigkeit/lastspitzen-planen.md)).
- Planen Sie einen Inhaltsstopp für den letzten Lauf ein und sagen Sie, wie lange er dauert.
- Halten Sie einen Puffer bereit; die Größe entscheiden Sie (eine Beispielannahme: ein Fünftel der gemessenen Zeit).
