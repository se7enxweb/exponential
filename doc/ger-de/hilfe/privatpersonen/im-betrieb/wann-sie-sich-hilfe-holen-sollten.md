# Wann Sie sich Hilfe holen sollten

Diese Seite ist für Privatpersonen, die ihre Website allein betreiben und sich fragen, wann es besser ist, jemanden
zu bezahlen. Alles selbst zu machen ist möglich; alles selbst gut zu machen, über Jahre, ist viel. Ein paar Stunden
bezahlter Hilfe im richtigen Moment können Wochenenden sparen.

## Was eine einzelne Person meist gut erledigt

Schreiben und Veröffentlichen, Bilder und Galerien, Menüs und Seiten, Kommentare und Konten, eine Newsletter-Ausgabe,
die monatliche Pflege. Nichts davon braucht einen Profi.

## Warnzeichen

Holen Sie sich Hilfe, wenn:

- Sie ein Sicherheitsupdate seit Wochen aufschieben, weil Sie unsicher sind, wie es geht;
- Sie keine Sicherung haben, die Sie je wiederhergestellt haben;
- E-Mails von der Website nicht mehr ankommen und Sie nicht wissen, warum;
- Sie Befehle auf einen Live-Server kopieren, die Sie nicht verstehen;
- die Website einem Verein oder einer Familie gehört und Sie die einzige Person sind, die sie reparieren kann.

## Einen kleinen Auftrag beschreiben

Eine klare Beschreibung bringt einen klaren Preis. Schreiben Sie:

1. **Was Sie möchten**, in einem Satz („Eine Galerieansicht, die Bilder bis 1600 Pixel Breite zeigt").
2. **Ihre Umgebung**: Exponential-Version (siehe `/ezinfo/about`), Art des Hostings, Datenbank, Webserver.
3. **Was vorhanden ist**: Klassen, Design-Erweiterung, Ihre eigenen Änderungen.
4. **Was „fertig" heißt**: wie Sie prüfen, dass es funktioniert.
5. **Zugang**: wenn möglich eine Testkopie, nicht Ihre Live-Website.
6. **Budget und Termin.**

Die Vorlage für eine Projektbeschreibung aus dem Bereich für Unternehmen passt auch für kleine Aufträge
([Vorlage für eine Projektbeschreibung](../../unternehmen/vorlagen/vorlage-fuer-projektbeschreibungen.md)).

## Fragen, die Sie stellen sollten

- Haben Sie mit Exponential 6 (oder den älteren Versionen, die es fortführt) gearbeitet?
- Arbeiten Sie zuerst an einer Kopie?
- Liegt die Änderung in meiner eigenen Erweiterung, damit Updates sie nicht überschreiben?
- Schreiben Sie auf, was Sie geändert haben?
- Was passiert, wenn es nach Abschluss kaputtgeht?

## Eigentümer bleiben

- Legen Sie für die helfende Person ein eigenes Konto an; deaktivieren Sie es, wenn der Auftrag erledigt ist.
- Behalten Sie Domain, Hosting und Administratorpasswörter auf Ihren Namen.
- Bitten Sie um die geänderten Dateien oder um die Änderung in einem Git-Repository, das Sie lesen können.
- Sie können darum bitten, dass allgemein nützliche Verbesserungen an das Projekt zurückgegeben werden; das hilft
  allen ([Erweiterungen zurückgeben](../../erweiterungen-zurueckgeben.md)).

## Zuerst kostenlose Hilfe

- Die Hilfe, die Sie gerade lesen, und das Installationsbuch.
- Die Community-Kanäle ([Community-Kanäle](../../fuersprecher/community-kanaele.md)).
- Fehlermeldungen auf GitHub, wenn etwas eindeutig ein Fehler ist ([GitHub-Issues](../../kunden/gesund-halten/github-issues.md)).

Wenn Sie selbst die Person werden möchten, die andere beauftragen, siehe
[Lernen mit der Stufe Student](lernen-mit-der-stufe-student.md).
