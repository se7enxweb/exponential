# Projekt 10: Abschlussprojekt, eine vollständige kleine Website

Das Abschlussprojekt führt die früheren Projekte zu einer Website zusammen, die Sie planen, bauen, dokumentieren und
vorstellen. Es ist das stärkste Stück im Portfolio von Lernenden. Arbeiten Sie allein oder in einem Team von zwei bis
vier Personen, in dem jedes Mitglied Teile verantwortet.

## Ziel

Eine funktionierende Website auf einer frischen Lerninstallation, die andere anhand Ihrer Dokumentation neu aufbauen
können, mit einem Plan, einem Inhaltsmodell, einer Struktur, einem Erscheinungsbild, mindestens einer mit Layouts
gebauten Seite, einer zweiten Sprache, Rollen für ihre Redakteure, einer funktionierenden Suche, einer Sicherung und
einer kurzen Präsentation.

## Eine Aufgabenstellung wählen

Wählen Sie eine oder vereinbaren Sie eine eigene mit Ihrer Lehrkraft oder Gruppe. Alle Inhalte sind erfunden.

| Aufgabenstellung | Inhalte |
|---|---|
| Eine Schülerzeitung | Artikel, Autoren, Rubriken, ein Veranstaltungskalender |
| Ein Club oder Verein | Neuigkeiten, Veranstaltungen, Mitgliederseiten, eine Seite zum Beitreten |
| Ein kleines Museum oder eine kleine Bibliothek | Sammlungsobjekte, Ausstellungen, Öffnungszeiten, zwei Sprachen |
| Eine Konferenz | Vorträge, Vortragende, ein Zeitplan, Informationen zum Veranstaltungsort |

## Anforderungen je Lernpfad

Alle bearbeiten die Meilensteine 1 bis 10. Zusätzlich, je nach Pfad:

| Pfad | Zusätzliche Anforderung |
|---|---|
| Redakteur | Zehn oder mehr veröffentlichte Elemente mit Bildern und Beziehungen; ein Stilleitfaden für die Redakteure der Website |
| Administrator | Eine schriftliche Betriebsnotiz: Caches, Logs, Sicherungen, Updates ([Mit Git aktualisieren](../mit-git-aktualisieren.md)); Anmeldung in zwei Schritten für die Redakteure |
| Entwickler | Eine eigene Erweiterung ([Projekt 8](projekt-08-ihre-erste-erweiterung.md)) oder ein Skript, das die Website über die REST API liest ([Projekt 7](projekt-07-inhalte-ueber-die-rest-api-lesen.md)) |
| Designer | Eine Design-Erweiterung mit Overrides für mindestens zwei Ansichtsmodi, nur mit der Tastatur und in einem schmalen Fenster geprüft |

## Abgabe

1. **Der Plan** und **der Abschlussbericht** (vier bis acht Seiten): was Sie gebaut haben, wie, was sich gegenüber dem
   Plan geändert hat, die verwendeten Seiten und die drei schwierigsten Probleme.
2. **Eine Anleitung zum Neuaufbau**: die Befehle und Klicks, die eine frische Installation in Ihre Website
   verwandeln. Eine andere lernende Person probiert sie aus; halten Sie fest, was sie nachfragen musste.
3. **Ihre Git-Repositorys**: Design oder Erweiterung, Skripte, Notizen. Kein `settings/override/`, keine Passwörter
   oder Schlüssel.
4. **Screenshots** jedes Meilensteins, ohne Geheimnisse oder personenbezogene Daten.
5. **Das Release**, auf dem Sie gebaut haben.

## Präsentation

Zehn Minuten, live oder aufgezeichnet:

1. Die Aufgabenstellung und die Zielgruppe (1 Minute).
2. Ein Rundgang durch die Website als Besucher (3 Minuten).
3. Ein Rundgang als Redakteur der Website, angemeldet als eingeschränkter Redakteur (3 Minuten).
4. Eine technische Entscheidung und ihre Begründung (2 Minuten).
5. Was Sie als Nächstes tun würden (1 Minute).

Zeigen Sie niemals Passwörter oder Schlüssel auf dem Bildschirm. Wenn Sie auf einer gemeinsamen oder öffentlichen
Demo-Installation präsentieren, denken Sie daran, dass ihre Inhalte zurückgesetzt werden können und andere sie ändern
können ([Die öffentliche Demo ausprobieren](die-oeffentliche-demo-ausprobieren.md)).

## Bewertungsraster

Bewerten Sie die vier gemeinsamen Kriterien aus [Die eigene Arbeit bewerten](die-eigene-arbeit-bewerten.md) zweimal:
einmal für die Website und einmal für die Dokumentation (insgesamt 0 bis 24). Fügen Sie diese Prüfungen hinzu (10):

1. Der Plan bestand vor dem Bau, und der Bericht vergleicht beide.
2. Die Website läuft auf einer frischen Installation eines benannten Releases.
3. Mindestens eine von der lernenden Person selbst entworfene Klasse wird verwendet.
4. Keine Kerndatei wurde bearbeitet; nur Overrides und Erweiterungen.
5. Ein Layout ist veröffentlicht und zugeordnet.
6. Eine zweite Sprache wird in einem Siteaccess angezeigt.
7. Redakteure arbeiten mit einer eingeschränkten Rolle, nicht als Administrator.
8. Der Suchtestplan ist erfüllt oder erklärt seine Fehlschläge.
9. Eine andere lernende Person hat die Website anhand der Anleitung neu aufgebaut.
10. Die zusätzliche Anforderung des Pfads ist erfüllt.

Für die Notenstufen verdoppeln Sie die Schwellen aus [Die eigene Arbeit bewerten](die-eigene-arbeit-bewerten.md#von-punkten-zur-note).

sind ein gutes Vorbild, wenn Ihre Lehrkraft ein strengeres Format möchte.
