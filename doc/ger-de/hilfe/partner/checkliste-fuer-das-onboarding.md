# Checkliste für das Onboarding neuer Partner

Diese Seite ist für die verantwortliche Person der Partnerschaft in einem neu aktivierten Partnerunternehmen. Arbeiten
Sie sie in den ersten Wochen durch; [Ihre ersten 30 Tage](ihre-ersten-30-tage.md) legt sie auf einen Kalender.

## Verwaltung

- [ ] Unterzeichnete Vereinbarung abgelegt, mit Datum und der Version der Programmseiten, auf die sie sich bezieht
- [ ] Abonnement im Shop aktiv; Rechnungen gehen an den Ansprechpartner für die Abrechnung
- [ ] Verlängerungsdatum im Kalender, dazu eine Erinnerung 45 Tage vorher (der Status wird „30 Tage vor Ablauf“ bewertet, <https://exponential.earth/partner/why>)
- [ ] Interne verantwortliche Person benannt, mit Vertretung

## Konten und Kanäle

- [ ] Eine GitHub-Organisation oder Konten für Ihr Team (Support-Tickets und Beiträge laufen über GitHub)
- [ ] Ein Konto auf share.exponential.earth für die Partnerseite und die Foren
- [ ] Treten Sie den Community-Kanälen bei: Telegram <https://t.me/exponentialcms>, Foren
      <https://share.exponential.earth/forums>; Slack und Discord wie auf <https://exponential.earth/about/project> aufgeführt
- [ ] Bitten Sie um Aufnahme in die Partner-Mailinglisten („Zugang zu Mailinglisten, Updates und strategischen Briefings“,
      <https://exponential.earth/partner/benefits>)
- [ ] Notieren Sie die Termine des nächsten vierteljährlichen Partnertreffens (wie sie angekündigt werden, ist nicht
      veröffentlicht; fragen Sie)

## Ihr öffentlicher Auftritt

- [ ] Schreiben Sie Ihre Partnerseite ([Ihre Partnerseite](ihre-partnerseite.md))
- [ ] Besorgen Sie die Logodateien für Ihre Stufe und lesen Sie die Regeln ([Partnerlogos und das Zertifizierungszeichen verwenden](partnerlogos-und-zeichen.md))
- [ ] Aktualisieren Sie Ihre eigene Website: Profil, Stufe, Link zu exponential.earth

## Support-Ablauf

- [ ] Legen Sie fest, wer in Ihrem Team Partner-Tickets eröffnen darf ([Ein Support-Ticket als Partner eröffnen](support-ticket-eroeffnen.md))
- [ ] Halten Sie Ihre Reaktionszeiten schriftlich fest ([Support-Stufen und Reaktionszeiten](support-stufen-und-reaktionszeiten.md))
- [ ] Notieren Sie den vertraulichen Sicherheitskontakt security@se7enx.com ([Eskalationen und Sicherheitsprobleme](eskalationen-und-sicherheitsprobleme.md))

## Technische Einrichtung

- [ ] Eine aktuelle Entwicklungsinstallation von Exponential 6.0 aus Git ([Mit Git entwickeln](../mit-git-entwickeln.md))
- [ ] Beobachten Sie die Releases des Hauptrepositorys auf GitHub (<https://github.com/se7enxweb/exponential>)
- [ ] Lesen Sie die Release-Übersicht und das neueste Änderungsprotokoll (`doc/en/us/release-overview`, `doc/changelogs/6.0/`)
- [ ] Eine Staging-Umgebung, in der Sie Releases testen, bevor Ihre Kunden es tun ([Releases testen](releases-testen.md))

## Internes Wissen

- [ ] Alle, die mit Kunden sprechen, lesen [Namens- und Markenregeln für Partner](namens-und-markenregeln.md)
- [ ] Der Vertrieb liest [Vertrieb und Marketing: hier beginnen](../geschaeft/vertrieb-und-marketing-hier-beginnen.md)
- [ ] Projektverantwortliche lesen [Projektverantwortliche: hier beginnen](../fuehrung/projektleiter-hier-beginnen.md)
- [ ] Entwickler lesen CONTRIBUTING.md und [Mit Git entwickeln](../mit-git-entwickeln.md)

## Erste Beiträge

- [ ] Eine Antwort im Forum pro Woche
- [ ] Ein Plan für Ihre erste Fallstudie ([Eine Fallstudie schreiben](eine-fallstudie-schreiben.md))
