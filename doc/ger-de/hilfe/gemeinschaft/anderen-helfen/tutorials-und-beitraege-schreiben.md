## Den Ort wählen

| Ihr Text ist | Veröffentlichen Sie ihn auf |
|---|---|
| Ein kurzer Kniff oder eine Notiz zum Nachschlagen | [eZpedia](https://ezpedia.exponential.earth/) ([Zu eZpedia beitragen](../../fuersprecher/zu-ezpedia-beitragen.md)) |
| Ein Tutorial oder ein Artikel | [Share](https://share.exponential.earth/) ([Auf Share und Projects veröffentlichen](../../fuersprecher/auf-share-und-projects-veroeffentlichen.md)) |
| Die Lösung einer Forenfrage | Im Forenthema selbst |
| Eine Korrektur der offiziellen Hilfe | Ein Pull Request ([Dokumentation und Hilfeseiten beitragen](../mitwirken/dokumentation-und-hilfeseiten-beitragen.md)) |
| Ihre eigene Meinung oder Erfahrung | Ihr eigener Blog, verlinkt aus den Foren |

## Eine Struktur, die funktioniert

1. **Was Sie bauen oder lösen werden**, in ein oder zwei Sätzen, mit einem Bildschirmfoto des Ergebnisses.
2. **Für wen es ist** und was die Lesenden vorher wissen müssen.
3. **Voraussetzungen**: die Exponential-Version, Erweiterungen, PHP-Version, die Einrichtung, auf der Sie getestet
   haben.
4. **Schritte**, nummeriert, je eine Handlung, mit den genauen Befehlen oder Einstellungen.
5. **Wie man prüft, dass es funktioniert hat.**
6. **Was schiefgehen kann** und wie man es behebt.
7. **Quellen**: die Hilfeseiten und Dateien, auf die Sie sich gestützt haben.

Die ausführliche Anleitung ist [Ein Tutorial schreiben, das funktioniert](../../fuersprecher/ein-tutorial-schreiben.md);
für Beiträge [Einen Blogbeitrag schreiben](../../fuersprecher/einen-blogbeitrag-schreiben.md).

## Jeden Schritt testen

Folgen Sie Ihrem eigenen Tutorial auf einer frischen Testinstallation, bevor Sie es veröffentlichen. Mit SQLite geht
das schnell ([Erste Schritte](../../erste-schritte.md)). Schritte, die auf Ihrer langjährigen Entwicklungsseite
funktioniert haben, hängen oft von etwas ab, das Sie vor Monaten konfiguriert haben.

## Die eigenen Texte lizenzieren

Sagen Sie, unter welcher Lizenz andere Ihren Text wiederverwenden dürfen. Wenn Sie die Hilfe zitieren oder bearbeiten,
steht sie unter der GNU FDL 1.3 oder neuer, und Ihre Bearbeitung muss diese Lizenz beibehalten
([Freie Dokumentation](../../freie-dokumentation.md),
[Quellen nennen und die eigenen Texte lizenzieren](../../fuersprecher/quellen-zitieren-und-texte-lizenzieren.md)).

## Dinge richtig benennen

- Das Produkt heißt **Exponential**. Verwenden Sie den alten Namen nur für die Geschichte, in der Vergangenheitsform.
- **7x** ist das Unternehmen; die **Exponential Foundation** ist die gemeinnützige Organisation.
- Nennen Sie Ihr Tutorial nicht „offiziell“ ([Behauptungen, die Sie nicht aufstellen dürfen](../../fuersprecher/aussagen-die-sie-nicht-machen-duerfen.md)).
- Kurzreferenz: [Namensregeln auf einen Blick](../../fuersprecher/kurzkarte-namensregeln.md).
