# Die Hilfe in der Community korrekt halten

Falsche Hilfe kostet Menschen Stunden. Diese Gewohnheiten halten Ihre Hilfe richtig.

1. [Wo die Fakten stehen](#wo-die-fakten-stehen)

## Wo die Fakten stehen

| Art der Tatsache | Quelle |
|---|---|
| Was die Software tut | Der Code und seine Einstellungen, die Funktionsseiten unter `doc/eng-us/features/` |
| Was ein Release geändert hat | Die Changelogs unter `doc/changelogs/` |
| Anforderungen | `README.md`, [Anforderungen](../../../installation/02-voraussetzungen.md) |
| Wer das Projekt leitet und betreibt | [Wer ist 7x?](../../wer-ist-7x.md), [Wer ist die Exponential Foundation?](../../wer-ist-die-exponential-foundation.md) |
| Lizenzen | `LICENSE`, `CONTRIBUTING.md`, [Freie Dokumentation](../../freie-dokumentation.md) |
| Sicherheitsrichtlinie | `SECURITY.md` |
| Verhalten | `CODE_OF_CONDUCT.md` |

Die ausführlichere Anleitung ist [Wo die Fakten stehen](../../fuersprecher/wo-die-fakten-stehen.md).

## Eine Behauptung prüfen

1. Suchen Sie die Quelle oben.
2. Probieren Sie es auf einer Testinstallation des aktuellen Release aus.
3. Notieren Sie die Version, die Sie geprüft haben.
4. Verlinken Sie die Quelle, wenn Sie die Behauptung weitergeben.

## Zahlen und Daten

Zahlen wie die Anzahl der Pakete ändern sich mit der Zeit. Wenn Sie eine verwenden, nennen Sie das Datum, oder zählen
Sie mit dem Befehl, den die Quellseite nennt, neu ([Community und Ökosystem als Verkaufsargument](../../geschaeft/community-und-oekosystem.md)).

## Wenn Sie sich geirrt haben

- Korrigieren Sie es an derselben Stelle, sichtbar: „Korrektur: ...“.
- Löschen Sie die falsche Antwort nicht stillschweigend; Menschen könnten danach gehandelt haben.
- Danken Sie der Person, die darauf hingewiesen hat.

Der Verhaltenskodex verlangt von Trainern und Fürsprechern, „Fehler offen zu korrigieren“; für alle anderen ist das
ebenfalls gute Praxis ([Ehrlichkeit und Genauigkeit](../../fuersprecher/ehrlichkeit-und-genauigkeit.md)).

## „Nicht dokumentiert“ ist eine Antwort

Wenn die Dokumentation und der Code eine Frage nicht beantworten, sagen Sie das. Füllen Sie die Lücke nicht mit einer
Vermutung, die als Tatsache dargestellt wird. Überlegen Sie dann, ein Issue zu eröffnen, damit die Lücke dokumentiert
wird.
