## Was jede Art von Beitrag braucht

| Beitrag | GitHub-Konto | Programmierkenntnisse | Unterschriebenes CLA |
|---|---|---|---|
| Ein Fehlerbericht oder eine Idee | Ja | Nein | Nein |
| Eine Bestätigung des Fehlers einer anderen Person | Ja | Nein | Nein |
| Eine Tippfehlerkorrektur auf einer Hilfeseite | Ja | Nein | Trotzdem vor einem Merge in das Kernel-Repository unterschreiben; siehe [Das CLA erklärt](das-cla-erklaert.md) |
| Eine Übersetzung der Oberfläche oder der Hilfe | Ja | Nein | Wie bei jeder Änderung am Kernel-Repository |
| Eine Code-Korrektur oder Funktion im Kernel | Ja | Ja | Ja, vor dem Merge |
| Eine Erweiterung, die Sie selbst veröffentlichen | Nur für GitHub | Ja | Nein |
| Eine Antwort in den Foren | Ein Share-Konto | Nein | Nein |

Das Kernel-Repository ist `se7enxweb/exponential`: „`kernel/`, `lib/`, `bin/`, `design/`, `settings/`, `doc/`, die
darin ausgelieferten Erweiterungen und alles andere in diesem Repository“ (`CONTRIBUTING.md`, „Copyright assignment (CLA)“).

## Die Regeln, die für alle gelten

- **Lizenzen.** Code steht unter der GPL Version 2 oder neuer; Dokumentation unter der GNU FDL 1.3 oder neuer. Was
  Sie beitragen, wird unter derselben Lizenz veröffentlicht (`CONTRIBUTING.md`, „Licensing“;
  [Freie Dokumentation](../../freie-dokumentation.md)).
- **Der Verhaltenskodex** gilt für jeden Beitrag, auch für KI-gestützte
  ([Der Verhaltenskodex](../beitreten/der-verhaltenskodex.md)).
- **Keine Geheimnisse oder personenbezogenen Daten** in Issues, Pull Requests, Beispielen oder Bildschirmfotos.
- **Sicherheitsprobleme sind vertraulich** (`SECURITY.md`).
- **Manche Fehler sind negative Funktionen.** Verhalten, das gewollt oder auslegungsfähig ist und von dem andere
  Websites abhängen, ändert sich nur mit einer klaren Begründung, vorzugsweise als Option statt als neuer
  Standard, und oft erst nach mehreren Review-Runden ([Negative Funktionen](../../projekt/unterstuetzung-erhalten.md#negative-funktionen)).
