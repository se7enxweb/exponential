# Eine führende Rolle in der Exponential-Community übernehmen

Diese Seite ist für alle, die Exponential verwenden und mehr tun möchten, als es nur zu verwenden: anderen Benutzern
helfen, das Produkt und seine Dokumentation verbessern und jemand sein, an den sich andere in der Community wenden. Es
spielt keine Rolle, ob Sie Projektleiter sind, im Vertrieb oder Marketing arbeiten, Redakteur, Administrator oder
Entwickler sind. Jede Rolle hat einen Weg nach oben.

Die Seite beantwortet drei Fragen: wie Führung in dieser Community aussieht, an welchen dokumentierten Orten Sie sich
beteiligen und was Sie in Ihren ersten 30, 60 und 90 Tagen tun, mit nichts als dieser Hilfe als Wegweiser.

## Was Führung hier bedeutet

Exponential ist Open-Source-Software mit einer langen Geschichte. Die Codebasis reicht bis 1999 zurück („Copyright (C)
1999 - 2014 eZ Systems AS“ in `COPYRIGHT.md`), und Exponential führt die Codebasis von eZ Publish fort, einem Produkt,
das sein Hersteller nach fast 18 Jahren eingestellt hat ([Wer ist 7x?](../wer-ist-7x.md#die-jahre-von-ez-publish-1999-bis-2021)).
Seit Dezember 2023 leitet das Unternehmen **7x** das Projekt, und seit März 2026 betreibt es die gemeinnützige
**Exponential Foundation** ([Wer ist die Exponential Foundation?](../wer-ist-die-exponential-foundation.md)).

Ein solches Projekt lebt von Menschen, die:

- **Fragen beantworten**, damit andere nicht feststecken;
- **Probleme gut melden**, damit sie für alle behoben werden können;
- **Dinge aufschreiben**, denn die Dokumentation ist frei und jeder darf sie verbessern
  ([Freie Dokumentation](../freie-dokumentation.md));
- **Änderungen zurückgeben**, statt private Korrekturen mit sich herumzutragen;
- **andere einbinden**: neue Benutzer, neue Mitwirkende, neue Sponsoren.

Das Projekt formuliert seine eigene Haltung: „Das Exponential Project und die Exponential Foundation unterstützen die
Open-Source-Community direkt, als Teil unserer täglichen Routine und Arbeitsethik, und stellen die Bedürfnisse der
Community-Benutzer an Unterstützung an die erste Stelle“ (`README.md`, „An open community“). Eine Führungsperson in der
Community handelt im selben Geist.

## Die Beitragsleiter

Jede Stufe baut auf der vorherigen auf. Sie können auf jeder Stufe bleiben, so lange Sie möchten; jede Stufe ist
wertvoll.

| Stufe | Was Sie tun | Was Sie brauchen | Wo es sichtbar wird | Hilfeseite |
|---|---|---|---|---|
| **1. Benutzer** | Exponential verwenden, die Hilfe lesen, sich zurechtfinden | Ein Konto auf einer Installation | Ihre eigene Arbeit | [Erste Schritte](../erste-schritte.md) |
| **2. Melder** | Fehler gut melden; Fragen stellen und beantworten | Ein kostenloses GitHub-Konto für Issues; ein Konto in den Foren | Issues und Forenbeiträge mit Ihrem Namen | [Wenn etwas schiefgeht](../wenn-etwas-schiefgeht.md) |
| **3. Dokumentierender** | Die Hilfe korrigieren, erweitern und übersetzen; Tutorials schreiben | GitHub oder den Link „Auf GitHub bearbeiten“ jeder Hilfeseite | Gemergte Änderungen an der Dokumentation | [Freie Dokumentation](../freie-dokumentation.md) |
| **4. Mitwirkender** | Korrekturen und Funktionen als Pull-Requests an den Kernel oder eine Erweiterung schicken | Git-Klone, einen Fork, `CONTRIBUTING.md` | Gemergte Pull-Requests | [Mit Git entwickeln](../mit-git-entwickeln.md#eine-änderung-per-pull-request-beitragen) |
| **5. Reviewer, Maintainer** | Pull-Requests anderer prüfen, eine Erweiterung betreuen, Neulinge anleiten | Erfahrung auf den Stufen 2 bis 4 | Kommentare zu Pull-Requests, eine Erweiterung, die Sie betreuen | [Mit der Community arbeiten](mit-der-community-arbeiten.md) |

### Stufe 2 im Detail: ein Melder, dem andere danken

- Durchsuchen Sie zuerst den Tracker; ergänzen Sie ein bestehendes Issue, statt ein Duplikat zu eröffnen
  ([Wenn etwas schiefgeht](../wenn-etwas-schiefgeht.md#einen-fehler-in-exponential-melden)).
- Verwenden Sie die Seite **Fehler melden** der Hilfe (`/exphelp/report`): Sie wählt den Tracker, bereitet das Issue vor
  und fügt eine Zusammenfassung der Installation ohne Passwörter, Schlüssel oder Serverpfade ein.
- Schreiben Sie einen kurzen Titel, die Schritte, was Sie erwartet haben und was passiert ist, und die Umgebung
  ([Eine gute Fehlerbeschreibung](../wenn-etwas-schiefgeht.md#eine-gute-fehlerbeschreibung)).
- Antworten Sie in den Foren mit einem Link auf die Hilfeseite, die die Frage beantwortet. So lernen die Leute, wo die
  Antworten zu finden sind.

### Stufe 3 im Detail: Dokumentierender

- Jede Hilfeseite hat einen Link **Auf GitHub bearbeiten** zu ihrer Quelldatei unter `doc/`
  ([Das Hilfesystem](../../funktionen/6.0/hilfesystem.md)).
- Eine Änderung an der Dokumentation wird unter der GNU Free Documentation License 1.3 oder einer späteren Version
  angenommen, damit sie für alle frei bleibt ([Freie Dokumentation](../freie-dokumentation.md#anderen-helfen)).
- Übersetzungen zählen: Die Administration hat viele Übersetzungen (die aktuellen Gesamtzahlen stehen am Anfang der Seite Sprachen), und Inhalte können in 368
  Locales verfasst werden ([Sprachen in Exponential](../../sprachen.md)). Eine Übersetzung zu vervollständigen ist ein
  Beitrag, den jeder zweisprachige Redakteur leisten kann.
- Gute erste Dokumentationsaufgaben: eine Seite, die Sie verwirrt hat, ein fehlendes Beispiel, eine Schritt-für-Schritt-
  Anleitung ohne Screenshots für eine Aufgabe, die Sie gerade erledigt haben.

### Stufe 4 im Detail: Mitwirkender

- Installieren Sie den Kernel und die Erweiterungen als Git-Klone: „Der empfohlene Weg ist, den Kernel und jede
  se7enxweb-Erweiterung als Git-Klone mit ihrer vollständigen Historie zu holen“ (`README.md`, „Installation“;
  [Mit Git entwickeln](../mit-git-entwickeln.md)).
- Forken, Branch anlegen, committen, pushen, einen Pull-Request öffnen
  ([Mit Git entwickeln](../mit-git-entwickeln.md#eine-änderung-per-pull-request-beitragen)).
- Folgen Sie `CONTRIBUTING.md`: Commit-Betreffzeilen beginnen mit `Added:`, `Updated:`, `Fixed:`, `Removed:` oder
  `Renamed:`; eine fokussierte Änderung pro Pull-Request; die Dokumentation aktualisieren; das Dateimanifest aktuell
  halten (`make manifest-fix`; `make hooks` installiert die Prüfungen).
- Kennen Sie die Lizenz: „alle am Projekt vorgenommenen Änderungen werden ebenfalls unter derselben Lizenz GPLv2 oder
  später veröffentlicht“ (`CONTRIBUTING.md`).
- Die Praxis des Projekts ist großzügig gegenüber Mitwirkenden: „Jeder Pull-Request wird gemergt, und seine Commits
  bleiben so erhalten, wie der Mitwirkende sie geschrieben hat, und werden nie umgeschrieben“; was korrigiert werden
  muss, wird in Commits obendrauf korrigiert ([Continuous Integration](../../bc/6.0/ci.md)).

### Stufe 5 im Detail: Reviewer und Maintainer

- „Alle Beiträge werden vor dem Mergen geprüft“ (`CONTRIBUTING.md`). Jeder kann öffentlich prüfen: einen Pull-Request
  lesen, ihn auf der eigenen Installation ausprobieren und kommentieren, was man gefunden hat.
- Lernen Sie die Prüfungen kennen, die ein Pull-Request bestehen muss: Die Workflows **Quality** und **PHPUnit**
  blockieren, **Performance** warnt, **CI health** berichtet ([Continuous Integration](../../bc/6.0/ci.md)).
- Lernen Sie die Release-Regeln, bevor Sie eine Erweiterung betreuen: Veröffentlichte Versionen ändern sich nie, die
  letzte Stelle einer Version zählt weiter (auf `0.1.9` folgt `0.1.10`), und eine Erweiterung gibt ihre Version in
  `ezinfo.php` und `extension.xml` an ([Erweiterungen, „Release it“](../../anleitungen/extensions.md#7-die-extension-veröffentlichen)).

## Die Leiter für jede Rolle

| Rolle | Stufe 2 (Melder) | Stufe 3 (Dokumentierender) | Stufe 4 (Mitwirkender) | Stufe 5 (Führung) |
|---|---|---|---|---|
| **Projektleiter** | Die Fehler des Teams sammeln und gut melden | Eine Projektmethode, die funktioniert hat, als Tutorial oder Hilfeseite aufschreiben | Eine Korrektur sponsern: Ihre Entwickler sie zurückgeben lassen, statt sie zu behalten | Eine monatliche „Community-Stunde“ für Ihr Team abhalten; andere Projektleiter in den Foren begleiten |
| **Vertrieb und Marketing** | Melden, wo die öffentliche Darstellung und das Produkt nicht übereinstimmen | Die Business-Seiten dieser Hilfe verbessern | Fallstudien mit Zustimmung der Kunden schreiben ([Fallstudien schreiben](../geschaeft/fallstudien-und-content-marketing.md)) | Die Community wachsen lassen ([Die Community wachsen lassen](../geschaeft/die-community-wachsen-lassen.md)) |
| **Redakteur** | Verwirrende Bildschirme mit Schritten melden | Die Hilfeseiten für Redakteure korrigieren; eine Übersetzung vervollständigen | Pull-Requests testen, die das Bearbeiten betreffen, und sagen, was Sie gefunden haben | Fragen von Redakteuren in den Foren beantworten |
| **Administrator** | Mit der Fehlerreferenz und dem Bericht der Systeminformationen melden | Ein Betriebsverfahren aufschreiben, das funktioniert hat | Korrekturen an Einstellungen und Skripten schicken | Änderungen an Sicherheit und Betrieb prüfen; Erfahrungen mit der Härtung teilen ([Sicherheitshärtung](../sicherheitshaertung.md)) |
| **Entwickler** | Mit einer Reproduktion und Log-Zeilen melden | Die verwendeten Erweiterungspunkte dokumentieren | Pull-Requests an den Kernel und die Erweiterungen | Pull-Requests prüfen; eine Erweiterung betreuen |

## Der 30/60/90-Tage-Plan

Der Plan nutzt nur diese Hilfe und die dokumentierten Orte. Der Zeitaufwand ist das, was eine Person mit einer
regulären Arbeitsstelle erübrigen kann: ein paar Stunden pro Woche.

### Tag 1 bis 30: lernen und zuhören

| Woche | Tun | Lesen | Erledigt, wenn |
|---|---|---|---|
| 1 | Erfahren, wer Exponential macht und was die Produktfamilie ist | [Wer ist 7x?](../wer-ist-7x.md), [Wer ist die Exponential Foundation?](../wer-ist-die-exponential-foundation.md), [Was Exponential ist](was-exponential-ist.md) | Sie können 7x, die Foundation und die Produktfamilie in drei Sätzen erklären |
| 2 | Die Administration auf einer Installation durchgehen, die Sie selbst verwalten | [Erste Schritte](../erste-schritte.md), [Ein Rundgang durch die Administration](../rundgang-durch-die-administration.md), [Der Layout-Editor](../layout-editor.md) | Sie haben ein Objekt und ein Layout bearbeitet, in der Vorschau angesehen und veröffentlicht |
| 3 | Den Orten beitreten: Foren, Telegram; die Issue-Tracker beobachten | [Die Orte der Community](#die-orte-der-community) | Sie haben eine Woche lang Fragen gelesen, ohne schon zu antworten |
| 4 | Die Regeln für Beiträge und die Lizenzen lesen | `CONTRIBUTING.md`, [Freie Dokumentation](../freie-dokumentation.md), [Mit Git entwickeln](../mit-git-entwickeln.md) | Sie wissen, was GPL v2 oder später und GFDL 1.3 für Ihren Beitrag bedeuten |

### Tag 31 bis 60: beitragen

| Woche | Tun | Erledigt, wenn |
|---|---|---|
| 5 | Drei Fragen in den Foren beantworten, jede mit einem Link auf eine Hilfeseite | Drei Antworten |
| 6 | Einen guten Fehlerbericht schreiben oder ein bestehendes Issue mit einer Reproduktion verbessern | Das Issue enthält alle Felder aus [Eine gute Fehlerbeschreibung](../wenn-etwas-schiefgeht.md#eine-gute-fehlerbeschreibung) |
| 7 | Eine Änderung an der Dokumentation über „Auf GitHub bearbeiten“ vornehmen | Ein Pull-Request ist offen |
| 8 | Entwickler: eine Code-Korrektur als Pull-Request; alle anderen: eine Übersetzung oder ein Tutorial | Ein zweiter Beitrag ist offen oder gemergt |

### Tag 61 bis 90: führen

| Woche | Tun | Erledigt, wenn |
|---|---|---|
| 9 | Einen Bereich wählen, um den Sie sich kümmern: eine Erweiterung, einen Abschnitt der Hilfe, eine Sprache, eine Forenkategorie | Sie haben es öffentlich gesagt, im Issue-Tracker der Community oder in den Foren |
| 10 | Zwei Pull-Requests anderer in Ihrem Bereich prüfen oder testen | Zwei Review-Kommentare |
| 11 | Eine neue Person einbinden: einen Kollegen, einen Redakteur eines Kunden, einen Übersetzer | Sie hat ihren ersten Beitrag geleistet (Stufe 2 oder 3) |
| 12 | Einen kurzen Bericht über Ihre 90 Tage für Ihr Team und die Community schreiben | Veröffentlicht in den Foren oder als Blog auf share.exponential.earth |
| 13 | Ihr nächstes Quartal mit dem Fortschrittsbogen unten planen | Der Bogen ist ausgefüllt |

> **Tipp**
> Wenn Sie ein Team leiten, führen Sie diesen Plan mit dem ganzen Team gleichzeitig durch. Der
> [Lesepfad für Führungskräfte](lesepfad-fuer-fuehrungskraefte.md) gibt jeder Rolle ihre Lesereihenfolge Woche für Woche vor.

## Gewohnheiten einer guten Führungsperson in der Community

- **Verweisen Sie auf die Quelle.** Antworten Sie mit einem Link auf die Hilfe, die README oder einen Changelog. Wenn
  keine Quelle es sagt, sagen Sie das, wie es die Hilfeseiten selbst tun
  ([Was die Quellen nicht sagen](../wer-ist-die-exponential-foundation.md#was-die-quellen-nicht-sagen)).
- **Benennen Sie die Dinge richtig.** Das Produkt heißt **Exponential**, das Unternehmen **7x**, die gemeinnützige
  Organisation **Exponential Foundation**. „eZ Publish“ ist der frühere Name des Produkts und wird nur für die
  Geschichte verwendet ([Marken- und Namensregeln](../geschaeft/marken-und-namensregeln.md)).
- **Schützen Sie die Daten von Menschen.** Keine Passwörter, Schlüssel, Serveradressen oder personenbezogenen Daten von
  Kunden oder Benutzern in einem öffentlichen Issue oder Beitrag ([Wenn etwas schiefgeht](../wenn-etwas-schiefgeht.md)).
- **Nennen Sie die Urheber.** Das Projekt würdigt die Arbeit, auf der es aufbaut, etwa die von Netgen und Mugo Web
  ([Wer ist 7x?](../wer-ist-7x.md#mitwirkende-und-freunde-des-projekts)). Tun Sie dasselbe für die Menschen, die
  Ihnen helfen.
- **Geben Sie es zurück.** Eine Korrektur, die Sie behalten, pflegen Sie allein. Eine Korrektur, die Sie zurückgeben,
  „erreicht mit dem nächsten Release jede Site“ ([Wenn etwas schiefgeht](../wenn-etwas-schiefgeht.md#noch-besser-die-korrektur-mitschicken)).
- **Haben Sie Geduld mit Neulingen.** An Tag 1 waren Sie selbst einer.

## Was die Quellen nicht sagen

Um ehrlich zu bleiben, erfindet diese Seite keine Regeln, die das Projekt nicht aufgeschrieben hat:

- Die Quellen beschreiben kein formales Verfahren, um Maintainer, Committer mit Schreibrechten oder Mitglied im Vorstand
  der Foundation zu werden. Fragen Sie im [Issue-Tracker der Community](https://github.com/se7enxweb/exponential-community/issues),
  wenn Sie eine solche Rolle übernehmen möchten.
- Die Quellen nennen keine Konferenzen oder Treffen („Es sind keine Veranstaltungen (Konferenzen, Treffen)
  dokumentiert“, [Wer ist die Exponential Foundation?](../wer-ist-die-exponential-foundation.md#orte-der-community)).
- `CONTRIBUTING.md` bittet Mitwirkende, einen Verhaltenskodex zu lesen, aber diese Datei ist derzeit nicht im
  Repository. Bis sie da ist, folgen Sie den Gewohnheiten oben und fragen im Tracker der Community nach.
