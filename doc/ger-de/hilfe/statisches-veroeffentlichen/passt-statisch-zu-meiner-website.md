# Passt statisch zu meiner Website?

## Was Sie am Ende haben

Ein Ja, ein Nein oder ein „ja, für einen Teil“, in fünf Minuten.

## Die Checkliste

Beantworten Sie jede Frage für den öffentlichen Teil Ihrer Website.

| Frage | Statisch passt, wenn |
|---|---|
| Lesen und schauen Besucher vor allem? | ja |
| Ändert sich der Inhalt höchstens ein paar Mal am Tag? | ja (ein Build dauert Minuten, nicht Sekunden) |
| Müssen sich Besucher **anmelden**, um etwas zu sehen? | nein |
| **Kaufen** oder bezahlen Besucher auf der Website? | nein |
| Sind Formulare das Herz der Website (Buchungen, Bewerbungen)? | nein; ein Kontaktformular ist in Ordnung |
| Ist die Website unter 1 GB, ohne eine Datei über 100 MB? | ja, für GitHub Pages ([Grenzen](grenzen-und-bedingungen-von-github-pages.md)) |
| Darf alles öffentlich sein? | ja, oder Sie lassen den Rest aus ([Private Inhalte privat halten](private-inhalte-privat-halten.md)) |

## Gut geeignet

- Eine **Visitenkarten-Website** für ein Unternehmen, einen Verein oder eine Praxis.
- Ein **Blog** oder ein Nachrichtenbereich.
- **Dokumentation** und Handbücher.
- Ein **Portfolio** oder eine persönliche Website.
- Eine Website für eine **Veranstaltung** oder Konferenz.
- Eine **gemeinnützige Organisation**, eine Schule, eine Gruppe oder eine Website mit öffentlichen Informationen.

## Wenig geeignet

- Ein **Shop**: Die Bedingungen von GitHub schließen ihn aus, und ein Warenkorb braucht einen Server.
- Ein **Mitgliederbereich** oder Intranet: Was hinter einer Anmeldung liegt, kommt nie in die Kopie.
- Eine Website, die von **Formularen** und Suchergebnissen lebt, etwa Buchungs- oder Verzeichnis-Websites.
- Inhalt, der sich jede Minute ändert (Live-Ergebnisse, Lagerbestände).

## Ein Teil einer Website

Auch eine gemischte Website kann es nutzen: Die öffentlichen Seiten statisch veröffentlichen und den Rest auf dem
eigenen Hosting lassen. Seiten nach Pfad oder Sektion auslassen (Schritt 7 des Assistenten); Links auf sie führen zur
Live-Website.
