# Aussagen zuordnen

Diese Seite ist für Reporter und Redakteure. Wer etwas gesagt hat, verändert, was es für den Leser bedeutet: Ein Fakt in
einem Git-Tag, eine Behauptung auf einer Unternehmenswebsite und eine Meinung in einem Forum sind drei verschiedene
Dinge. Diese Seite gibt die richtige Zuordnung für jede Quelle rund um Exponential.

## Zuordnung nach Quelle

| Quelle | Was sie ist | Formulierung |
|---|---|---|
| Git-Tags und Verlauf | Ein Nachweis, was veröffentlicht wurde und wann | „die Release-Historie des Projekts zeigt“, oder als Tatsache nennen |
| README, SECURITY.md, CONTRIBUTING.md | Die eigenen Aussagen des Projekts in seinem Repository | „die README des Projekts sagt“, „seine Sicherheitsrichtlinie besagt“ |
| Diese Hilfe und `doc/` | Dokumentation, geschrieben vom Projekt und seinen Beitragenden | „laut der Dokumentation des Projekts“ |
| exponential.earth | Die Website des Projekts, betrieben von der Foundation | „die Website des Projekts sagt“ |
| foundation.exponential.earth | Die Selbstbeschreibung der Foundation | „die Foundation sagt auf ihrer Website“ |
| se7enx.com | Die Selbstbeschreibung und die Angebote von 7x | „7x sagt auf seiner Website“ |
| Eine Pressemitteilung | Eine datierte Aussage ihres Herausgebers | „7x erklärte in einer Pressemitteilung vom <Datum>“ |
| Ein Social-Media-Beitrag | Eine Aussage des Inhabers des Kontos | „<Konto> schrieb am <Datum> auf <Netzwerk>“ |
| Ein Interview oder eine E-Mail an Sie | Eine Aussage einer Person für eine Organisation | „<Name>, <Rolle> bei <Organisation>, sagte“ |
| Ein Community-Mitglied, Fürsprecher oder Partner | Eigene Meinung oder Erfahrung | „<Name>, der <Beziehung zu Exponential>, sagte“ |
| Ein Artikel Dritter | Die Darstellung des Autors | „<Medium> berichtete“; prüfen Sie es an den Primärquellen ([Wo die Fakten stehen, für die Presse](wo-die-fakten-stehen-fuer-die-presse.md)) |

## Fakten, die Sie ohne „laut“ nennen können

Fakten, die jeder in einem öffentlichen Nachweis prüfen kann, können Sie schlicht nennen, wenn Sie sie geprüft haben:

- „Exponential 6.0.14 wurde am 7. Juni 2026 getaggt“ (Git-Tag).
- „Die Software steht unter der GNU GPL, Version 2 oder später“ (LICENSE).
- „Der älteste Commit des Repositorys stammt vom September 2002“ (`git log`).

Selbstbeschreibungen und Bewertungen behalten immer ihre Zuordnung: „die Foundation beschreibt sich als gemeinnützige
Organisation nach 501(c)(3)“, „die README nennt Velocity die empfohlene Engine“.

## Fehler, die das Gewicht verändern

| Fehler | Wirkung | Korrektur |
|---|---|---|
| „7x sagte“ für einen Satz aus der README | Macht aus Dokumentation einen Sprecher | „die README sagt“ |
| „Experten sagen“ für den Beitrag eines Fürsprechers | Bläht eine Meinung auf | Nennen Sie die Person und ihre Beziehung |
| „das Unternehmen behauptet“ für einen geprüften Fakt | Weckt Zweifel an einem prüfbaren Fakt | Nennen Sie den Fakt mit seiner Quelle |
| Eine Pressemitteilung von 2024 als „sagte heute“ | Datiert eine Aussage falsch | Behalten Sie das Datum der Mitteilung |
| „das Exponential-Team“ für einen einzelnen Beitragenden | Bläht eine Stimme zu einer Gruppe auf | Nennen Sie die Rolle des Beitragenden |
| „Ibexa sagt“ für den Hinweis zur Umbenennung | Der Hinweis stammt vom Projekt, über die Bitte von Ibexa | „die Website des Projekts sagt, es habe sich auf Bitte von Ibexa umbenannt“ |

## Ihre Zuordnung datieren

Websites ändern sich. Wenn Sie eine Aussage einer Website zuordnen, ergänzen Sie, wann Sie sie gelesen haben, zumindest
in Ihren Notizen und am besten im Text: „die Website der Foundation sagte am 18. Oktober 2026“. Das Repository bewahrt
seinen Verlauf, sodass eine Datei immer zu einem Commit zitiert werden kann ([Daten prüfen](daten-pruefen.md)).
