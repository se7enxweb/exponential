# Stil und Schreibweise für Berichte

Diese Seite ist für Autoren und Redakteure in der Schlussredaktion, deren Texte zur Schreibweise des Projekts passen
sollen oder die entscheiden müssen, wie sie mit Fachbegriffen umgehen. Wo Ihr Hausstil abweicht, hat er Vorrang; diese
Seite sagt Ihnen, was das Projekt tut und warum, damit Sie wählen können.

## Schreibweise

Das Projekt schreibt seine englische Oberfläche und Dokumentation in **amerikanischem Englisch**: license (mit s),
color, behavior, organization, customize ([Regeln für Marke und Namen](../geschaeft/marken-und-namensregeln.md#sprache-und-schreibweise)).
Zitieren Sie den Text des Projekts so, wie er geschrieben ist, auch wenn Ihr Hausstil britisches Englisch vorsieht;
schreiben Sie Ihren eigenen Text so, wie Ihr Hausstil es verlangt.

## Namen von Produkten und Funktionen

| Schreiben Sie | Hinweise |
|---|---|
| Exponential | Großes E, ohne Artikel |
| Exponential Velocity, Velocity | Produktname, groß geschrieben |
| Exponential Intelligence | Produktname; nicht „Exponential AI“ |
| Exponential Layouts, der Layout-Editor | Produktname; der Editor ist ein Gattungsbegriff |
| das Hilfesystem, die Hilfe | Gattungsbegriffe |
| admin4, admin3 | Designnamen klein geschrieben, wie das Projekt sie schreibt |
| AdminUI | So, wie es geschrieben wird |
| die Content Security Policy, der Audit-Trail | Funktionsnamen als allgemeine Begriffe |

## Begriffe der Oberfläche

Verwenden Sie die Wörter, die der Leser auf dem Bildschirm sieht. Der eigene Hilfestil des Projekts bevorzugt Begriffe
der Oberfläche wie „object“, „content class“, „draft“ und „trash“ (in der deutschen Oberfläche „Objekt“,
„Inhaltsklasse“, „Entwurf“ und „Papierkorb“) ([Regeln für Marke und Namen](../geschaeft/marken-und-namensregeln.md#sprache-und-schreibweise)).
Schreiben Sie Namen von Menüs und Schaltflächen so, wie sie erscheinen, fett, wenn Ihr Stil das erlaubt: **Setup**,
**Zur Veröffentlichung schicken**, **Auf GitHub bearbeiten**.

## Code, Befehle und Dateien

- Bezeichner im Code, Dateinamen, Paketnamen und Befehle in Code-Schrift, wenn Ihr Medium das kann: `eZContentObject`,
  `SECURITY.md`, `expai`, `./console exp:install`.
- Übersetzen oder „korrigieren“ Sie Namen aus dem Code nie ([Warum es Exponential heißt](warum-es-exponential-heisst.md)).
- Paketnamen werden klein geschrieben, wie in `composer.json`.

## Zahlen, Versionen und Daten

| Element | Stil |
|---|---|
| Versionen | 6.0.14, ohne „v“; das „v“ gehört zu Git-Tags ([Versionsnummern im Text](versionsnummern-im-text.md)) |
| Zählungen | Mit dem Datum, an dem gezählt wurde ([Exponential in Zahlen](exponential-in-zahlen.md)) |
| Daten | So genau wie die Quelle: „1. Januar 2024“, „Dezember 2023“, „2022“ ([Daten prüfen](daten-pruefen.md)) |
| Geschwindigkeitswerte | Mit ihren Bedingungen: „0,36 ms pro gecachter Seite“ |

## Begriffe, die Sie allgemeinen Lesern erklären sollten

| Begriff | Einfache Erklärung |
|---|---|
| Content-Management-System (CMS) | Software, mit der man die Inhalte einer Website ohne Programmierung bearbeitet und veröffentlicht |
| Inhaltsmodell, Inhaltsklasse | Die Arten von Inhalten, die eine Website hat (Artikel, Veranstaltung, Produkt), und ihre Felder |
| Open Source, GPL | Jeder darf den Code nutzen, untersuchen, ändern und weitergeben |
| Fork | Eine Kopie einer Codebasis, die jemand eigenständig weiterführt |
| Siteaccess | Ein Zugang zu einer Installation: eine Website, eine Sprache oder die Administration |
| Multisite | Mehrere Websites, die von einer Installation aus betrieben werden |
| Entwurf | Eine Version, die noch nicht veröffentlicht ist |
| Webserver | Das Programm, das die Anfragen eines Browsers beantwortet |
| Von rechts nach links | Schriften wie Arabisch und Hebräisch, die von rechts nach links geschrieben werden |

Weitere Begriffe: [Glossar für Journalisten](glossar-fuer-journalisten.md).
