# Kommerzielle Bedingungen neben der GPL

Diese Seite ist für Designer, die mit einem Theme Geld verdienen wollen. Sie beschreibt Optionen so, wie die GPL
allgemein verstanden wird; fragen Sie für Ihre Verträge einen Anwalt. Preise behandelt [Preismodelle](../verkauf/preismodelle.md).

## Wofür Sie nach der GPL Geld verlangen dürfen

| Sie dürfen Geld verlangen für | Hinweis |
|---|---|
| Eine Kopie des Themes | Der Käufer darf sie dann unter der GPL weitergeben, auch kostenlos |
| Installation, Anpassung, Designarbeit | Eine Dienstleistung, keine Lizenz |
| Support und Wartung | Ein Vertrag über Ihre Zeit und Ihre Reaktion |
| Das Hosting einer Website mit dem Theme | Nutzen ist kein Verbreiten |
| Frühen Zugang zu neuen Versionen | Einmal verbreitet, steht die Kopie unter der GPL |

## Was Sie mit GPL-Code nicht tun können

- Käufern verbieten, den erhaltenen GPL-Code weiterzugeben, zu ändern oder weiterzuverkaufen.
- Den Quellcode des GPL-Codes den Personen vorenthalten, an die Sie ihn verbreitet haben.
- In Ihren Verkaufsbedingungen Einschränkungen über die GPL hinaus hinzufügen.

## Optionen, die beides verbinden

| Option | Wie sie funktioniert | Achten Sie darauf |
|---|---|---|
| GPL-Code, getrennt lizenzierte Assets | Templates und Code unter der GPL; Ihre Fotos oder Illustrationen zu Bedingungen Ihrer Wahl | Die Lizenz der Assets muss klar sagen, was sie abdeckt; das Theme muss ohne sie funktionieren |
| GPL-Code, bezahlte Dienstleistungen | Alles unter der GPL; Sie verkaufen Support, die Lieferung von Updates, Anpassungen | Das häufigste Modell in GPL-Ökosystemen |
| Ein proprietäres Theme | `LicenseRef-Proprietary` für alles | Templates und PHP, die in einem GPL-Programm laufen, können als abgeleitetes Werk gelten; holen Sie vor dieser Wahl rechtlichen Rat ein |

## Schritt für Schritt

1. Entscheiden Sie, was Code ist (GPL) und was ein Asset (Bedingungen Ihrer Wahl).
2. Formulieren Sie die Verkaufsbedingungen so, dass sie Dienstleistungen und Assets abdecken, nicht Freiheiten, die die
   GPL gewährt.
3. Nennen Sie die Lizenzen im README und auf Ihrer Produktseite getrennt.
4. Lassen Sie die Bedingungen vor dem ersten Verkauf von einem Anwalt prüfen.
