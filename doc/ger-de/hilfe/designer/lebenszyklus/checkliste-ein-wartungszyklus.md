# Checkliste: ein Wartungszyklus

Diese Seite ist für Designer, die einen Wartungszyklus durchführen. Kopieren Sie sie in ein Issue und haken Sie sie ab.

## Beobachten

- [ ] Changelog des neuen Releases von Exponential auf Auswirkungen für das Theme gelesen ([Ein Changelog lesen](ein-changelog-als-designer-lesen.md)).
- [ ] Issues und Sicherheitsmeldungen durchgesehen ([Sicherheitsmeldungen bearbeiten](sicherheitsmeldungen-bearbeiten.md)).
- [ ] Abhängigkeiten geprüft ([Abhängigkeiten aktuell halten](abhaengigkeiten-aktualisieren.md)).

## Testen

- [ ] Testinstallation aktualisiert ([Eine Upgrade-Testumgebung](upgrade-testumgebung.md)).
- [ ] Seitenliste durchgegangen, Logs sauber ([Upgrade-Test](upgrade-test-schritt-fuer-schritt.md)).
- [ ] Overrides mit den Standard-Templates verglichen ([Ihre Overrides vergleichen](overrides-mit-dem-standard-vergleichen.md)).
- [ ] Älteste und neueste PHP-Version geprüft ([PHP-Versionskompatibilität](php-versionskompatibilitaet.md)).

## Prüfen

- [ ] Barrierefreiheit ([Eine Prüfung der Barrierefreiheit](barrierefreiheitspruefung-pro-release.md)).
- [ ] Content Security Policy ([Eine CSP-Prüfung](csp-pruefung-pro-release.md)).
- [ ] Visuelle Regression in hell, dunkel und mit Zoom ([Visuelle Regressionsprüfungen](visuelle-regressionspruefungen.md)).
- [ ] Leistung ([Eine Leistungsprüfung](leistungspruefung-pro-release.md)).

## Veröffentlichen und mitteilen

- [ ] Korrekturen gemacht; Abkündigungen angekündigt oder abgeschlossen ([Eine Abkündigungsrichtlinie](abkuendigungsrichtlinie.md)).
- [ ] Kompatibilität angegeben ([Kompatibilität angeben](kompatibilitaet-angeben.md)).
- [ ] Release veröffentlicht ([Checkliste: vor der Veröffentlichung](../veroeffentlichung/checkliste-vor-der-veroeffentlichung.md)).
- [ ] Kunden und Community informiert ([Release Notes schreiben](../veroeffentlichung/release-notes-schreiben.md)).
