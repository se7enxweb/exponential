# Ein Wartungskalender

Diese Seite ist für Designer, die möchten, dass die Wartung geschieht, ohne dass sie daran denken müssen. Passen Sie den
Rhythmus an die Zeit an, die Sie haben; ein kleinerer Kalender, der eingehalten wird, ist besser als ein großer, der
ignoriert wird.

## Der Rhythmus

| Wann | Aufgabe | Seite |
|---|---|---|
| Wöchentlich | Neue Issues lesen; Änderungen an Exponential beobachten | [Releases von Exponential verfolgen](exponential-releases-verfolgen.md) |
| Bei jedem Release von Exponential | Upgrade-Test, dann bei Bedarf ein Theme-Release | [Upgrade-Test Schritt für Schritt](upgrade-test-schritt-fuer-schritt.md) |
| Bei jedem Theme-Release | Prüfungen von Barrierefreiheit, CSP, Optik und Leistung | [Barrierefreiheit](barrierefreiheitspruefung-pro-release.md), [CSP](csp-pruefung-pro-release.md) |
| Bei jeder Sicherheitsmeldung | Sofort bearbeiten | [Sicherheitsmeldungen bearbeiten](sicherheitsmeldungen-bearbeiten.md) |
| Vierteljährlich | Abhängigkeiten und ihre Lizenzen; fällige alte Abkündigungen | [Abhängigkeiten aktuell halten](abhaengigkeiten-aktualisieren.md), [Eine Abkündigungsrichtlinie](abkuendigungsrichtlinie.md) |
| Jährlich | Support-Richtlinie, Kompatibilitätsmatrix, PHP-Bereich, Screenshots, README | [Eine Support-Richtlinie](support-richtlinie-fuer-ihr-theme.md), [Eine Kompatibilitätsmatrix](kompatibilitaetsmatrix.md) |

## Schritt für Schritt

1. Tragen Sie die Zeilen in Ihren Kalender ein oder als wiederkehrende Issues im Repository des Themes.
2. Führen Sie zu jedem Zyklus ein kurzes Protokoll in einem Issue: was geprüft, was veröffentlicht wurde.
3. Überprüfen Sie den Rhythmus einmal im Jahr.
