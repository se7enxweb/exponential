# Wartungsabonnements

Diese Seite ist für Designer, die mit der Pflege von Themes wiederkehrende Einnahmen wollen. Wartung ist jedes Mal echte
Arbeit, wenn sich Exponential, PHP oder ein Browser bewegt; ein Abonnement bezahlt sie.

## Was ein Wartungszeitraum enthalten kann

| Arbeit | Seite, die sie beschreibt |
|---|---|
| Jedes neue Release von Exponential mit dem Theme testen | [Upgrade-Test Schritt für Schritt](../lebenszyklus/upgrade-test-schritt-fuer-schritt.md) |
| Updates für PHP-Versionen | [PHP-Versionskompatibilität](../lebenszyklus/php-versionskompatibilitaet.md) |
| Sicherheitskorrekturen | [Sicherheitskorrekturen in Themes](../lebenszyklus/sicherheitskorrekturen-in-themes.md) |
| Eine Prüfung der Barrierefreiheit | [Eine Prüfung der Barrierefreiheit bei jedem Release](../lebenszyklus/barrierefreiheitspruefung-pro-release.md) |
| Eine Prüfung der Content Security Policy | [Eine CSP-Prüfung bei jedem Release](../lebenszyklus/csp-pruefung-pro-release.md) |
| Updates von Bibliotheken | [Abhängigkeiten aktuell halten](../lebenszyklus/abhaengigkeiten-aktualisieren.md) |
| Updates auf der Website des Kunden installieren | Optional, gesondert berechnet oder in einer höheren Stufe |

## Schritt für Schritt: das Angebot festlegen

1. Wählen Sie die Arbeiten oben aus, die Sie in jedem Zeitraum erledigen.
2. Schreiben Sie den Zeitraum (Monat, Quartal, Jahr) und was darin geliefert wird.
3. Geben Sie an, was nicht enthalten ist (neue Funktionen, Redesigns).
4. Geben Sie an, was am Ende geschieht: Der Kunde behält den Code und jedes gelieferte Release (unter der GPL behält er
   das Recht, ihn zu nutzen und zu ändern); Updates und Support enden.
5. Legen Sie Bedingungen für Verlängerung und Kündigung fest ([Verträge und Bedingungen](vertraege-und-bedingungen.md)).

## Bewährte Praxis

- Führen Sie einen Wartungskalender ([Ein Wartungskalender](../lebenszyklus/wartungskalender.md)).
- Schicken Sie in jedem Zeitraum einen kurzen Bericht: getestete Releases, gemachte Korrekturen, Ergebnisse der Prüfungen.
- Halten Sie bei einem öffentlichen Theme nie eine Sicherheitskorrektur vor Nicht-Abonnenten zurück; veröffentlichen Sie
  sie für alle.
