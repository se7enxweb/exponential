# Kundendaten und Datenschutz

Diese Seite ist für Designer, die Themes verkaufen und unterstützen. Sie werden auf personenbezogene Daten treffen: Namen
und Adressen Ihrer Käufer und die Inhalte und Benutzer der Websites Ihrer Kunden. In vielen Ländern gilt
Datenschutzrecht; fragen Sie einen Anwalt, was für Sie gilt. **Dies ist keine Rechtsberatung.**

## Wo personenbezogene Daten auftauchen

| Wo | Regel |
|---|---|
| Bestellungen und Rechnungen | Nur behalten, was Sie brauchen; sicher speichern; eine Datenschutzerklärung veröffentlichen |
| Zugang zur Website eines Kunden | Ein eigenes Konto mit den geringsten Rechten verwenden; es entfernen, wenn Sie fertig sind |
| Datenbankkopien zum Debuggen | Vermeiden; wenn nötig, zuerst anonymisieren und danach löschen |
| Screenshots | Nur Demo-Inhalte ([Screenshot-Checkliste](../veroeffentlichung/screenshot-checkliste.md)) |
| Fehlermeldungen und öffentliche Issues | Nie Namen, E-Mails, Adressen, Passwörter oder Sitzungsdaten einfügen |
| Demo-Inhalte und Startdaten | Erfunden, nie von einem Kunden kopiert ([Demo-Inhalte](../veroeffentlichung/demo-inhalte.md)) |
| Fallstudien | Einen Kunden nur mit schriftlicher Einwilligung nennen ([Fallstudien](../../geschaeft/fallstudien-und-content-marketing.md)) |

## Schritt für Schritt

1. Listen Sie auf, wo personenbezogene Daten zu Ihnen gelangen.
2. Entscheiden Sie für jeden Ort: vermeiden, minimieren oder schützen.
3. Schreiben Sie eine Datenschutzerklärung für Ihre Website und eine kurze Datenklausel für Ihre Verträge.
4. Räumen Sie auf: Entfernen Sie regelmäßig alte Konten, Datenbankkopien und Exporte.

## Wenn etwas durchsickert

Wurden personenbezogene Daten versehentlich veröffentlicht (ein Screenshot, ein Commit), entfernen Sie sie, informieren Sie
den Kunden und folgen Sie den Meldepflichten Ihres Rechts. Ein gepushter Commit bleibt in der Historie: Holen Sie Hilfe,
bevor Sie ihn umschreiben.
