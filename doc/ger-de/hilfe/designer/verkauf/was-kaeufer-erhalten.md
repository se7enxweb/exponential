# Was Käufer erhalten

Diese Seite ist für Designer, die ein Theme oder eine Theme-Dienstleistung verkaufen. Viele Streitigkeiten beginnen mit
unterschiedlichen Vorstellungen davon, was gekauft wurde. Schreiben Sie es auf.

## Die Liste, die Sie für jedes Angebot füllen

| Punkt | Beispielantwort |
|---|---|
| Dateien | Die Theme-Erweiterung, der Quellcode allen CSS und JavaScripts, ein Paket mit Demo-Inhalten |
| Lizenz des Codes | GPL-2.0-or-later |
| Lizenzen der Assets | Fotos: zur Nutzung auf den Websites des Käufers lizenziert; Icons: CC BY 4.0 |
| Updates | Jedes Release der Linie 1.x für 12 Monate |
| Support | E-Mail, Antworten innerhalb von zwei Arbeitstagen, für eine Installation |
| Dokumentation | README, INSTALL.md, eine Konfigurationsanleitung |
| Kompatibilität | Getestet mit Exponential 6.0.15 und PHP 8.1 bis 8.5 |
| Nicht enthalten | Inhaltseingabe, Hosting, individuelle Änderungen |

## Schritt für Schritt

1. Füllen Sie die Tabelle für jedes Angebot.
2. Setzen Sie sie auf die Produktseite und in die Auftragsbestätigung ([Die Produktseite eines Themes schreiben](produktseite.md)).
3. Verweisen Sie in Ihren Bedingungen darauf ([Verträge und Bedingungen](vertraege-und-bedingungen.md)).
4. Liefern Sie genau das und nichts, was dem widerspricht.

## Regeln

- Geben Sie die Lizenz des Codes klar an. Ein Käufer von GPL-Code hat die Rechte der GPL, egal was in der Bestellung steht.
- Schreiben Sie Versionen, die Sie getestet haben, nicht Versionen, von denen Sie hoffen, dass sie funktionieren.
- Liefern Sie über ein privates Repository, sagen Sie, wie lange der Zugang besteht und was danach geschieht.
