# Reaktionszeiten und Zusagen

Diese Seite ist für Designer, die Versprechen in Support-Angebote schreiben. Ein verfehltes Versprechen kostet mehr
Vertrauen als ein bescheidenes, das gehalten wird.

## Zu definierende Begriffe

| Begriff | Definieren Sie |
|---|---|
| Erste Antwort | Wann der Kunde von einer Person hört, dass die Anfrage bearbeitet wird |
| Lösung | Wann das Problem behoben, umgangen oder beantwortet ist |
| Arbeitszeiten | Tage, Stunden und Zeitzone, Feiertage |
| Schweregrad | Zum Beispiel: Website ausgefallen; eine Funktion kaputt; ein optisches Problem; eine Frage |
| Uhr hält an | Solange Sie auf Informationen oder Zugang des Kunden warten |

## Schweregrade als Beispielstruktur

| Stufe | Bedeutung | Erste Antwort | Lösungsziel |
|---|---|---|---|
| 1 | Die Website ist wegen des Themes ausgefallen | (Ihr Wert) | (Ihr Wert) |
| 2 | Eine Hauptfunktion kaputt | (Ihr Wert) | (Ihr Wert) |
| 3 | Ein kleines oder optisches Problem | (Ihr Wert) | Nächstes Release |
| 4 | Eine Frage | (Ihr Wert) | - |

## Schritt für Schritt

1. Sehen Sie sich Ihre tatsächliche Verfügbarkeit über einen normalen Monat an.
2. Setzen Sie Werte darunter, mit Spielraum für Krankheit und Urlaub.
3. Organisieren Sie eine Vertretung für Stufe 1, oder versprechen Sie Stufe 1 nicht außerhalb der Arbeitszeiten.
4. Geben Sie in den Bedingungen an, was Sie tun, wenn Sie eine Zeit verfehlen (eine Gutschrift, eine Entschuldigung, eine
   Eskalation).
5. Messen Sie: Schreiben Sie auf, wann jede Anfrage eintraf, beantwortet und gelöst wurde.
