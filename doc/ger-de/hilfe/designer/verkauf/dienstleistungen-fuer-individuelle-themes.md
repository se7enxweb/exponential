# Dienstleistungen für individuelle Themes

Diese Seite ist für Designer, die Themes auf Bestellung bauen. Ein individuelles Theme ist ein Projekt; behandeln Sie es
wie eines.

## Die Phasen

| Phase | Lieferung | Endet, wenn |
|---|---|---|
| Bedarfsklärung | Ein kurzes Briefing: Zielgruppe, Ziele, Seiten, Inhaltsklassen, Sprachen | Der Kunde es bestätigt |
| Designentwürfe | Entwürfe der wichtigsten Seiten, hell und dunkel, wenn vereinbart | Der Kunde sie freigibt |
| Bau | Eine Theme-Erweiterung mit eigenem Repository ([Theme-Erweiterungen: hier beginnen](../erweiterungen/theme-erweiterungen-hier-beginnen.md)) | Alle Templates existieren |
| Review | Feedbackrunden auf einer Testseite | Die vereinbarten Runden genutzt oder freigegeben sind |
| Qualität | Barrierefreiheit, CSP, Breiten und Zoom geprüft ([Checkliste: Die Theme-Erweiterung ist bereit](../erweiterungen/checkliste-theme-erweiterung-bereit.md)) | Die Checkliste bestanden ist |
| Start | Das Theme auf der Live-Website | Es live ist |
| Übergabe | Dokumentation, eine Schulung für Redakteure, das Repository | Sie abgenommen ist |

## Die Eigentumsfrage

Entscheiden Sie vor dem Beginn und schreiben Sie es in den Vertrag ([Verträge und Bedingungen](vertraege-und-bedingungen.md)):

- Wem gehören das Design (das Aussehen) und die kundenspezifischen Assets?
- Steht der Code unter der GPL, und dürfen Sie allgemeine Teile in anderen Themes wiederverwenden?
- Dürfen Sie die Arbeit in Ihren Referenzen zeigen, und dürfen Sie den Kunden nennen?

## Schritt für Schritt

1. Führen Sie die Bedarfsklärung durch und schicken Sie das Briefing.
2. Erstellen Sie ein Angebot für das Projekt ([Preise für ein individuelles Theme-Projekt](preise-fuer-ein-individuelles-theme.md)).
3. Bauen Sie in einem Repository, auf das der Kunde Zugriff hat.
4. Testen Sie auf einer Staging-Website, die die Live-Website spiegelt.
5. Übergeben Sie mit einem README, einem Leitfaden für Redakteure und dem Wartungsangebot.
