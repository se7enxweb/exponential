# Ausschreibungsvorlagen

Dieser Abschnitt richtet sich an Beschaffungsstellen, Rechtsberatung und Projektleitungen, die Ausschreibung und Vertrag
für eine Website oder ein Intranet entwerfen, das auf Exponential oder einem anderen Open-Source-CMS beruht. Jede Seite
enthält Klauseltext in einem Block, den Sie kopieren können, mit `<placeholders>` und Lücken für jede Zahl: Diese Hilfe
schlägt nie Reaktionszeiten, Prozentsätze oder Preise vor. Jede Seite erklärt dann, was ein auf Exponential beruhendes
Angebot für die Klausel zeigen kann, mit Links zu den Nachweisen, und gibt Hinweise für die bewertende Person.

**Vorlage** - an Ihre Vergaberegeln anpassen; keine Rechtsberatung

> **Hinweis** Diese Seite beschreibt Funktionen und übliche Praxis; sie ist keine Rechtsberatung. Prüfen Sie das für
> Ihre Organisation geltende Recht mit Ihrer Rechtsberatung.

## Lesereihenfolge

1. Beginnen Sie mit der [Gliederung einer Leistungsbeschreibung](gliederung-einer-leistungsbeschreibung.md), um zu sehen, wohin jede Klausel
   gehört.
2. Schreiben Sie zuerst die Anforderungen ([Anforderungen an ein CMS für den öffentlichen Sektor](../anforderungen/README.md));
   die Klauseln verweisen darauf.
3. Ergänzen Sie die Qualitätsklauseln (Barrierefreiheit, Sicherheit, Patches, Datenschutz), dann die Leistungsklauseln
   (Hosting, Service-Levels, Support, Schulung, Dokumentation, Sprachen).
4. Schließen Sie mit den Klauseln ab, die langfristig schützen: Open Source, individuelle Entwicklungen, Abnahme,
   Ausstieg und kein Lock-in.
5. Lassen Sie das Ergebnis von Ihrer Rechtsberatung gegen Ihre Vergaberegeln prüfen.

## Konventionen auf diesen Seiten

- Klauselnummern (`X.1`, `Y.2` …) sind Platzhalter; nummerieren Sie sie in Ihrem Vertrag neu.
- Eckige Klammern markieren Optionen: Behalten Sie eine, löschen Sie die übrigen.
- Statusangaben für Exponential (Complies, Partly complies, Unverified, Does not comply) stammen von den
  [Seiten zu den Standards](../../../../../eng-us/standards/README.md) und werden hier nicht aufgewertet.
