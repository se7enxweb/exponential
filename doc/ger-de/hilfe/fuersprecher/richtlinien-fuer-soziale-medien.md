# Richtlinien für soziale Medien

Diese Seite ist für Fürsprecher, die in irgendeinem sozialen Netzwerk über Exponential schreiben. Beiträge verbreiten
sich schnell und weit, ohne Zusammenhang. Diese Richtlinien halten Ihre Beiträge nützlich, genau und sicher. Sie sind
Ratschläge für Ehrenamtliche, keine Regeln des Projekts; wo das Projekt Regeln hat (Namen, Sicherheit, Lizenzen),
nennen die unten verlinkten Seiten sie.

## Zehn Richtlinien

1. **Sprechen Sie als Sie selbst.** Ihr Profil sagt, wer Sie sind. Sie sprechen nicht für 7x oder die Foundation, es sei
   denn, Sie werden darum gebeten ([Offenlegung und Interessenkonflikte](offenlegung-und-interessenkonflikte.md)).
2. **Verlinken Sie eine Quelle** für jede Tatsache ([Wo die Fakten stehen](wo-die-fakten-stehen.md)).
3. **Ein Beitrag, ein Punkt.** Fügen Sie den Link hinzu, unter dem man mehr lesen kann.
4. **Verwenden Sie die richtigen Namen** ([Kurzkarte zu den Namensregeln](kurzkarte-namensregeln.md)).
5. **Seien Sie freundlich**, auch zu Kritikern und zu anderen Projekten ([Öffentlich antworten](oeffentlich-antworten.md)).
6. **Schützen Sie Menschen**: keine personenbezogenen Daten, keine Screenshots mit Namen, keine Kundennamen ohne
   Zustimmung ([Die Privatsphäre von Menschen schützen](privatsphaere-schuetzen.md)).
7. **Halten Sie Sicherheit vertraulich**: Veröffentlichen Sie nie Details zu Sicherheitslücken; verweisen Sie auf
   `SECURITY.md` ([Sicherheitsmeldungen bleiben vertraulich](sicherheitsmeldungen-bleiben-vertraulich.md)).
8. **Legen Sie offen**, wenn Sie bezahlt werden oder für einen Anbieter arbeiten.
9. **Korrigieren Sie Fehler offen** ([Aussagen, die Sie nicht machen dürfen](aussagen-die-sie-nicht-machen-duerfen.md#wenn-sie-sich-geirrt-haben)).
10. **Schicken Sie Fragen in die Kanäle**, wo andere die Antwort finden können: die Foren und Telegram
    ([Die Community-Kanäle](community-kanaele.md)).

## Gebote und Verbote

| Tun Sie | Tun Sie nicht |
|---|---|
| „Exponential 6.0.14 ist am 7. Juni 2026 erschienen (Link)“ | „Riesiges Release, alle wechseln!“ |
| Eine Hilfeseite teilen, die Ihr Problem gelöst hat | Ganze Hilfeseiten als Bilder einfügen |
| Andere nennen: „Danke an <Name> für die Korrektur“ (wenn öffentlich) | Die Arbeit anderer als Ihre ausgeben |
| Neugierig fragen „Was nutzt ihr für X?“ | Auf jede Erwähnung eines anderen CMS mit Exponential antworten |
| Eine Frage mit einem Link beantworten | In den Diskussionen anderer Communities streiten |
| Screenshots Ihrer Demo-Installation veröffentlichen | Screenshots der Administration echter Websites veröffentlichen |
| Die Adressen des Projekts so verwenden, wie sie geschrieben sind | Konten, Gruppen oder Hashtags „des Projekts“ erfinden |

## Namen und Links

- Exponential, Exponential 6, Exponential Velocity, Exponential Intelligence, Exponential Layouts, 7x, die Exponential
  Foundation. Der alte Name nur in der Vergangenheitsform.
- Verlinken Sie die Adressen, die die Dokumentation verwendet: `exponential.earth`, `share.exponential.earth/forums`,
  `t.me/exponentialcms`, `github.com/se7enxweb/exponential`, die Sponsorenseiten.
- Die Dokumentation nennt keine offiziellen Konten in sozialen Medien oder Hashtags. Stellen Sie kein Konto und keinen
  Hashtag als offiziell dar. Wenn Sie einen Hashtag verwenden, ist das Ihre Wahl; `#Exponential` allein ist mehrdeutig,
  geben Sie also im Text Zusammenhang.
- Discord und Slack werden auf exponential.earth/about/project nur „unter den Support-Kanälen genannt“; die Quellen
  geben hier keine Adressen an, also erfinden Sie keine ([Orte der Community](../wer-ist-die-exponential-foundation.md#orte-der-community)).

## Barrierefreiheit von Beiträgen

- Fügen Sie jedem Bild Alternativtext hinzu.
- Schreiben Sie den wesentlichen Text in den Beitrag, nicht nur in ein Bild.
- Schreiben Sie Hashtags in CamelCase (`#OpenSource`), damit Screenreader sie als Wörter lesen.
- Untertiteln Sie Videos ([Einen Screencast aufnehmen](einen-screencast-aufnehmen.md)).
- Vermeiden Sie Emoji-Wände; sie werden einzeln vorgelesen.

## Die Checkliste vor dem Veröffentlichen

```text
[ ] Is it true, and is the source linked?
[ ] Are the names right?
[ ] Does it contain anyone's personal data, a secret, a server address, a customer name? (then no)
[ ] Does it criticize another project or person? (then rewrite)
[ ] Do I need a disclosure?
[ ] Do images have alt text?
[ ] Would I be happy to see it quoted out of context?
```
