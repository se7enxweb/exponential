# Einwand: „Warum nicht ein anderes CMS?“

Diese Seite ist für Fürsprecher, die gefragt werden: „Warum nicht einfach ein bekannteres CMS?“ Die faire Antwort ist
nie „weil das andere schlecht ist“. Sie lautet: „Das kann Exponential, so prüfen Sie es, und hier passt es nicht.“ Die
Regeln stammen aus [Exponential sachlich vergleichen](../geschaeft/exponential-sachlich-vergleichen.md#die-regeln-eines-fairen-vergleichs).

## Die Regeln

1. **Vergleichen Sie Eigenschaften, nicht Ruf.** Eine Lizenzdatei, eine Release-Geschichte, eine Liste von Datenbanken.
2. **Jede Aussage hat eine Quelle.**
3. **Beschreiben Sie nie ein anderes Produkt.** Was ein anderes Produkt kann, findet die Person in dessen eigener
   Dokumentation.
4. **Datieren Sie Ihre Zahlen.**
5. **Nennen Sie die Grenzen von sich aus.**

## Zuerst nach dem Bedarf fragen

Die beste Antwort beginnt mit Fragen:

1. „Welche Inhalte verwalten Sie, und haben sie eine Struktur (Produkte, Veranstaltungen, Personen), oder sind es
   überwiegend Seiten?“
2. „Wie viele Websites und Sprachen?“
3. „Wer bearbeitet, und braucht man Freigaben und Versionen?“
4. „Welche Fähigkeiten und welches Hosting haben Sie?“
5. „Wie lange muss die Website leben?“

Ordnen Sie die Antworten dann den dokumentierten Stärken von Exponential zu oder sagen Sie ehrlich, dass es nicht am
besten passt.

## Wo Exponential gut passt

| Bedarf | Eigenschaft von Exponential | Quelle |
|---|---|---|
| Strukturierte Inhalte vieler Typen | Ein vollständig anpassbares Inhaltsmodell, in der Administration definiert | [Das Inhaltsmodell und das Bearbeiten von Inhalten](../../anleitungen/inhaltsmodell-und-bearbeitung.md) |
| Mehrere Websites und viele Sprachen aus einer Installation | Siteaccesses, Übersetzungen pro Inhalt, von rechts nach links | [Funktions-Highlights](../geschaeft/funktionshighlights-fuer-kunden.md#mehrere-sites-aus-einer-installation) |
| Redaktionelle Kontrolle | Entwürfe, Versionen, Freigabe-Workflows, ein Prüfprotokoll | [Funktions-Highlights](../geschaeft/funktionshighlights-fuer-kunden.md#strukturierte-inhalte-freigabe-und-versionen) |

## Wo es nicht passt

Sagen Sie das selbst. Jeder Punkt ist dokumentiert in
[Wo Exponential nicht passt](../geschaeft/exponential-sachlich-vergleichen.md#wo-exponential-nicht-die-richtige-wahl-ist):

- Microsoft SQL Server ist vorgeschrieben: kein Treiber in 6.0.x.
- Ein reines Symfony-Projekt ohne den Legacy-Kernel: Dann ist Exponential Platform DXP das passende Familienmitglied.
- Shared Hosting, das lang laufende Prozesse verbietet: Velocity kann dort meist nicht laufen.
- Mehr als 62 Inhaltssprachen in einer Installation.
- Eine vollständig übersetzte Administration in einer Sprache, die heute nicht vollständig ist.
- Ein veröffentlichtes SLA-Dokument: Das Projekt veröffentlicht keines; Verträge kommen von Anbietern.

## Antwortvorlagen

```text
NEUTRAL
Depends what you need. Exponential is strongest when content has structure (many content types),
when you run several sites or languages from one install, and when editors need versions and approvals.
If you mostly need a simple blog, other tools may suit you better. What are you building?

AFTER THEY DESCRIBE THEIR NEEDS
For <their need>, Exponential has <property> (<link>). You can try it in a few minutes on SQLite:
<link to Install in one command>. Compare it with the other options on the same checklist.

WHEN IT IS NOT A FIT
Honestly, for <their need> Exponential isn't the best fit: <documented limit> (<link>). Good luck with
the project - and if your needs change, the forums are open.
```

## Sagen Sie nicht

- Irgendetwas Negatives über ein anderes Produkt, sein Unternehmen oder seine Benutzer.
- „Exponential kann alles, was X kann.“
- „X ist unsicher / langsam / am Aussterben.“
- Zahlen zur Beliebtheit irgendeines Produkts.
