# Für wen Exponential ist: Personas und Branchen

Diese Seite ist für Mitarbeiter aus Vertrieb und Marketing, die entscheiden, wen sie ansprechen, und für Projektleiter,
die prüfen, ob ein Projekt zum Produkt passt. Sie beantwortet: Für welche Arten von Organisationen und für welche
Menschen ist Exponential laut seinen eigenen Quellen gemacht; welches Produkt der Exponential-Familie passt jeweils;
und an welchen Fragen erkennen Sie, ob ein Interessent gut passt.

Die Quellen beschreiben ihre Zielgruppen in allgemeinen Worten. Sie veröffentlichen **keine** Kundenlisten,
Marktanteile oder Statistiken darüber, wer das Produkt einsetzt, und diese Seite tut es ebenfalls nicht. Die Personas
unten sind Arbeitsmodelle, gebildet aus dem, was das Produkt laut den Quellen leistet und wem es laut ihnen dient.
Überprüfen Sie sie an Ihren eigenen Gesprächen.

## Käufer-Personas

Käufer sind die Menschen, die entscheiden oder die Entscheidung beeinflussen. Zu jeder Persona steht, was ihr wichtig
ist, was Sie zeigen und was Sie schicken. Die Zitate unter „Was ihnen wichtig ist“ sind typische Anliegen, keine Zitate
realer Personen.

### 1. Die digitale Führungskraft

| | |
|---|---|
| **Rolle** | Leitung Digital, Web oder Kommunikation |
| **Situation** | Betreibt eine oder mehrere Websites; Redakteure warten auf Entwickler; Sprachen und Marken werden immer mehr |
| **Was ihnen wichtig ist** | Tempo bei Änderungen, Unabhängigkeit der Redakteure, viele Sites und Sprachen, Gesamtkosten |
| **Einstieg mit** | Redakteure bauen Seiten mit Exponential Layouts; mehrere Sites und 268 Locales aus einer Installation; keine Lizenzgebühr |
| **Zeigen** | [Demo-Drehbücher](demo-drehbuecher.md), das 15-Minuten-Drehbuch: Dashboard, Bearbeiten, Layout-Editor, Sprachen |
| **Schicken** | [Funktionshighlights, den Bedürfnissen der Kunden zugeordnet](funktionshighlights-fuer-kunden.md), [Positionierung und Nutzenversprechen](positionierung-und-nutzenversprechen.md) |

### 2. Die IT- und Betriebsleitung

| | |
|---|---|
| **Rolle** | Leitung IT, Infrastruktur oder Hosting |
| **Situation** | Hat Standardbetriebssysteme, eine bevorzugte Datenbank, Sicherheitsregeln, einen Upgrade-Kalender |
| **Was ihnen wichtig ist** | Wo es läuft, mit welcher Datenbank, wie es gepatcht, abgesichert und überwacht wird |
| **Einstieg mit** | Fast jedes Betriebssystem mit PHP 8.0 oder später; sechs Datenbanken; jeder gängige Webserver oder Velocity; klare Regeln für Releases und Sicherheit |
| **Zeigen** | **Setup > Systeminformationen**, **Setup > Logdateien**, den Tab **Audit** |
| **Schicken** | [Unterstützte Betriebssysteme](../betriebssystemunterstuetzung.md), [Unterstützte Datenbanken](../datenbankunterstuetzung.md), [Sicherheitshärtung](../sicherheitshaertung.md), [Hosting, Datenbank und Betriebssystem auswählen](../fuehrung/hosting-datenbank-und-betriebssystem-waehlen.md) |

### 3. Die Verantwortlichen für Sicherheit und Compliance

| | |
|---|---|
| **Rolle** | Informationssicherheitsbeauftragte, Datenschutzbeauftragte, Prüfer |
| **Situation** | Müssen neue Systeme freigeben; verlangen Nachweise |
| **Was ihnen wichtig ist** | Zugriffskontrolle, Audit, Umgang mit Sicherheitslücken, Datenflüsse (auch die des Schreibassistenten) |
| **Einstieg mit** | Rollen und Richtlinien; das manipulationssichere Audit-Protokoll; die Content Security Policy; vertrauliche Meldung von Sicherheitslücken; die Datenrichtlinie von Exponential Intelligence und ihre druckbare Zusammenfassung für Datenschutzbeauftragte (`README.md`, „Safety“) |
| **Zeigen** | Den Tab **Audit**; eine Rollenseite, deren Richtlinien als Sätze dargestellt sind |
| **Schicken** | [Das Audit-Protokoll](../../../eng-us/features/6.0/audit-trail.md), [Content Security Policy](../../../eng-us/features/6.0/content-security-policy.md), [Checklisten für Barrierefreiheit, Sicherheit und Compliance](../fuehrung/checklisten-barrierefreiheit-sicherheit-und-compliance.md), `SECURITY.md` |

### 4. Die Betreiber einer älteren Site

| | |
|---|---|
| **Rolle** | Site-Betreiber oder IT-Verantwortliche einer Site, die gebaut wurde, als die Software noch eZ Publish hieß, oder die auf eZ Platform oder Ibexa läuft |
| **Situation** | Die Site funktioniert, läuft aber auf einem alten PHP oder einer nicht mehr gepflegten Version |
| **Was ihnen wichtig ist** | Die Inhalte und die Investition erhalten; das Risiko des Umzugs; wer die Site danach pflegt |

### 6. Die Ansprechpartner aus Einkauf oder Finanzen

| | |
|---|---|
| **Rolle** | Einkauf, Finanzen, Recht |
| **Was ihnen wichtig ist** | Lizenzbedingungen, Gesamtkosten, Ausstiegsmöglichkeiten |
| **Einstieg mit** | Kostenlos unter der GPL; keine Professional License mehr; Dienstleistungen werden separat gekauft, bei einem Anbieter nach Wahl des Kunden |
| **Schicken** | [Lizenzen für Käufer erklärt](lizenzen-fuer-kaeufer.md) (keine Rechtsberatung; die Entscheidung trifft ihre Rechtsabteilung) |

## Anzeichen, das Tempo herauszunehmen

Nicht jeder Interessent ist bereit, und das offen zu sagen schafft Vertrauen. Diese Anzeichen schließen einen Kunden
nicht aus; sie bedeuten, dass die Frage geklärt sein muss, bevor Sie etwas versprechen.

| Anzeichen | Warum es wichtig ist | Was zu tun ist |
|---|---|---|
| „Wir wollen einen Dienst, bei dem wir nie an Server denken müssen.“ | Exponential ist Software, die installiert wird; jemand muss sie hosten und betreiben | Benennen Sie, wer sie hostet: die IT des Kunden, ein Partner oder ein Managed-Hosting-Dienst, wie ihn 7x anbietet ([Dienstleistungen und Hosting](../wer-ist-7x.md#dienstleistungen-und-hosting)) |
| „Wir haben nur Shared Hosting.“ | Velocity braucht einen lang laufenden Prozess; „Shared Hosting erlaubt das in der Regel nicht“ (`README.md`) | Planen Sie Apache oder LiteSpeed mit `.htaccess` ein, wie es die README empfiehlt |
| „Wir brauchen die Funktionen X, Y und Z“, die keine Hilfeseite beschreibt | Nichts Undokumentiertes darf versprochen werden | Geben Sie es als Frage zum Projektumfang an den Projektleiter weiter ([Aufwand schätzen und Umfang festlegen mit Erweiterungen](../fuehrung/schaetzen-und-abgrenzen-mit-erweiterungen.md)) |
| „Wir brauchen eine Zertifizierung oder eine garantierte Support-Zeit.“ | Die Quellen nennen keine Zertifizierungen; `SECURITY.md` verspricht nur eine erste Antwort auf Sicherheitsmeldungen innerhalb eines Werktags | Sagen Sie, was die Quellen sagen; Service-Level sind Sache Ihres eigenen Vertrags |
| „Wir brauchen Microsoft SQL Server.“ | Es „ist bekanntermaßen mit zusätzlichem Aufwand möglich“, wird heute aber nicht unterstützt (`README.md`) | Lesen Sie [Unterstützte Datenbanken](../datenbankunterstuetzung.md) gemeinsam mit der IT des Kunden |
| „Unsere Site läuft auf PHP 7.“ | PHP 7.4 wird nur bis 6.0.7 unterstützt (`README.md`) | Planen Sie das PHP-Upgrade als Teil des Projekts ein |
| „Wir wollen einen reinen Symfony-Stack.“ | Der Kernel von Exponential 6 ist kein Symfony | Sehen Sie sich Exponential Platform DXP an ([Welches Produkt der Familie passt](#welches-produkt-der-familie-passt)) |
