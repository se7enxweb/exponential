# Lektion 5.1: Barrierefreie Kursmaterialien

Ein Kurs ist nur so barrierefrei wie seine Handouts. Wer einen Screenreader nutzt, kann den Screenshot eines Befehls
nicht lesen; wer schlecht sieht, kann grauen Text auf einer hellen Folie nicht lesen. Diese Lektion wendet einfache
Regeln auf Folien, Handouts und Übungen an und zeigt, welches Material Exponential bereits in barrierefreier Form
bereitstellt.

## Lernziele

Nach dieser Lektion können die Teilnehmenden:

- fünf Regeln auf Folien anwenden: echter Text, Kontrast, große Schrift, Alternativtext, keine Bedeutung allein durch
  Farbe;
- Befehle und Code als Text schreiben, niemals als Bild;
- Hilfeseiten und ihre PDFs als Handouts mit Überschriften und markierbarem Text nutzen;
- ein Handout mit einem Screenreader oder der Gliederung des Dokuments prüfen.

## Hinweise für Trainer

### So präsentieren Sie es

1. Gehen Sie [Barrierefreie Folien und Grafiken](../../../fuersprecher/barrierefreie-folien-und-grafiken.md) durch
   (8 Minuten): Folien, Bilder und Screenshots, Code auf Folien, Diagramme und Grafiken, die Checkliste.
2. Zeigen Sie die Hilfe als Handout (4 Minuten): Jede Hilfeseite hat Überschriften, ein Inhaltsverzeichnis und
   **Als PDF herunterladen**; mit einer TrueType-Schrift lässt sich der Text des PDFs markieren und durchsuchen, und
   die Überschriften werden zu Links.
3. Erwähnen Sie den Standard (3 Minuten): [Barrierefreiheitsstandards](../../../../standards/barrierefreiheit.md) zeigt,
   wie Exponential gegenüber WCAG 2.2 AA abschneidet, und nennt seine Lücken ehrlich.

### Häufige Fragen

**Sind Screenshots verboten?** Nein. Fügen Sie einen Alternativtext hinzu, der sagt, worauf es im Bild ankommt, und
zeigen Sie einen Befehl niemals nur in einem Screenshot.

**Ist die Administration barrierefrei?** Das Design Admin 4 wurde nach den Kriterien von WCAG 2.2 AA gebaut und
getestet; die Seite zu den Standards führt auf, was teilweise erfüllt und was nicht geprüft ist. Unterrichten Sie
nach Möglichkeit in Admin 4.

### Stolperfallen

- **Bilder von Text.** Befehle in Bildern lassen sich weder kopieren noch vorlesen.
- **Nur Farbe.** „Klicken Sie auf die rote Schaltfläche“ funktioniert für farbenblinde Teilnehmende nicht; nennen Sie
  die Beschriftung.
- **Winziger Code.** Code auf Folien braucht eine große Festbreitenschrift.

## Praktische Übung

1. Nehmen Sie eine Lektion dieses Kurses und machen Sie daraus ein zweiseitiges Handout.
2. Prüfen Sie: Jeder Befehl ist Text; jedes Bild hat einen Alternativtext; Überschriften sind echte Überschriften; der
   Kontrast ist hoch.
3. Laden Sie dieselbe Lektion im Hilfe-Center mit **Als PDF herunterladen** herunter und vergleichen Sie: Hat das PDF
   Überschriften, markierbaren Text und den Lizenzhinweis?
4. Lassen Sie sich Ihr Handout eine Minute lang von einem Screenreader (oder der Vorlesefunktion Ihres Systems)
   vorlesen. Notieren Sie alles, was übersprungen wurde oder verwirrend war.
5. Beheben Sie, was Sie gefunden haben.

## Erwartetes Ergebnis

- Ein zweiseitiges Handout, in dem jeder Befehl Text ist, jedes Bild einen Alternativtext hat und die Gliederung der
  Überschriften sinnvoll ist.
- Notizen aus dem Vorlesetest, mit umgesetzten Korrekturen.

## Quiz

1. Warum dürfen Befehle niemals nur in einem Screenshot erscheinen?
2. Welche WCAG-Version und welche Stufe strebt das Design Admin 4 an?
3. Was sagt ein guter Alternativtext für einen Screenshot?
4. Nennen Sie ein Problem mit „Klicken Sie auf die grüne Schaltfläche“.

<details>
<summary>Antworten</summary>

1. Sie lassen sich weder kopieren noch von einem Screenreader lesen.
2. WCAG 2.2, Stufe AA ([Barrierefreiheitsstandards](../../../../standards/barrierefreiheit.md)).
3. Was im Bild für die Aufgabe wichtig ist, nicht jedes Pixel.
4. Es verlässt sich allein auf die Farbe; nennen Sie die Beschriftung der Schaltfläche.

</details>
