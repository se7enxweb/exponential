## Was Sie veröffentlichen können

| Arbeit | Weg | Seite |
|---|---|---|
| Eine Erweiterung | Eigenes Repository, Packagist, aufgeführt unter Projects | [Erweiterungen zurückgeben](../../erweiterungen-zurueckgeben.md) |
| Ein Theme | Eine Design-Erweiterung, wie oben | [Verteilung (Designer)](../../designer/veroeffentlichung/ein-theme-veroeffentlichen-hier-beginnen.md) |
| Ein Seitenpaket | Ein Pull-Request an die Quellen der Pakete | [Ihr Seitenpaket beitragen](../../seitenpakete/ihr-seitenpaket-beitragen.md) |
| Eine Korrektur oder Funktion für den Kernel | Ein Pull-Request | [Code beitragen](../../gemeinschaft/mitwirken/code-beitragen.md) |
| Dokumentation | Ein Pull-Request, eZpedia oder Share | [Dokumentation und Hilfeseiten beitragen](../../gemeinschaft/mitwirken/dokumentation-und-hilfeseiten-beitragen.md) |
| Eine Übersetzung | Ein Pull-Request | [Übersetzungen beitragen](../../gemeinschaft/mitwirken/uebersetzungen-beitragen.md) |

## Selbst veröffentlichen oder zum Projekt beitragen

| | Selbst veröffentlichen | Zum Projekt beitragen |
|---|---|---|
| Wer es pflegt | Sie | Das Projekt |
| Copyright | Ihres | Über das CLA an die Exponential Foundation und 7x übertragen, für Kernel-Code und Code, der zur Aufnahme übergeben wird |
| Lizenz | Ihre Wahl; GPL 2 oder später empfohlen | GPL 2 oder später (Code), GNU FDL (Dokumentation) |

Quelle: `CONTRIBUTING.md`, "What it does not cover"; [Das CLA erklärt](../../gemeinschaft/mitwirken/das-cla-erklaert.md).

## Bevor Sie veröffentlichen

Verwenden Sie die [Release-Checkliste](../../erweiterungsentwicklung/teil-7-veroeffentlichen/die-release-checkliste.md) und die
[Checklisten zum Ökosystem](../checklisten-zum-oekosystem.md): keine Geheimnisse oder Kundendaten, eine Lizenzdatei,
Versionsfelder gleich dem Tag, eine `composer.json`, eine README mit den unterstützten Versionen.
