# Site packages no longer install extension packages

Since 6.0.15 no site package requires the extension packages `ezwt_extension`, `ezstarrating_extension` or
`ezgmaplocation_extension`. Composer installs ezstarrating and ezgmaplocation (root `composer.json`). The installers
activate them as before, and their tables come from each extension's own `share/db_schema.dba`. The website sidebar
expwt takes the place of ezwt in every installer's `extension_list`.

This concerns `sevenx_site`, `sevenx_site_clean`, `ezwebin_site`, `ezwebin_site_clean`, `ezflow_site`,
`ezflow_site_clean`, `ezdemo_site` and `ezdemo_site_clean` (the `<requires>` of `package.xml`), and the installers of
these packages and of `sevenx_multisite`, `sevenx_multisite_clean` and `cjw_multisite` (`extension_list` and the
tables).

## Why

An extension package carried a copy of the extension's files, and installing the site package wrote that copy over
the copy Composer had installed. Since 6.0.15 the package handler keeps a copy that Composer or git manages (see
[A site package keeps the newer installed extension](package-install-keeps-newer-extensions.md)). The packages then
only cost a download, and the site setup wizard stopped at the site selection when one of them was missing.

## What changes

| Before | Since 6.0.15 |
|---|---|
| `package.xml` requires `ezwt_extension`, `ezstarrating_extension`, `ezgmaplocation_extension` | no such `<require>` |
| the installer activates `ezwt` | the installer activates `expwt`, the website sidebar |
| the tables of ezstarrating and ezgmaplocation from the package's copy (`insertDBFile()`, `declaredExtensionSchemas()` named the package) | from `extension/ezstarrating/share/db_schema.dba` and `extension/ezgmaplocation/share/db_schema.dba` (`expInstallDefaultExtensions::ensureExtensionTables()`) |
| an active extension's missing tables on an existing installation: by hand | the upgrade step `6.0.15-active-extension-tables` |

The three extension packages are taken off the 6.0.15 folder of the package server once the rebuilt site packages are
published. The folders of earlier versions (6.0.0 to 6.0.14) are left as they were published.

## What you do

- **New installation**: nothing. Run `composer install` before the setup wizard or `exp:install`, as always.
- **Existing installation**: run `./console exp:upgrade` (dry run first). The step `6.0.15-active-extension-tables`
  creates the tables of every active extension that ships a `share/db_schema.dba` and lacks them. It creates
  nothing where the tables are there. ezwt moves to expwt with `./console exp:wt:migrate-from-ezwt --apply` (step
  `6.0.15-expwt-enable`).
- **A site package of your own** that requires one of the three packages: remove the `<require>` and keep the name
  in `extension_list`. If the installer created the tables from the package (`$package->path() . '/ezextension/...'`),
  call `expInstallDefaultExtensions::ensureExtensionTables( '<extension>', eZExtension::baseDirectory() )` instead.
