# The migrationpush.php cronjob

Migrations: push the record of the runs whose push failed to the migrations repository's remote again.

Entry point `cronjobs/migrationpush.php`, code in `kernel/private/classes/cronjobs/migrationpush.php`.

> The cronjob part migrationpush (cronjobs/migrationpush.php; \[CronjobPart-migrationpush\] in cronjob.ini): pushes the  
> commits and tags of the migration runs whose push failed (exp\_migration\_run.push\_state pending) to the remote of  
> the migrations repository again (expMigrationRepository::retryPushes()). Does nothing while no run waits.  

## When it runs

In the shipped `settings/cronjob.ini` it belongs to: the part `migrationpush`.

```bash
# run its part (as the user the web server runs as, from the installation root)
php runcronjobs.php migrationpush
./console exp:runcronjobs migrationpush
# run only this script
php runcronjobs.php migrationpush
```

Add it to a part in an override:

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/cronjob.ini.append.php
[CronjobPart-migrationpush]
Scripts[]=migrationpush.php
*/ ?>
```
