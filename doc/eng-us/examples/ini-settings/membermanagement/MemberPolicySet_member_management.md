# membermanagement.ini [MemberPolicySet_member_management]

The block `[MemberPolicySet_member_management]` of `settings/membermanagement.ini`, with 1 setting(s).

> A policy set: Policies\[\] lines of the form module/function\[;Limitation=value,value;...\]. Class and ParentClass take  
> class identifiers. Every content policy whose function takes a Subtree limitation gets one: the rule's managed  
> groups. Policies outside the content module get no Subtree (user/preferences opens user/setting, which the guard and  
> SettingRequiresEdit above still limit to the accounts the manager may edit).  

Never edit `settings/membermanagement.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/membermanagement.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/membermanagement.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/membermanagement.ini.append.php` in an extension (read when the extension is active).

## Policies

Default: a list of 9: `content/read`, `content/create;Class=user,user_group;ParentClass=user_group`, `content/edit;Class=user,user_group`, `content/remove;Class=user,user_group`, `content/manage_locations;Class=user,user_group`, `content/versionread`, `content/versionremove`, `content/diff`, `user/preferences`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/membermanagement.ini.append.php
[MemberPolicySet_member_management]
# an empty "Policies[]" first replaces the shipped list; without it the items are added
Policies[]
Policies[]=content/read
```
