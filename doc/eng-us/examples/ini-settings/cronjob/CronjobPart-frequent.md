# cronjob.ini [CronjobPart-frequent]

The block `[CronjobPart-frequent]` of `settings/cronjob.ini`, with 1 setting(s).

Never edit `settings/cronjob.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/cronjob.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/cronjob.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/cronjob.ini.append.php` in an extension (read when the extension is active).

## Scripts

> Content jobs whose worker died, or that nobody started (kernel/classes/contentjob/)  
> The data table synchronisations that are due (doc/eng-us/features/6.0/data-tables.md; nothing without them)  
> The audit: sink spools, alert rules; once a day rotation, archives, retention and the  
> checkpoint (audit.ini \[AuditRotationSettings\] RotateAfter). Here so that an installation  
> running only the frequent group needs no extra crontab line.  
> The bounce mailbox (mailpreferences.ini \[BounceSettings\]; does nothing until it is set up)  
> The GraphQL webhooks: the events of the journal to their end points, with retries (graphql.ini \[GraphQLWebhooks\];  
> does nothing until one is configured)  

Default: a list of 7: `notification.php`, `workflow.php`, `contentjobs.php`, `datatablesync.php`, `audit.php`, `mailbounces.php`, `graphqlwebhooks.php`.
