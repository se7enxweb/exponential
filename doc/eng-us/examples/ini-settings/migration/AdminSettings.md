# migration.ini [AdminSettings]

The block `[AdminSettings]` of `settings/migration.ini`, with 5 setting(s).

Never edit `settings/migration.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/migration.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/migration.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/migration.ini.append.php` in an extension (read when the extension is active).

## PhpCliPath

> Setup > Migrations (module migration) starts a run or a rollback as a console process of its own, which goes on when  
> the page is closed; its files are in var/<site>/migration/jobs/.  
>
> The php command line binary those processes run with. Empty: cronjob.ini \[AdminSettings\] PhpCliPath, else the  
> usual places (the bin directory of this php, /usr/bin/php, /usr/local/bin/php). Never the php-fpm binary.  

Default: empty.

```ini
# settings/override/migration.ini.append.php
[AdminSettings]
PhpCliPath=
*/ ?>
```

## Background

> How a run started there goes to the background:  
>   process  a console process of its own, started at once (the default)  
>   queue    a job of expqueue (the extension), run by its worker, when expqueue is active, its tables are installed,  
>            expqueue.ini has the job type below and a worker is running; else a process as above  
> The job type, in the site's expqueue.ini.append.php:  
>   \[JobType\_migration.run\]  
>   Handler=expMigrationQueueHandler  
>   Class=bulk  
>   Timeout=86400  
>   Description=A migration run started in Setup > Migrations  

Default: `process`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/migration.ini.append.php
[AdminSettings]
Background=process
*/ ?>
```
