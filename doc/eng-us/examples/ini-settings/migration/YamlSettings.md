# migration.ini [YamlSettings]

The block `[YamlSettings]` of `settings/migration.ini`, with 1 setting(s).

Never edit `settings/migration.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/migration.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/migration.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/migration.ini.append.php` in an extension (read when the extension is active).

## LibraryPath

> YAML migrations (YYYYMMDDHHMMSS\_name.yml) are read with symfony/yaml, which composer.json requires. An  
> installation that keeps it outside its Composer vendor/ names the folder here: a Composer directory (with  
> vendor/autoload.php) or the package itself (the folder with Yaml.php), relative to the root or absolute. The  
> environment variable MIGRATION\_YAML\_LIBRARY\_PATH is read the same way when this is empty.  

Default: empty.
