# exphelp.ini [LandingSettings]

The block `[LandingSettings]` of `settings/exphelp.ini`, with 7 setting(s).

Never edit `settings/exphelp.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/exphelp.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/exphelp.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/exphelp.ini.append.php` in an extension (read when the extension is active).

## Enabled

> exphelp/audience/<audience>: a landing page per audience (expHelpLanding, doc/eng-us/features/6.0/help-system.md "Landing  
> pages"). enabled: the dashboard's audience cards open it; disabled: the view is a 404 and the cards open the search.  

Default: `enabled`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/exphelp.ini.append.php
[LandingSettings]
Enabled=enabled
*/ ?>
```

## Blocks

> The blocks of every landing page, in order. \[Landing\_<audience>\] Blocks\[\] replaces the list for one audience.  
>   hero: name, summary, a search box and buttons    start: the reading path ("start here")  
>   boxes: info boxes, pages with their summaries    categories: a search button per category  
>   key: the key pages                               latest: recently updated pages for the audience  
>   related: related audiences                       commits: the latest commits of the project (\[CommitFeedSettings\])  
>   support: the Support Exponential block (\[SupportSettings\])  

Default: a list of 7: `hero`, `start`, `boxes`, `categories`, `key`, `latest`, `related`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/exphelp.ini.append.php
[LandingSettings]
# an empty "Blocks[]" first replaces the shipped list; without it the items are added
Blocks[]
Blocks[]=hero
Blocks[]=start
Blocks[]=boxes
Blocks[]=categories
Blocks[]=key
Blocks[]=latest
Blocks[]=related
*/ ?>
```
