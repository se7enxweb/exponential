# site.ini [Cache_exphelpcontent]

The block `[Cache_exphelpcontent]` of `settings/site.ini`, with 5 setting(s).

> The rows of help maintained as content (var/<site>/cache/exphelp/content/repository-\*.cache).  
> It checks itself against the help subtree on every request and reads again only  
> the objects that changed, so it needs no clearing after a publish; clearing it  
> makes the next help page read every help object (a few seconds).  

Never edit `settings/site.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/site.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/site.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/site.ini.append.php` in an extension (read when the extension is active).
