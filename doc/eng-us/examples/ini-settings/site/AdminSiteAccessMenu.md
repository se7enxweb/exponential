# site.ini [AdminSiteAccessMenu]

The block `[AdminSiteAccessMenu]` of `settings/site.ini`, with 5 setting(s).

Never edit `settings/site.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/site.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/site.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/site.ini.append.php` in an extension (read when the extension is active).

## Show

> The site menu of the administration (designs admin4 and admin4l): the globe  
> button in the header opens a list of this installation's siteaccesses with  
> their addresses. Its first entry opens the site, as the globe did; the  
> others are grouped into sites and administrations, and the siteaccess in use  
> is marked. Signed-in users only. The addresses are worked out as  
> siteaccess\_url() does, with the scheme of the request: each siteaccess gets  
> the first address that the matching rules (host\_uri, host and uri, in  
> MatchOrder order) lead back to it with no part of the path left over. Tried  
> in turn: this host with its HostUriMatchMapItems entry or its URI element,  
> its own \[SiteSettings\] SiteURL, a host that HostMatchMapItems gives it, then  
> one of its host\_uri entries on another host. Where none of them can be shown  
> to lead there, its URI element on this host is used as before (else its  
> SiteURL as written, else this host).  
> Read from the settings of the administration siteaccess.  
>
> enabled or disabled; disabled leaves the globe a plain link to the site  

Default: `enabled`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[AdminSiteAccessMenu]
Show=enabled
*/ ?>
```

## List

> related: \[SiteAccessSettings\] RelatedSiteAccessList\[\] of this siteaccess (the  
> siteaccesses sharing its database), or this siteaccess alone where it is  
> empty; available: AvailableSiteAccessList\[\]. Only siteaccesses of  
> AvailableSiteAccessList\[\] are listed either way. An installation that serves  
> several sites sets RelatedSiteAccessList\[\] for each administration to list  
> its own site's siteaccesses.  

Default: `related`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[AdminSiteAccessMenu]
List=related
*/ ?>
```

## HiddenSiteAccessList

> Siteaccesses left out of the menu. The site the globe opens (FrontSiteAccess,  
> else DefaultAccess) is always its first entry.  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[AdminSiteAccessMenu]
# an empty "HiddenSiteAccessList[]" first replaces the shipped list; without it the items are added
HiddenSiteAccessList[]
*/ ?>
```

## AdminSiteAccessList

> The siteaccesses that count as administrations. Empty: those whose  
> \[DesignSettings\] SiteDesign begins with "admin", or that set a  
> \[SiteSettings\] FrontSiteAccess.  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/site.ini.append.php
[AdminSiteAccessMenu]
# an empty "AdminSiteAccessList[]" first replaces the shipped list; without it the items are added
AdminSiteAccessList[]
*/ ?>
```

## ListAdministrations

> disabled: the menu lists sites only; enabled: the administrations too, as a
