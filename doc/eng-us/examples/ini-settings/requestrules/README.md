# requestrules.ini

The shipped settings of `settings/requestrules.ini`: 4 blocks, 19 settings.

> Request rules: what happens to a request before its module view runs.  
>
> Guide with every condition, action and fact, and recipes:  
>   doc/en/us/bc/6.0/view\_full\_security.md  
>
> A rule is a group \[Rule-<name>\] with conditions and an action. The rules  
> named in RuleList\[\] are asked in that order about every module view the  
> kernel is about to run -- after the URL alias is translated and after the  
> user's role policies allowed the view. The first rule whose conditions all  
> match decides; when none does, the request runs as it always has.  
>
> Rules only ever take access away or send the visitor elsewhere. They never  
> give access that a policy refused.  
>
> Do not edit this file. Override it in  
>   settings/override/requestrules.ini.append.php           every siteaccess  
>   settings/siteaccess/<name>/requestrules.ini.append.php  one siteaccess  
>   extension/<name>/settings/requestrules.ini.append.php   from an extension  
>
> Check the settings and see what the rules decide for any address with  
>   php bin/php/ezrequestrules.php -s <siteaccess> --check  
>   php bin/php/ezrequestrules.php -s <siteaccess> --uri=content/view/full/2
