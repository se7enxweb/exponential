# rest.ini [ApiProvider]

The block `[ApiProvider]` of `settings/rest.ini`, with 1 setting(s).

Never edit `settings/rest.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/rest.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/rest.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/rest.ini.append.php` in an extension (read when the extension is active).

## ProviderClass

> Context help of help maintained as content for clients with a token (an OAuth token or a personal API key with  
> the scope help): /api/help/v1/topic/<help\_id>, /api/help/v1/manual/<remote\_id> (doc/eng-us/features/6.0/help-content.md)  
> The GraphQL API, /api/graphql (settings/graphql.ini, off until enabled; doc/eng-us/features/6.0/graphql.md)  

Default: a hash of 3: `auth=ezpRestAuthProvider`, `help=expHelpRestProvider`, `graphql=expGraphQLRestProvider`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/rest.ini.append.php
[ApiProvider]
# an empty "ProviderClass[]" first replaces the shipped list; without it the items are added
ProviderClass[]
ProviderClass[auth]=ezpRestAuthProvider
ProviderClass[help]=expHelpRestProvider
ProviderClass[graphql]=expGraphQLRestProvider
*/ ?>
```
