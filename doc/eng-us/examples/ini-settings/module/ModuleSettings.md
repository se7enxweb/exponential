# module.ini [ModuleSettings]

The block `[ModuleSettings]` of `settings/module.ini`, with 3 setting(s).

Never edit `settings/module.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/module.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/module.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/module.ini.append.php` in an extension (read when the extension is active).

## ModuleRepositories

> An array of directories to search for modules  

Default: a list of 2: `kernel`, `kernel/private/modules`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/module.ini.append.php
[ModuleSettings]
# an empty "ModuleRepositories[]" first replaces the shipped list; without it the items are added
ModuleRepositories[]
ModuleRepositories[]=kernel
ModuleRepositories[]=kernel/private/modules
*/ ?>
```

## ExtensionRepositories

> A list of extensions which have modules  
> It's common to create a settings/module.ini.append file  
> in your extension and add the extension name to automatically  
> get modules from the extension when it's turned on.  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/module.ini.append.php
[ModuleSettings]
# an empty "ExtensionRepositories[]" first replaces the shipped list; without it the items are added
ExtensionRepositories[]
*/ ?>
```

## ModuleList

> An array of known modules in the system, extensions should  
> append to this array.  
> This is currently used to avoid URL aliases overriding  
> existing module names  
> The data tables and the named database connections (doc/eng-us/features/6.0/data-tables.md)  
> The kernel's secret store (doc/eng-us/features/6.0/secret-store.md)  

Default: a list of 36: `apikey`, `audit`, `class`, `collaboration`, `contentcheck`, `csp`, `contentfinder`, `content`, `datatable`, `error`, `exphelp`, `ezinfo` ....
