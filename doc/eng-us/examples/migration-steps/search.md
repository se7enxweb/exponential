# search

Reindexes objects in the search engine (the ones named or the ones the run changed), or every object.

A step of a YAML migration with `type: search`. The class `expMigrationStepSearch` (`kernel/classes/migration/steps/expmigrationstepsearch.php`) is registered in `settings/migration.ini` `[StepSettings] StepTypeList[search]`.

## Modes

`mode:` is one of `reindex`, `full`; without it, `reindex`.

## Keys

| Key | Type | Modes | Default | What it is |
|---|---|---|---|---|
| `objects` | `list` | reindex |  | the objects (id, remote:, path:); without: the objects the run created or changed so far |
| `classes` | `list` | full |  | only the objects of these classes (identifiers) |
| `queue` | `bool` | all | `true` | true: queued for the cronjob indexcontent; false: indexed at once |

Besides these, every step takes the keys of the engine: `type`, `mode`, `if`, `references`, `environments`, `engines` and `comment` ([the file format](../../specifications/6.0/migration-file-format.md#a-step)). A key of type `identifier` names a node, an object or another part of the installation by id, remote id, path or name ([identifiers](../../specifications/6.0/migration-file-format.md#identifiers-and-the-id-map)).

## Values for references

`references: { <name>: <value> }` keeps a value of the step's result as `${ref.<name>}` for the steps and migrations after it:

| Value | What it is |
|---|---|
| `count` | how many objects were queued or indexed |

## Undoing

Every step of this type undoes itself when its migration is rolled back without `down:`.

It touches no cache.

## Example

```yaml
- type: search
  mode: reindex
  objects: [ "remote:home" ]
  queue: false
```
