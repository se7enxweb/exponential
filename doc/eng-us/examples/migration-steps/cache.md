# cache

Clears caches of ezcache by id or tag and the view caches of single objects, at once or after the run.

A step of a YAML migration with `type: cache`. The class `expMigrationStepCache` (`kernel/classes/migration/steps/expmigrationstepcache.php`) is registered in `settings/migration.ini` `[StepSettings] StepTypeList[cache]`.

## Keys

| Key | Type | Default | What it is |
|---|---|---|---|
| `caches` | `list` |  | ids of ezcache: content, template-block, exphttpcache, template-override ... |
| `tags` | `list` |  | tags of ezcache: ini, template, content, image ... (every cache with the tag) |
| `objects` | `list` |  | objects (id, remote:, path:) whose content view caches are cleared |
| `when` | `string`: `end`, `now` | `"end"` | end: cleared once after the run with the caches of the other steps; now: cleared at once |

Besides these, every step takes the keys of the engine: `type`, `mode`, `if`, `references`, `environments`, `engines` and `comment` ([the file format](../../specifications/6.0/migration-file-format.md#a-step)). A key of type `identifier` names a node, an object or another part of the installation by id, remote id, path or name ([identifiers](../../specifications/6.0/migration-file-format.md#identifiers-and-the-id-map)).

## Values for references

`references: { <name>: <value> }` keeps a value of the step's result as `${ref.<name>}` for the steps and migrations after it:

| Value | What it is |
|---|---|
| `caches` | the ids and tags the step clears (or leaves for the end), comma-separated |
| `objects` | how many objects had their view caches cleared |

## Undoing

Every step of this type undoes itself when its migration is rolled back without `down:`.

It touches no cache.

## Example

```yaml
- type: cache
  caches: [ template-block ]
  tags: [ ini ]
  objects: [ "remote:home" ]
  when: now
```
