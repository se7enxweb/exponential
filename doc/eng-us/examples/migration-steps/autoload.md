# autoload

Regenerates the autoload array of the extensions or of the kernel classes extensions replace.

A step of a YAML migration with `type: autoload`. The class `expMigrationStepAutoload` (`kernel/classes/migration/steps/expmigrationstepautoload.php`) is registered in `settings/migration.ini` `[StepSettings] StepTypeList[autoload]`.

## Keys

| Key | Type | Default | What it is |
|---|---|---|---|
| `scope` | `string`: `extension`, `kernel-override` | `"extension"` | extension: the classes of the extensions; kernel-override: the kernel classes extensions replace |

Besides these, every step takes the keys of the engine: `type`, `mode`, `if`, `references`, `environments`, `engines` and `comment` ([the file format](../../specifications/6.0/migration-file-format.md#a-step)). A key of type `identifier` names a node, an object or another part of the installation by id, remote id, path or name ([identifiers](../../specifications/6.0/migration-file-format.md#identifiers-and-the-id-map)).

## Values for references

`references: { <name>: <value> }` keeps a value of the step's result as `${ref.<name>}` for the steps and migrations after it:

| Value | What it is |
|---|---|
| `file` | the autoload array written, below the root |

## Undoing

Every step of this type undoes itself when its migration is rolled back without `down:`.

It touches no cache.

## Example

```yaml
- type: autoload
  scope: extension
```
