# exp:expstaticrollback

Roll a static publishing target back to an earlier publish: a new commit with the files of that tag, tagged and pushed; the history stays.

Script `bin/php/expstaticrollback.php`, code in `kernel/private/classes/commands/expstaticrollback.php`. Run it from the installation root, as the user the web server runs as:

```bash
./console exp:expstaticrollback --help
./console exp:static:rollback --help
php bin/php/expstaticrollback.php --help
```

## Help text

```text
Roll a static site back to an earlier publish
Names an earlier publish by its number or its tag static/<target>/<n> (exp:static:status lists
them) and lists what would change. With --apply it makes a new commit that holds the files of that
publish, tags it with the next number and pushes it: nothing is deleted from the history, no tag is
moved and the push is never forced, so a rollback can itself be rolled back.

./console exp:static:rollback github-public 4                 what would change
./console exp:static:rollback github-public 4 --apply
./console exp:static:rollback github-public static/github-public/4 --apply --no-push
```

## Options

| Option | Value | Help |
|---|---|---|
| `--apply` |  | Make the rollback commit; without it the command only lists what would change |
| `--message` | required | The commit message (default: what was published, or which publish is restored) |
| `--no-push` |  | Commit and tag, but do not push (exp:static:push pushes later) |
| `--format` | required | text (default) or json (the machine output exp-static/1) |
| `--login` | required | Run as this user (the administration starts its jobs so); recorded as who ran it |
| `--run-id` | required | The id of the run (date-time-6 hex digits) instead of a new one (the administration passes its job's id) |
| `--progress` | required | Also append the progress, one JSON object per line, to this file (the administration follows it) |
