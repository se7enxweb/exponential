# Designing support tiers

This page is for designers who want more than one level of support. Tiers should differ in things a customer can feel
and you can deliver.

## Dimensions that can differ

| Dimension | Lower tier | Higher tier |
|---|---|---|
| Channel | Public issues, email | Email, phone or chat |
| First response | Longer | Shorter |
| Sites covered | One | Several |
| Included change time | None | Some hours per month |
| Updates | Releases as published | Releases installed for the customer |
| Security | Fix in the next release | Fix and install, with notice |

## A template to fill

| | Community | Standard | Priority |
|---|---|---|---|
| Who | Everyone | Paying customers | Paying customers |
| Channel | Public issues, forum | Email | Email and phone |
| First response | No promise | (your value) | (your value) |
| Sites | - | (your value) | (your value) |
| Change hours | - | - | (your value) |
| Price | Free | (your value) | (your value) |

Fill the values only with what you can keep for months, also when you are ill or on holiday.

## Step by step

1. Pick two or three dimensions; more confuse buyers.
2. Fill the template with values you can deliver.
3. Write what is not included in every tier.
4. Publish the table on the product page.
