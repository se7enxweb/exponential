# Custom theme services

This page is for designers who build themes to order. A custom theme is a project; treat it like one.

## The phases

| Phase | Deliverable | Ends when |
|---|---|---|
| Discovery | A short brief: audience, goals, pages, content classes, languages | The client confirms it |
| Design drafts | Drafts of the key pages, light and dark if in scope | The client approves them |
| Build | A theme extension with its own repository ([Theme extensions: start here](../extensions/theme-extensions-start-here.md)) | All templates exist |
| Review | Rounds of feedback on a test site | Agreed rounds used or approved |
| Quality | Accessibility, CSP, widths and zoom checked ([Checklist: the theme extension is ready](../extensions/checklist-theme-extension-ready.md)) | Checklist passed |
| Launch | The theme on the live site | Live |
| Handover | Documentation, an editor session, the repository | Accepted |

## The ownership question

Decide before you start, and write it in the contract ([Contracts and terms](contracts-and-terms.md)):

- Who owns the design (the look) and the client-specific assets?
- Is the code GPL, and may you reuse general parts in other themes?
- May you show the work in your portfolio, and may you name the client?

## Step by step

1. Run discovery and send the brief.
2. Quote the project ([Pricing a custom theme project](pricing-a-custom-theme.md)).
3. Build in a repository the client can access.
4. Test on a staging site that mirrors the live one.
5. Hand over with a README, an editor guide and the maintenance offer.
