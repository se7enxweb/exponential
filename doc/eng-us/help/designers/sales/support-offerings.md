# Support offerings

This page is for designers who want to offer support for a theme. "Support" means different things to different
customers; define it.

## What support can include

| Element | Example definition |
|---|---|
| Questions | How to configure and use the theme, by email or a ticket system |
| Bug fixes | A defect in the theme, reproduced on a supported version, fixed in a release |
| Compatibility | Updates for new Exponential and PHP releases ([Following Exponential releases](../lifecycle/following-exponential-releases.md)) |
| Security fixes | Within a stated time after a report ([Security fixes in themes](../lifecycle/security-fixes-in-themes.md)) |
| Small changes | Up to an agreed amount of time per month |
| Emergency help | Outside office hours, at an agreed rate |
| Not included | Content work, other extensions, the customer's own template changes |

## Paid and community support side by side

The `se7enxweb` organization publishes a `SUPPORT.md` that separates commercial support (a company's services) from
community support (a chat and the public issues). Doing the same keeps both clear: the public issue tracker stays open
to everyone, and paying customers get response times.

## Step by step

1. Choose the elements you offer.
2. Write a definition for each, as in the table.
3. Decide tiers, if any ([Designing support tiers](support-tiers.md)), and the times you can keep
   ([Response times and commitments](response-times-and-commitments.md)).
4. Publish a `SUPPORT.md` and a support page on your site.
5. Set up one channel per kind of request ([Issue tracker and support channel](../distribution/issue-tracker-and-support-channel.md)).
