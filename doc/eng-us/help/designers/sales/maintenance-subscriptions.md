# Maintenance subscriptions

This page is for designers who want recurring income from keeping themes healthy. Maintenance is real work every time
Exponential, PHP or a browser moves; a subscription pays for it.

## What a maintenance period can contain

| Work | Page that describes it |
|---|---|
| Testing each new Exponential release with the theme | [Upgrade testing, step by step](../lifecycle/upgrade-test-step-by-step.md) |
| PHP version updates | [PHP version compatibility](../lifecycle/php-version-compatibility.md) |
| Security fixes | [Security fixes in themes](../lifecycle/security-fixes-in-themes.md) |
| An accessibility audit | [An accessibility audit for every release](../lifecycle/accessibility-audit-per-release.md) |
| A Content Security Policy audit | [A CSP audit for every release](../lifecycle/csp-audit-per-release.md) |
| Library updates | [Keeping dependencies up to date](../lifecycle/dependency-updates.md) |
| Installing updates on the customer's site | Optional, priced separately or in a higher tier |

## Step by step: define the offer

1. Pick the work items above you will do in every period.
2. Write the period (month, quarter, year) and what is delivered in it.
3. State what is not included (new features, redesigns).
4. State what happens at the end: the customer keeps the code and every release delivered (under the GPL they keep
   the right to use and change it); updates and support stop.
5. Set renewal and cancellation terms ([Contracts and terms](contracts-and-terms.md)).

## Good practice

- Keep a maintenance calendar ([A maintenance calendar](../lifecycle/maintenance-calendar.md)).
- Send a short report each period: releases tested, fixes made, audit results.
- Never hold back a security fix from non-subscribers of a public theme; publish it for everyone.
