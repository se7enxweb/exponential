# Handing over keys and secrets at exit

This page is for project managers who must make sure nothing secret is lost or left behind when a supplier leaves,
and for the administrators who do the handover. Some secrets of an Exponential site are generated by the software and
cannot be recreated; losing them breaks things no content restore can repair. Others must be changed after the old
supplier has gone. The facts come from [Backups: what to back up](../../../hosting/operations/backups-what-to-back-up.md)
and [Moving a site between hosts](../../../hosting/migrations/moving-a-site-between-hosts.md).

## Secrets that cannot be recreated

| Secret | Where | If lost |
|---|---|---|
| Audit signing and pseudonym keys | `settings/override/audit.ini.append.php` | existing audit records can no longer be verified as intact ([Audit trail](../../../../features/6.0/audit-trail.md)) |
| Mail preferences site secret | `settings/override/mailpreferences.ini.append.php`, `[SecretSettings] TokenSecret` | every unsubscribe link in every mail already sent stops working, and the suppression list stops matching ([Mail preferences for administrators](../../../../guides/mail-preferences-administrator.md)) |
| Velocity certificate private keys | Velocity's configuration tree, `ssl/` (`/etc/vc` or `var/vc/qbix/etc`) | HTTPS on Velocity must be set up again |

Hand these over with the backup, and keep them: do not regenerate them on the new host.

## Secrets to rotate after the exit

These can be changed, and should be, because the old supplier knew them:

| Secret | Where | How |
|---|---|---|
| Database password | `settings/override/site.ini.append.php`, `[DatabaseSettings]` | change on the database server and in the setting; the hosting offboarding checklist tells the customer to change it at the new host ([Customer offboarding](../../../hosting/checklists/customer-offboarding.md)) |
| Mail server credentials | `[MailSettings]` | change with the mail provider |
| Passwords of administrator accounts | the user accounts | change, or remove the accounts ([Change the admin password](../../../change-the-admin-password.md)) |
| Personal API keys and OAuth clients | **Setup > oAuth admin** | revoke keys of the old supplier's staff ([Personal API keys](../../../../guides/api-keys.md)) |
| Two-step sign-in of the old supplier's staff | their accounts | removed with the accounts ([Two-step sign-in](../../../../guides/two-factor-login.md)) |
| Third-party service keys (maps, captcha, AI providers, analytics) | settings of the extensions | regenerate at each provider, update the settings |
| Server, SFTP, panel and Git access | outside Exponential | remove or change |

## How to transfer secrets

- Transfer `settings/override/` and other secret files over an encrypted channel, never in a ticket, chat, e-mail
  or public repository ([Moving a site between hosts](../../../hosting/migrations/moving-a-site-between-hosts.md#settings-that-name-the-old-machine)).
- Store them encrypted, readable only by named roles.
- In documentation, write where a secret is kept, never the secret itself ([Documentation handover](documentation-handover.md)).
- The system report of **Setup > System information** leaves passwords and keys out, so it can be shared; settings
  files cannot ([System information](../../../../guides/system-information.md)).

## Accounts to remove

- Administration accounts of the old supplier's staff: remove them, or deactivate them if your records rules require
  keeping them. **Check user accounts** (`/user/hygiene`) helps find accounts unused for a time
  ([Check user accounts](../../../../features/6.0/user-hygiene.md)).
- Their role assignments, API keys and sessions (**Setup > Sessions**, [Sessions](../../../../guides/sessions.md)).
- Their access to servers, panels, monitoring and repositories.

## Checklist

- [ ] Audit keys, mail preferences secret and certificate keys received, stored encrypted, not regenerated.
- [ ] Database, mail and service credentials rotated after the move.
- [ ] Old supplier's accounts, API keys and sessions removed in the administration.
- [ ] Old supplier's access to servers, panels and repositories removed.
- [ ] `./console exp:audit verify` reports the chain intact with the transferred keys.
- [ ] Rotation recorded in the exit plan with dates.
