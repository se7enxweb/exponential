# The first 90 days for schools and universities

This page is for project managers and administrators who start an education site on Exponential. Time the launch to
the academic year: never in the weeks before an admissions deadline or at the start of term. It assumes an
installation exists ([Getting started](../../../../guides/getting-started.md)).

## Contents

1. [Days 1 to 30: central site and governance](#days-1-to-30-central-site-and-governance)
2. [Days 31 to 60: model, departments, intranet](#days-31-to-60-model-departments-intranet)
3. [Days 61 to 90: content, training, launch](#days-61-to-90-content-training-launch)
4. [The first year](#the-first-year)

## Days 1 to 30: central site and governance

| Step | Output |
|---|---|
| Set the launch date against the academic calendar | a date outside deadline periods |
| Decide the department model: pages in the central site, or subsites | a decision ([Intranets and department subsites](intranets-and-department-subsites.md)) |
| Name a content owner per department | a list |
| Decide how staff and students sign in (manual accounts, import, directory) | a decision; development planned if needed |
| Agree a photo consent rule with the data protection officer | a written rule ([Requirements](requirements-emphasis.md)) |
| Inventory admissions and program content | an inventory |

## Days 31 to 60: model, departments, intranet

| Step | Check |
|---|---|
| Create Program, Course, Department and Policy document classes ([Content model](content-model.md)) | a test program lists its courses |
| Build the public tree and department sections ([Structure](structure-sections-and-roles.md)) | logged out, departments open |
| Build the intranet sections and reader roles | logged out, the intranet is closed; as a test student it opens |
| Create department subsites if chosen (siteaccesses) | each subsite answers on its host |
| Turn on two-step sign-in for staff | the web team has set it up |
| Test the design's accessibility | no open serious finding |

## Days 61 to 90: content, training, launch

| Step | Read |
|---|---|
| Write admissions and program pages first | [What schools and universities publish](what-it-publishes.md) |
| Train department editors by department | [Editors 101](../../../trainers/editors-101/README.md) |
| Redirect old program and admissions addresses (prospective students bookmark them) | [Redirects and moved content](../../../creators/website-creators/redirects-and-moved-content.md) |
| Publish the accessibility statement and privacy notice | [Accessibility for site builders](../../../creators/website-creators/accessibility-for-site-builders.md) |
| Launch | [Launch checklist](../../../creators/website-creators/launch-checklist.md) |

Checks at launch:

- [ ] Every program page shows its deadline and links to the application system.
- [ ] Search finds programs by the words prospective students use.
- [ ] Staff and student test accounts reach what they should and nothing more.

## The first year

| When | Task |
|---|---|
| Before admissions open | update programs, deadlines, fees |
| Start of the year | create accounts for new students and staff; check intranet access |
| End of the year | disable leavers (**Users > Check user accounts**), archive the year's news and events |
| Yearly | review policies whose review date has passed |
