# Before a tender

This checklist is for the procurement officer and project manager of a public body, before the tender is published.
It points to the procurement section of this help for each step.

> **Note** This page describes features and common practice; it is not legal advice. Check the procurement law and
> rules that apply to your organization with your procurement and legal counsel.

## Contents

## Needs

- [ ] Goals of the site written down: audiences, services, languages, volume of content.
- [ ] Current site and content inventoried ([Site map and content inventory](../../creators/website-creators/site-map-and-content-inventory.md)).
- [ ] Legal duties listed with counsel: accessibility, privacy, records, languages, FOI.
- [ ] What you buy decided: software services, implementation, hosting, support, training, or a combination ([Procuring Exponential in the public sector](../procurement/README.md)).

## Requirements

- [ ] Requirements written so each can be verified ([Requirements](../procurement/requirements/README.md)).
- [ ] Each requirement mapped to the evidence you will ask for; where the open source project has none (VPAT, ASVS assessment, SLA), ask bidders to provide it ([Procuring Exponential](../procurement/README.md#what-the-repository-can-and-cannot-evidence)).
- [ ] Accessibility target stated (for example WCAG 2.2 AA for the public site) ([Accessibility standards](../../../standards/accessibility.md)).
- [ ] Hosting and data location stated.
- [ ] No requirement that only one product or supplier can meet without reason.

## Market and evidence

- [ ] A test installation tried by your own team: `./console exp:install --apply` on SQLite ([Installing Exponential in one command](../../../features/6.0/install-in-one-command.md)).
- [ ] The standards pages read: [accessibility](../../../standards/accessibility.md), [security](../../../standards/security.md), [privacy](../../../standards/privacy.md).
- [ ] Supported versions and release policy understood ([Supported versions](../procurement/lifecycle/supported-versions.md)).
- [ ] Possible suppliers and partners known ([Partners: start here](../../partners/partners-start-here.md)); market consultation done within your rules.

## Evaluation

- [ ] Criteria and weights fixed and published with the tender ([Evaluation](../procurement/evaluation/README.md)).
- [ ] Panel named, conflicts of interest declared.
- [ ] Demo script and proof-of-concept tasks prepared.
- [ ] Reference check questions prepared.

## Money and time

- [ ] Budget built on total cost of ownership over the whole term, not the first year ([Total cost of ownership](../procurement/total-cost-of-ownership/README.md)).
- [ ] Training budget ([Budgeting training effort](../procurement/training/budgeting-training-effort.md)).
- [ ] Upgrade and security update effort per year ([Planning upgrades in the budget](../procurement/lifecycle/planning-upgrades-in-the-budget.md)).
- [ ] Timeline with the tender period, evaluation, standstill and build.

## The end, planned at the start

- [ ] Exit requirements and clauses in the tender ([Exit plans](../procurement/exit-plans/README.md)).
- [ ] Ownership of custom code and documentation stated; custom extensions delivered under the GPL into a repository you control ([Licensing questions](../../project/licensing-faq.md)).
- [ ] Tender clauses drafted from the [Tender templates](../procurement/tender-templates/README.md).
