# Editorial quality checklist

This checklist is for editors and approvers in a public body, for every page before it is published. It is short on
purpose; print it or keep it next to the editor. The features it mentions are explained in
[Editing content](../../editing-content.md) and [Publishing and versions](../../publishing-and-versions.md).

## Contents

1. [Content](#content)
2. [Structure and accessibility](#structure-and-accessibility)

## Content

- [ ] Facts, dates, amounts, names and contact details checked against the source.
- [ ] The most important information comes first.
- [ ] Written in plain language for the intended audience ([Plain language checklist](plain-language-checklist.md)).
- [ ] No personal data that does not need to be public.
- [ ] Spelling and style as your organization's guide says.

## Structure and accessibility

- [ ] One main heading; sub-headings in order, not chosen for their size.
- [ ] Lists for lists, tables only for data, with header rows.
- [ ] Link texts that say where they lead ("Apply for a permit", not "click here").
- [ ] No information by color alone; no text in images.
- [ ] More in [Editors 201, Module 8: quality and accessibility](../../trainers/editors-201/module-08-quality-and-accessibility/README.md).

## Links, images and documents

- [ ] Every link tested in the preview.
- [ ] Images: informative ones have alternative text; decorative ones are marked so; sizes fit ([Images and image variations](../../creators/website-creators/images-and-image-variations.md)). Nothing in the software forces the field to be filled ([Accessibility standards](../../../standards/accessibility.md#known-gaps)).
- [ ] Documents are accessible, current and named clearly; consider an HTML page instead of a PDF ([Files and downloads](../../creators/website-creators/files-and-downloads.md)).
- [ ] Rights to use every image and document are clear.

## Metadata and placement

- [ ] Title and summary make sense in search results and on social media ([Metadata and social sharing](../../creators/website-creators/metadata-and-social-sharing.md)).
- [ ] Tags set where your site uses them ([Tagging with eztags](../../creators/website-creators/tagging-with-eztags.md)).
- [ ] Placed in the right section and location; extra locations added where readers will look ([Relations and reuse](../../creators/website-creators/relations-and-reuse.md)).
- [ ] The address (URL alias) is readable ([URL aliases and nice URLs](../../creators/website-creators/url-aliases-and-nice-urls.md)).

## Review and publish

- [ ] Previewed in the site's design, and on a phone width.
- [ ] Translations ready, or the page marked as available in one language only ([Multilingual checklist](multilingual-checklist.md)).
- [ ] Sent for approval where a workflow requires it; the approver checks this list too ([Workflows](../../../guides/workflows.md)).
- [ ] A version note or comment explains a significant change, for the history ([Versions of an object](../../../guides/content-history.md)).

## After publishing

- [ ] Check the published page as a visitor (signed out).
- [ ] If an old page is replaced, redirect or link it ([Redirects and moved content](../../creators/website-creators/redirects-and-moved-content.md)).
- [ ] Unfinished drafts cleaned up ([My drafts and my pending items](../../../guides/drafts-and-pending.md)).
- [ ] A review date set for content that will go out of date.
