# Archive last year's notices

For editors and administrators. A yearly routine for notices, announcements or news: they leave the current list but stay
available and keep their history ([Archiving old notices](../../records-and-archiving/archiving-old-notices.md)).

## Contents

1. [Before you start](#before-you-start)
2. [Steps](#steps)
3. [Check that it worked](#check-that-it-worked)
4. [Related pages](#related-pages)

## Before you start

- Agreement with the records manager on what is archived (by date, by class) and whether archived notices stay public.
- An "Archive" folder under the notices (create it once); the year folders go inside it.
- Rights to create folders and move content in that part of the tree.

## Steps

1. Create the folder "Archive" > "<last year>" under the notices folder.
2. In the notices folder's sub-items list, sort by publication date; select last year's notices (a page at a time).
3. **Move** them into the year folder (the context menu or the Move button); confirm the destination.
4. If the archive must not be public, put it into an archive section (Assign content on the archive folder) whose read
   policy excludes Anonymous, or set an archive state ("Object states for records").
5. Check that the current list's template fetches only the notices folder's direct children (not the archive), so the
   archive does not reappear there; ask the developer if unsure.
6. Write a note: date, number of items, folder.

## Check that it worked

- The current list shows only this year's notices.
- An old notice's previous address redirects to its new place (moved nodes keep a history alias).
- The audit shows the moves: `/audit/console/(name)/content.node.move`.
