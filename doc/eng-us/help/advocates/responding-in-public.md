# Responding in public

This page is for advocates who see Exponential mentioned in public: on social media, in other communities' forums, in
reviews, in comments. Not every mention needs you. When one does, your reply should leave the conversation better than
it was.

## Should you reply at all?

| The mention | Reply? |
|---|---|
| Praise | A short thank-you, maybe a useful link |
| A question | Yes, with a link, or point to the forums |
| A bug report in the wrong place | Yes: thank them and point to the right tracker |
| A security problem posted publicly | Yes, privately if possible: ask them to remove details and report via `SECURITY.md` |
| A factual error about Exponential | Once, politely, with a source |
| An opinion you disagree with | Usually no |
| Criticism that is right | Yes: acknowledge it, point to where it is tracked, help fix it |
| A discussion in another community that does not mention Exponential | No: do not advertise in others' threads |
| Hostility | See [Handling hostile threads](handling-hostile-threads.md) |

## Reply patterns

```text
PRAISE
Glad it helped! If you haven't seen it yet, <related help page or feature> is worth a look: <link>

QUESTION
Good question. <Short answer> - details here: <link>. If it doesn't fit your case, the forums are a good
place to ask: share.exponential.earth/forums

BUG IN THE WRONG PLACE
Thanks for reporting! So it gets fixed, could you open an issue here: <tracker link>? The help's
"Report an error" page prepares one for you. Please leave out passwords and personal data.

SECURITY DETAILS POSTED PUBLICLY
Thanks for finding this. Could you remove the details here and send them privately as described in
SECURITY.md (security@se7enx.com)? That way it can be fixed before others misuse it.

FACTUAL ERROR
Small correction: <fact> (<source link>). Things changed quite a bit since <year> - the history pages
explain it: <link>

RIGHT CRITICISM
You're right, <the problem>. It's tracked here: <issue link> / I've opened an issue: <link>. If you'd like
to help, a pull request is welcome - every one is merged.
```

## Turning mentions into improvements

Every public complaint or confusion is information:

| Mention | Turn it into |
|---|---|
| The same question asked three times | A help page improvement ([Improving the help](improving-the-help.md)) |
| A bug described in a post | An issue with a reproduction ([Reporting bugs well](reporting-bugs-well.md)) |
| A misunderstanding of a feature | A clearer talking point, a tutorial ([Writing a tutorial that works](writing-a-tutorial-that-works.md)) |
| A wish | A discussion in the community tracker ([Which tracker for which report](which-tracker-for-which-report.md)) |
| A great review | A thank-you; ask if you may quote it, with consent |

## What never to do

- Reply from an account that looks official if it is not.
- Ask the author to delete honest criticism.
- Argue about taste ("our admin is prettier").
- Attack another product to defend Exponential.
- Reveal private information about the author.
- Promise fixes or dates.
