(`README.md`, "How to contribute new features and bugfixes into Exponential"). Contributions are not only code:
reports, translations, documentation, tests and shared extensions all count.

## What each kind of contribution needs

| Contribution | GitHub account | Code skills | Signed CLA |
|---|---|---|---|
| A bug report or an idea | Yes | No | No |
| A confirmation of someone else's bug | Yes | No | No |
| A typo fix on a help page | Yes | No | Sign it anyway before a merge into the kernel repository; see [The CLA explained](the-cla-explained.md) |
| A translation of the interface or the help | Yes | No | As for any change to the kernel repository |
| A code fix or feature in the kernel | Yes | Yes | Yes, before the merge |
| An extension you publish yourself | Only for GitHub | Yes | No |
| An answer in the forums | A Share account | No | No |

The kernel repository is `se7enxweb/exponential`: "`kernel/`, `lib/`, `bin/`, `design/`, `settings/`, `doc/`, the
extensions shipped inside it, and everything else in this repository" (`CONTRIBUTING.md`, "Copyright assignment (CLA)").

## The rules that apply to all

- **Licenses.** Code is GPL version 2 or later; documentation is GNU FDL 1.3 or later. What you contribute is
  published under the same license (`CONTRIBUTING.md`, "Licensing"; [Free documentation](../../free-documentation.md)).
- **The code of conduct** applies to every contribution, including AI-assisted ones
  ([The code of conduct](../joining/the-code-of-conduct.md)).
- **No secrets or personal data** in issues, pull requests, examples or screenshots.
- **Security problems are private** (`SECURITY.md`).
- **Some bugs are negative features.** Behavior that is deliberate or open to interpretation, and that other sites
  depend on, changes only with a clear justification, preferably as an option rather than a new default, and often
  after several rounds of review ([Negative features](../../project/getting-support.md#negative-features)).
