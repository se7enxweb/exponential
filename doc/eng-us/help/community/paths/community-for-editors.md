# The community for editors

Editors are the largest group of people who use Exponential every day, and the group whose experience developers
most need to hear about.

## What editors can give back

| Contribution | Why it matters | Page |
|---|---|---|
| Fix or extend editor help pages | Editors know which steps are missing | [Contributing documentation and help pages](../contributing/contributing-documentation-and-help-pages.md) |
| Translate the interface | Editors notice wrong or missing words first | [Contributing translations](../contributing/contributing-translations.md) |
| Describe usability problems | Developers rarely edit content all day | [Describing a usability problem](#describing-a-usability-problem) |
| Share an editorial workflow | Other teams can copy it | [Writing tutorials and posts](../helping-others/writing-tutorials-and-posts.md) |
| Test new editor features on the development line | Find problems before release | [Testing releases](../contributing/testing-releases.md) |
| Answer other editors | Editors explain to editors best | [Answering questions](../helping-others/answering-questions.md) |

None of these need programming.

## Describing a usability problem

A usability problem is a real bug for the people who meet it. Describe it like this:

```text
Task: <what I wanted to do, e.g. move ten articles to another folder>
Steps: <what I clicked>
Problem: <what was slow, confusing or impossible>
Design and browser: <admin design, browser, screen size or zoom>
Idea (optional): <what would help>
```

File it on the software tracker ([Filing a bug](../contributing/filing-a-bug.md)). A screenshot helps, without
private content.
