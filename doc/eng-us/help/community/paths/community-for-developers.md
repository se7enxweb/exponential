## Working with the code

- Install from Git clones so that a fix is "a branch in your fork and a pull request away"
  ([When something goes wrong](../../when-something-goes-wrong.md)).
- Watch the repositories you depend on; read the changelogs ([Staying informed](../joining/staying-informed.md)).
- Test your extensions against `main` before a release ([Testing releases](../contributing/testing-releases.md)).

## Rules every developer meets

- Commit messages with `Added:`, `Updated:`, `Fixed:`, `Removed:` or `Renamed:`; the manifest line for every changed
  file; squash and rebase (`CONTRIBUTING.md`).
- New code uses the `exp` prefix; existing `eZ*` identifiers are never renamed
  ([Naming prefixes](../../../standards/naming-prefixes-sevenx-and-exp.md)).
- The CLA for kernel contributions ([The CLA explained](../contributing/the-cla-explained.md)).
- AI-assisted code: you are responsible for it and say when a substantial part was generated (`CODE_OF_CONDUCT.md`).
