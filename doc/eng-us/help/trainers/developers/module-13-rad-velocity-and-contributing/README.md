# Module 13: RAD, Velocity and contributing

The course ends with three things a working developer uses every week: the RAD tools that write and survey
extension code, the Velocity deploy that puts a PHP change live in the right order, and a pull request that gives a
fix back to the project.

## At a glance

| | |
|---|---|
| Course | [Developers](../README.md) |
| Duration | 2 hours 30 minutes (with one 10-minute break) |
| Lessons | 3 |
| Level | Intermediate |

## Lessons

| Lesson | Duration | What learners do |
|---|---|---|
| [Lesson 13.1: The RAD tools](the-rad-tools.md) | 45 minutes | Generate an operator extension, read the survey and health check |
| [Lesson 13.2: Velocity for developers](velocity-for-developers.md) | 45 minutes | Engines, restart, `exp:velocity deploy` with a dry run first |
| [Lesson 13.3: A pull request](a-pull-request.md) | 50 minutes | A branch, a focused commit, the checks, a push to a fork, the description |

## Preparing this module

- Administrator accounts for **Setup** > **RAD** (`setup/setup` policy).
- For lesson 13.2 step 7, a Qbix engine on a training server shows the restart effect best; without one, show it on
  the projector.
- For lesson 13.3, ask learners in advance to create a free GitHub account if they want to open a real pull request;
  everything up to the push works without one.
- Collect a short list of small documentation improvements learners noticed during the course; they make good first
  pull requests.
