# Lesson 5.1: What a site package is

Every Exponential installation starts from a site package: the package the installer installs to shape the new site,
with the packages it requires. This lesson explains what a package is, what makes one a site package, where packages
are kept and where the installer finds them, and the PHP install scripts that make the default site package a
"multi-site installer".

## Learning objectives

After this lesson, learners can:

- define a package, a site package and the three things one can do with a package (install, import, export);
- find the repositories below `var/storage/packages/` and say which one the installer uses;
- name the three sources of site packages (remote index, local repository, upload);
- choose between a full site package and its `_clean` variant;
- explain the install scripts of a site package and when they run.

## Trainer's notes

### How to present it

Sources: [4.3 Site packages: what is installed](../../../../install/04-choosing-an-install-method.md#43-site-packages-what-is-installed)
and [Packages](../../../../guides/packages.md#1-where-packages-live).

1. **Package** (5 minutes). A directory with a `package.xml` and the files it names: content classes, content
   objects, extensions, settings files, images and documents. A package is **installed** (its items are created on
   the site), **imported** (only kept, as a site package is) or **exported** (written as one `.ezpkg` file).
2. **Site package** (4 minutes). A package of type `site` (`<type>site</type>`), plus the packages it requires. The
   default, `sevenx_multisite`, requires `sevenx_classes` (the content classes) and `sevenx_multisite_democontent`
   (the demo content).
3. **Repositories** (4 minutes). Below `var/storage/packages/`: `local` for packages made or imported here, one
   directory per vendor otherwise. The installer's repository is `package.ini [RepositorySettings] Vendor` (`7x`), so
   an imported package lands in `var/storage/packages/7x/<name>/`.
4. **Sources** (4 minutes). The installer reads the remote index of `[RepositorySettings] RemotePackagesIndexURL`
   and offers its site packages next to those already imported; a package listed remotely and not yet imported is
   downloaded and imported with its requirements. A package already in the local repository is used as it is; when
   the index cannot be read, an `index.xml` in the system repository is used (offline install). The setup wizard also
   accepts an uploaded `.ezpkg`.
5. **Full or clean** (3 minutes). A `_clean` package installs the same structure without the demo articles and
   images: choose it for a real site; the full one to evaluate Exponential or to teach.
6. **Install scripts** (5 minutes). A site package can carry PHP install scripts as `<settings-file>` entries; the
   step `CreateSites` calls their functions at fixed points (`eZSitePreInstall()`, `eZSiteINISettings()`,
   `eZSiteRoles()`, `eZSitePostInstall()` and others). `sevenx_multisite` creates a `sevenxMultiSiteInstaller`, a
   subclass of the kernel's `eZSiteInstaller`. This "multi-site installer" is not a fourth install method: it is the
   site package's part of every install.

### Common questions

**Which site packages does this version offer?** The index of 6.0.15 offers eleven: `sevenx_multisite`,
`sevenx_site` and their `_clean` variants, and the older `ezwebin_site`, `ezflow_site`, `ezdemo_site` (each also
`_clean`) and `plain_site`, kept for sites built on them.

**Is a site package installed again later?** No; it is imported by the setup wizard together with the packages it
requires. Its page says there is nothing to install on its own.

**What if a post-install script stops?** `CreateSites` reports error `EZSW-080`, naming the step that stopped.

**Can I make my own site package?** Yes, but it is a developer task; this module shows the packages you can make in
the administration (lesson 5.4).

### Pitfalls

- **Confusing packages and Composer packages.** Exponential packages (`.ezpkg`) carry content and settings; Composer
  packages carry code. A theme can be both; see the theme course.
- **Deleting an installer source.** Removing a package of the `7x` repository changes what new installations are
  built from. Lesson 5.2 shows the warning.
- **Old remote packages.** To force a fresh copy of a package, its imported directory has to be removed first; never
  do that on a shared server during a course.

## Hands-on exercise

Use your training installation. Commands run in its root directory.

1. List the repositories: `ls var/storage/packages/`.
2. List the packages of the installer's repository: `ls var/storage/packages/7x/`.
3. Read the vendor and the index URL in effect:

   ```bash
   php bin/php/console exp:ini get package.ini/RepositorySettings/Vendor
   php bin/php/console exp:ini get package.ini/RepositorySettings/RemotePackagesIndexURL
   ```

4. Open `var/storage/packages/7x/sevenx_multisite/package.xml` (read only) and find `<type>`, the required packages
   and the `<settings-file>` entries.
5. List the packages with the package manager: `php ezpm.php list -r 7x`.
6. Show one package's information: `php ezpm.php info sevenx_multisite -r 7x`.
7. In pairs: a customer wants a real site with the default structure and no demo articles. Which site package?
8. Write down the three sources the installer takes site packages from.

## Expected result

- Step 2 lists `sevenx_classes`, `sevenx_multisite` and `sevenx_multisite_democontent` on an installation made with
  the default package.
- Step 4: `<type>site</type>`, two required packages, and settings files such as `ini-site.php`, `ini-admin.php`,
  `install-scripts.php`, `roles.php` and `preferences.php`.
- Step 7: `sevenx_multisite_clean`.
- Step 8: the remote package index, the local repository, an upload of an `.ezpkg`.
- The trainer checks step 4 on the projector with one learner.

## Quiz

1. What makes a package a site package?
2. Where does a package imported from the vendor `7x` land?
   A. `var/storage/packages/local/` B. `var/storage/packages/7x/<name>/` C. `extension/` D. `var/cache/`
3. What is the difference between `sevenx_multisite` and `sevenx_multisite_clean`?
4. Which step calls the install scripts of a site package?
5. True or false: the multi-site installer is a fourth install method next to the wizard, the kickstarter and
   `exp:install`.

<details>
<summary>Answers</summary>

1. Its type is `site` in `package.xml`.
2. **B.** The vendor names the repository; `package.ini [RepositorySettings] Vendor` is `7x`.
3. The `_clean` package installs the same structure without the demo articles and images.
4. `CreateSites` ([4.3](../../../../install/04-choosing-an-install-method.md#package-install-scripts-the-multi-site-installer)).
5. **False.** It is the site package's part of every install, whichever front end started it.

</details>
