# Bootcamp 4.2: The agency onboarding week

An agency adopting Exponential needs its whole team ready at once. This week mixes shared days, where everyone learns
the same model, with role tracks, and ends with the team delivering one small site together, as on a real project.

## At a glance

| | |
|---|---|
| Course | [Workshops and bootcamps](../README.md) |
| Module | [Module 4: Five-day bootcamps](README.md) |
| Duration | 5 days, 6 hours of sessions each |
| Level | Beginner to intermediate |
| Audience | An agency team: project manager, editors or content staff, an administrator, developers; 6 to 16 people |
| Prerequisites | One installation per developer and administrator; a shared training site for the joint project |

## Learning objectives

At the end of the week, the team can:

- share one vocabulary for the content model, roles and publishing;
- work in their roles: editors publish, the administrator runs and secures, developers build;
- plan and deliver a small site together;
- name their next training steps per role.

## The agenda

| Day | Everyone | Role tracks |
|---|---|---|
| 1 | [Exponential in a day](../module-02-one-day-agendas/exponential-in-a-day.md), morning part; [Teaching the core concepts](../../teaching-the-core-concepts.md) | Afternoon: editors: [Editors 101 Module 3](../../editors-101/module-03-creating-and-editing/README.md); admins: install and roles; developers: Git installation |
| 2 | Morning: the project brief and site plan (project manager leads; [Project managers: start here](../../../leadership/project-managers-start-here.md)) | Afternoon: editors: Online Editor and images; admins: sections, caches, logs; developers: classes |
| 3 | Morning stand-up (15 min) | All day: editors: versions, search, translations; admins: security, 2FA, backups; developers: templates and overrides |
| 4 | Morning stand-up | All day: the joint project: developers build, the administrator sets up roles and the shared site, editors fill content as soon as classes exist |
| 5 | Morning: finish and test the joint project; afternoon: demo to the "client" (the trainer), retrospective, next steps per role | |

Breaks: 15 minutes mid-morning and mid-afternoon, 45 minutes lunch, each day.

## Trainer's notes

- **Two trainers** are easier: one for content tracks, one for technical tracks.
- **Day 4 feels like a real project**: expect friction between roles; it is the point of the exercise.
- **Retrospective** with the three feedback questions
  ([Collecting feedback](../../train-the-trainer/module-06-assessment-and-follow-up/collecting-feedback.md)).

## Hands-on exercise: the joint project

Brief: a microsite for an invented charity run with home, about, route, registration information and news.

1. The project manager writes a one-page plan with roles and tasks.
2. Developers create the classes and views; the administrator creates the roles and the editors' group.
3. Editors create all content, with images and alternative text, in two languages if time allows.
4. On day 5 the team demos the site and the trainer gives client feedback.

## Expected result

- The microsite works on the shared training site, with content by the editors and roles set by the administrator.
- A retrospective with one improvement per role.

## Quiz (end of week)

1. Who should create roles on a project, and who gets them?
2. Why must classes exist before editors start?
3. Name one next course per role.

<details>
<summary>Answers</summary>

1. The administrator creates them; editors (through their group) get them.
2. Content is created from classes; changing classes later affects existing content.
3. Editors: Editors 201; administrators: Site administration; developers: Developers
   ([Course catalogue](../../course-catalogue.md)).

</details>
