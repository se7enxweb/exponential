# From another system

"From another system, the effort is in mapping its content to Exponential's content model and keeping URLs working
with redirects" ([Switching to Exponential](../../businesses/choosing/switching-to-exponential.md#what-drives-the-effort)).

## Contents

2. [Decide first](#decide-first)

## The three steps

| Step | What happens | Page |
|---|---|---|
| Export | Get content, files and users out of the old system in a structured form | [Migrating to and from Exponential](../../../install/migration/README.md) |
| Map | Decide which old item becomes which content type and field | [Content modeling first steps](../planning/content-modeling-first-steps.md) |
| Import | Create the content in Exponential, then check it | [Content migration checklist](content-migration-checklist.md) |

Then keep the old addresses working ([URLs and redirects when migrating](urls-and-redirects-when-migrating.md)).

## Decide first

- What is not migrated: old news, drafts, unused pages. Less content means a faster, cleaner migration.
- Whether user accounts move, and how members set new passwords if password hashes cannot be carried over.
- Whether orders and customer data move, and under which privacy rules ([GDPR basics](../../businesses/security/gdpr-basics.md)).
- Who checks the result: the content lead, item by item for samples.
