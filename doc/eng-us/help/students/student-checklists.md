## Before your first session

- [ ] I chose a learning path ([Choosing a learning path](choosing-a-learning-path.md)).
- [ ] I started a study journal ([Keeping a study journal](keeping-a-study-journal.md)).
- [ ] I have PHP 8.0 or newer and Composer, or I start with the public demo
      ([Your first site: three ways](your-first-site-three-ways.md)).
- [ ] I have a password manager for the passwords the installer prints.

## A study site that is ready

- [ ] `php bin/php/console --version` works and the release is in my journal.
- [ ] The site answers at its address, and I signed in to the administration.
- [ ] I changed the administrator password and deleted `var/log/initial-admin-password`
      ([Installing a study site in one command](installing-a-study-site-in-one-command.md#sign-in-and-change-the-password)).
- [ ] Test accounts use addresses at `example.invalid`.
- [ ] I know how to back it up and rebuild it ([Resetting and rebuilding your study site](resetting-and-rebuilding-your-study-site.md)).
- [ ] It is on my own computer or a training machine, never a live site.

## Every study session

- [ ] One goal, written down before I start.
- [ ] Read a section, do it, compare with "Expected" ([How to study with the help](how-to-study-with-the-help.md#the-read-do-check-loop)).
- [ ] When something differs: log, cache, siteaccess ([Reading logs and errors](reading-logs-and-errors.md#a-routine-for-any-error)).
- [ ] Journal entry written; work committed; nothing secret committed.

## Before you hand in a project

- [ ] Every task done, or the report says why not.
- [ ] Every project check answered with evidence ([Grading your own work](grading-your-own-work.md#project-checks)).
- [ ] No core file edited; overrides, `.ini.append.php` files and extensions only.
- [ ] Every printed value in templates escaped.
- [ ] No passwords, keys, `settings/override/` or `kickstart.ini` in the repository or screenshots.
- [ ] Only invented content; no personal data.
- [ ] The release named; the pages used cited.
- [ ] Self review done a day later ([Grading your own work](grading-your-own-work.md#self-review)).

## Before a pull request

- [ ] The task is small and real ([Your first contribution, step by step](your-first-contribution-step-by-step.md)).
- [ ] I searched the tracker for an existing issue.
- [ ] Work is on a branch; the commit subject starts with `Added:`, `Updated:`, `Fixed:`, `Removed:` or `Renamed:`.
- [ ] For the kernel: `make hooks` installed, `share/filelist.md5` current, CLA signed
      ([The CLA for students](the-cla-for-students.md)).
- [ ] The description says what, why and how I tested it.
- [ ] I am ready for review rounds and will squash and rebase when asked.

## Before a presentation

- [ ] The study site runs; a backup is ready in case it does not.
- [ ] No password or key on screen; the browser shows no saved logins or private tabs.
- [ ] Demo data only.
- [ ] If I show a public demo, I know its content may change or be reset ([Trying the public demo](trying-the-public-demo.md)).
- [ ] I name the release and use the right names: Exponential, 7x, the Exponential Foundation
      ([Names and history for learners](names-and-history-for-learners.md)).

## Before you buy the Student level

- [ ] I read [The Student partner level](the-student-partner-level.md) and the live program pages.
- [ ] I compared it with what is free ([Student level or free community: what to choose](student-level-or-free-community.md)).
- [ ] I asked the partner team what "sandbox access" includes.
- [ ] I understand the order: apply, review, pay, then sign ([How to apply](../partners/how-to-apply.md)).
- [ ] I know it is not a certification, and that official certifications are planned but not available yet ([Certifications and certificates](certifications-and-certificates.md)).
