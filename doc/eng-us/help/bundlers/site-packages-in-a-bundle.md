# Site packages in a bundle

This page is for bundlers whose bundle installs a site, which is almost every bundle. The site an installer creates is
built from a **site package**. The full reference is the [Site packages](../site-packages/README.md) section; this
page is the bundler's view of it.

## What a site package brings

"A **package** is a folder with a `package.xml` and the files it names, shipped as one gzip compressed tar file ending
in `.ezpkg`. A **site package** is a package of type `site`; it requires other packages (content classes, content) and
can carry install scripts that set up siteaccesses, extensions, roles and preferences"
([Site packages: start here](../site-packages/README.md#the-short-version)).

The install scripts run inside `CreateSites`, whichever installer started the run; the "multi-site installer" of
`sevenx_multisite` "is therefore not a fourth install method: it is the site package's part of every install"
([4.3](../../install/04-choosing-an-install-method.md#package-install-scripts-the-multi-site-installer)).

## Choosing a package

The 6.0.15 package index offers twelve site packages
([4.3](../../install/04-choosing-an-install-method.md#43-site-packages-what-is-installed)):

| Site package | For a bundle that ... |
|---|---|
| `sevenx_multisite` | shows Exponential with demo content: evaluations, demos, classrooms. It is the default of `exp:install --package` |
| `sevenx_multisite_clean` | delivers the same site empty, for a real site the recipient fills |
| `cjw_multisite` | wants the CJW starter site with an English and a German site |
| `sevenx_site`, `sevenx_site_clean` | wants a simpler site |
| `ezwebin_site`, `ezflow_site`, `ezdemo_site`, `plain_site` (and `_clean`) | must match older sites built on them |
| your own | carries your design and content model ([Your own site package](#your-own-site-package)) |

"A `_clean` package installs the same structure without the demo articles and images: choose it for a real site you
will fill yourself, and the full one to evaluate Exponential."

## Naming the package to the installer

| Installer | How |
|---|---|
| `exp:install` | `--package=<name>` |
| Kickstarter | `kickstart.ini`, `[site_types] Site_package=<name>` |
| Setup wizard | the **Site package** page; it can be preselected by `kickstart.ini` |

Source: [Pointing a site at your package server](../site-packages/your-own/pointing-a-site-at-your-package-server.md#name-your-site-package).

## Ship the files you tested

By default the installers download the site package and its requirements from the package server named in
`settings/package.ini [RepositorySettings] RemotePackagesIndexURL`. For a bundle that is a moving part:

- "Packages in a release folder are fixed in place on the public server: the file name stays, the content changes"
  ([Offline installs and mirrors](../site-packages/package-server/offline-installs-and-mirrors.md#keeping-a-mirror-current)).
  A bundle that downloads at install time can therefore install a newer package than the one you tested.
- "When a package exists in the installation, the site type step uses it instead of downloading it"
  ([Kickstarter](../../features/6.0/kickstarter-cli.md#things-to-know)).

So a bundle that must install the same site every time ships the `.ezpkg` files it tested and imports them before the
install ([Offline bundles](offline-bundles.md)), or points at a mirror it controls
([Your own package server](your-own-package-server.md)). Record the checksum of every `.ezpkg` you ship.

## Your own site package

The steps are in [Making your own site package](../site-packages/your-own/README.md): fork a package, change classes,
content and the installer script, rebuild the `.ezpkg`, version it, test it in a sandbox. Before you ship it, meet the
[documentation requirements](../site-packages/requirements/README.md): required `package.xml` fields, license,
changelog, versions, thumbnails, dependencies, validation.

7x and the Exponential Foundation "strongly encourage you to submit it by pull request to the repository behind the
package server, so every installation can offer it" ([Contribute your site package](../site-packages/contribute-your-site-package.md)).

## Checklist

- [ ] The site package and every package it requires are chosen and their versions recorded.
- [ ] The `.ezpkg` files the bundle installs are the ones you tested (shipped, mirrored, or checked by checksum).
- [ ] Demo content is only in bundles meant for demonstration.
- [ ] The package's license and the licenses of its images are known ([Third-party components](third-party-components-and-their-licenses.md)).
- [ ] The package carries no user accounts with known passwords ([Default credentials](default-credentials-and-first-sign-in.md)).
- [ ] `exp:install --package=<name> --dry-run` passes in the build.
