# Für Barrierefreiheit eintreten

Diese Seite ist für Fürsprecher, denen wichtig ist, dass alle Exponential und die damit gebauten Websites nutzen können.
Das Projekt testet seine Administration bereits auf Barrierefreiheit ([Gesprächspunkte: Barrierefreiheit](gespraechspunkte-barrierefreiheit.md));
Fürsprecher können helfen, dass es so bleibt, es auf öffentliche Websites ausweiten und die Community selbst barrierefrei
machen.

## Wo Sie etwas bewirken können

| Bereich | Was es gibt | Was Sie tun können |
|---|---|---|
| Die Administration | admin4 testet Kontrast und Zielgröße, Landmarks, Tastatur | Mit Ihrer assistiven Technologie testen; Probleme melden |
| Beiträge | Gestaltungsregeln und ein Test, der sie durchsetzt | Pull Requests mit diesen Regeln im Kopf prüfen |
| Öffentliche Websites | Das eigene Design jeder Website | Theme-Ersteller und Redakteure schulen |
| Inhalte | Alternativtext kann pro Klasse verlangt werden | Redakteure ermutigen, ihn zu schreiben |
| Community-Material | Ihre Beiträge, Folien, Videos | Sie barrierefrei machen |

## Die Administration testen

1. Nutzen Sie, was Sie jeden Tag nutzen: einen Screenreader, nur die Tastatur, Vergrößerung, hohen Kontrast, Sprachsteuerung.
2. Gehen Sie die Hauptaufgaben durch: anmelden, bearbeiten, veröffentlichen, hochladen, den Layouts-Editor nutzen, die
   Hilfe durchsuchen.
3. Schreiben Sie auf, wo Sie hängen bleiben: was Sie getan haben, was Ihr Werkzeug angesagt oder getan hat, was Sie
   erwartet haben.
4. Melden Sie es als Fehler und nennen Sie Ihre assistive Technologie und Ihren Browser ([Fehler gut melden](fehler-gut-melden.md)).

Was das Design bieten soll, ist in [Das Design admin4](../../../en/us/features/6.0/admin4-design.md#landmarks-and-names) und
[Tastatur](../../../en/us/features/6.0/admin4-design.md#keyboard) dokumentiert: Nutzen Sie es als erwartetes Ergebnis.

## Beiträge an den Regeln messen

CONTRIBUTING.md verlangt, dass jedes Template der Administration [Die Administration gestalten](../../../en/us/bc/6.0/admin4-styling.md)
folgt: keine Inline-Styles, gemeinsame Komponenten, Tokens mit Werten für den Dunkelmodus; ein Test prüft das
([CONTRIBUTING.md](https://github.com/se7enxweb/exponential/blob/main/CONTRIBUTING.md)). Wenn Sie einen Pull Request
prüfen, achten Sie auf:

- jedes Formularfeld hat einen Namen;
- Tastaturzugang zu neuen Bedienelementen;
- sichtbarer Fokus;
- Kontrast im hellen und dunklen Modus;
- keine Information allein über Farbe.

## Website-Erstellern helfen

- Verweisen Sie Theme-Ersteller auf die eigene Praxis der Administration als Beispiel und auf die WCAG.
- Ermutigen Sie dazu, verpflichtenden Alternativtext für Bildklassen einzuschalten
  ([Checklisten zur Barrierefreiheit](../../../en/us/help/leadership/accessibility-security-and-compliance-checklists.md#accessibility)).
- Zeigen Sie Redakteuren den Bericht „Fehlender Alternativtext“ von Exponential Intelligence, wo er eingerichtet ist
  ([expai, Für Redakteure](../../../en/us/features/6.0/extensions/expai.md#for-editors)).
- Schreiben Sie ein Tutorial über barrierefreie Inhalte: Überschriften, Linktext, Alternativtext, Tabellen
  ([Ein Tutorial schreiben, das funktioniert](ein-tutorial-schreiben.md)).

## Die Community barrierefrei machen

- Barrierefreie Folien, Untertitel und Transkripte ([Barrierefreie Folien und Grafiken](barrierefreie-folien-und-grafiken.md)).
- Treffen an stufenlos erreichbaren Orten, mit Pausen; Online-Treffen mit Untertiteln ([Checklisten für Veranstaltungen](checklisten-fuer-veranstaltungen.md)).
- Einfache Sprache in Antworten; Geduld mit Menschen, die langsam tippen oder diktieren.
