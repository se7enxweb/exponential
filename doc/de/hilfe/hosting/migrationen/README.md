# Kunden migrieren: Überblick

Dieser Bereich ist für Hosting-Anbieter, die Kunden-Websites auf ihre Plattform umziehen. Er beantwortet: wie Sie eine
laufende Exponential-Website zu sich holen, was sich ändert, wenn die Website auf einer älteren Version oder einer anderen
Plattform läuft, und wie Sie unterwegs die Datenbank-Engine wechseln.

Die tiefe technische Arbeit ist im Installationsbuch, Kapitel 14 bis 17, beschrieben. Diese Seiten ordnen sie für einen
Hoster: die Bewertung, der Plan, der Umzug, die Prüfungen und die Zuständigkeiten zwischen Ihnen und dem Kunden.

| Seite | Was sie Ihnen gibt |
|---|---|
| [Kunden zu Ihrem Hosting migrieren](kunden-zu-ihrem-hosting-migrieren.md) | den ganzen Ablauf für einen Hoster: Bewertung, Angebot, Staging, Umschaltung, Nachbetreuung |
| [Von älteren Exponential-Versionen](kunden-von-aelteren-versionen-migrieren.md) | Websites aus der Zeit von 3.x, 4.x und 5.x und ältere Releases 6.0.x |
| [Von eZ Platform und Ibexa](kunden-von-ez-platform-und-ibexa-migrieren.md) | Symfony-basierte Websites und ihre zwei Ziele |

| [Die Datenbank-Engine wechseln](die-datenbank-engine-einer-kunden-website-wechseln.md) | eine Website auf eine andere der sechs Datenbanken umziehen |

## Welche Seite brauche ich?

| Die Website des Kunden läuft auf ... | Lesen Sie |
|---|---|
| Exponential 6.0.x, bei einem anderen Hoster | [Eine Website zwischen Hostern umziehen](eine-website-zwischen-hostern-umziehen.md) |
| eZ Publish 3.x, 4.x oder 5.x Legacy (der alte Name des Produkts, das sein Hersteller nach fast 18 Jahren eingestellt hat) | [Von älteren Exponential-Versionen](kunden-von-aelteren-versionen-migrieren.md) |
| eZ Platform 1.x bis 3.x, Ibexa DXP oder OSS 3.3 bis 5.0 | [Von eZ Platform und Ibexa](kunden-von-ez-platform-und-ibexa-migrieren.md) |
| einer dieser Versionen, und die Datenbank soll sich ändern | zusätzlich [Die Datenbank-Engine wechseln](die-datenbank-engine-einer-kunden-website-wechseln.md) |

> **Hinweis**
> Nur die Linie 6.0 wird gepflegt; 5.x, 4.x, 3.x und älter erhalten keine Sicherheitskorrekturen (`SECURITY.md`). Ein
> Kunde auf einer alten Version ist ein Migrationsprojekt, kein Umzug des Hostings. Bepreisen und planen Sie es als solches.
