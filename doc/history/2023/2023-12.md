# December 2023

On 11 December 2023 the first outside change was merged into the new repository: upstream pull request #40 (`2ddbc4c624`) stopped the object relation class attribute from failing when no default selection node had been chosen. Two days later pull request #41 (`8df0f2cd19`, the fix itself `b2af30cd2c`) corrected the HTTP date strings that were also written into package exports, so a content package exported with the package tool no longer carried wrong date and time attributes in `contentobject.xml`. From there the month is the story of a code base changing hands: the maintainers turn a dormant upstream project into a product that installs and runs on current PHP.

## What changed for a user

**A project that explains itself.** The README was rewritten several times to say what the software is now, which PHP versions it supports, where to ask for help and how to install it (`9abb8c6850`, `f9c9d6547a`, `21c521abc3`, `20fafbd863`, `035eac80f9`). Funding metadata, a `SECURITY.md` and a `CONTRIBUTING.md` (`ad4a5e6c`... listed below) were added so reporters and contributors know where to go.

**Installable with Composer under a new name.** `composer.json` was branded as a 7x product and its requirements pointed to `se7enxweb` packages (`bb9601a94d`, `f2e0cc863a`, `91c7d6d92c`, `330b0ef3`...); several extension versions were set so that they install cleanly (`c39efa3c63`, `45e5c69d15`, `fb9f17ba4c`). See [the default extension distribution](../../features/6.0/default-extension-distribution.md).

**Planned versions, not "development".** `lib/version.php` switched from a version-less development state to planned versions (`db7dca6e57`); `6.0.0beta1` was set on 25 December (`7e453d53db`), `beta2` on 31 December (`f6bf82ab43`) and the edition text and alias for the release (`ab10c96a7e`).

**The setup wizard works on PHP 8 and talks to the right servers.** The wizard printed PHP 8 warnings and sent users to servers of the former vendor. Fixed in this month: a PHP 8 error in the wizard (`06eca74187`), the `{for}` template function on PHP 8 (`d6d7837233`, `3d9406a688`) and PHP 8.3 (`bd03edbbe3`), the installer autoload code that printed error text during installation (`634f00704a`, `1558406cbc`), package service URLs and vendor in `package.ini` (`12ce4a8168`), links in the community registration template (`c25d9a4386`, `9a8c9c4006`, `3378ca6176`) and in the wizard's documentation links (`7286590cea`). A fault that stopped the default package installation from advancing past one wizard step was fixed twice (`4233c84a04`, `a756066edf`). See [PHP 8 support](../../bc/6.0/php8.md), whose outline was created now (`fde5a6900e`, `99ca162e89`).

**An upgrade path from 5.4.** The database update scripts from 5.4 to 6.0 were published, one for MySQL (`update/database/mysql/6.0/dbupdate-5.4.0-6.0.0.sql`, `e7d696b368`) and one for PostgreSQL (`update/database/postgresql/6.0/dbupdate-5.4-to-6.0.sql`, `bd547fd2c1`); they record the new version in `ezsite_data` and need no schema change, and the version note was moved into the bc folder (`a15cb1dd27`). See [Changelog 6.0.0](../../changelogs/6.0/6.0.0.md).

**Honest dashboards and footers.** The community activity dashboard block, which no longer worked, was commented out (`0c9d42ba5e`) and the maintenance dashboard names 7x as maintainer (`fcf96edc79`); admin and standard design footers carry 7x links and copyright (`2a37bcbe2a`). See [the rebranding page](../../features/6.0/rebranding-to-exponential.md) for the larger rename that followed in 2025.
