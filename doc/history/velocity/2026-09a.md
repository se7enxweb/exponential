# Velocity chronicle: September 2026, 7 to 21 September

*Part of the [Exponential Velocity history](README.md). Previous: [August 2026](2026-08.md). Next: [22 September](2026-09b.md).*

## In short

The first three weeks of September carry the engine from "a fast server for new PHP applications" to "a server that runs existing PHP applications unchanged". A compatibility layer (`243d1ba`) lets Laravel, Symfony, WordPress, Drupal, Joomla and similar code run on persistent workers; a measured speed-up of existing code of about twelve times against other application servers is reported on the 17th (`8e69b26`); standalone binaries for Linux and macOS are finalised; and on the 21st a contributor's fixes begin to land and the repository gets its first tag, `v0.0.1`.

## How the period went

**7 September.** `243d1ba` adds the compatibility layer: 1,666 lines in `Compat.php` plus a `COMPATIBILITY.md`. It does three jobs: it rewrites the few PHP functions that behave differently under a long-lived CLI process (`header()`, `setcookie()`, `exit`, `die`), it wraps the file layer so includes and stat calls are cheap, and it resets the state a request leaves behind. The same day, `c57a8e0` forks extra workers to send large files, and `6b43dd1` finalises standalone binaries for Linux and macOS.

**17 September: the benchmark.** `8e69b26` changes the pool, the compat layer and the state snapshot, and rewrites the benchmark documents under the title "existing PHP codebases run 12x faster than with Swoole and FrankenPHP". The figure is the commit's own; the measurement method is in the engine's benchmark document.

**19 September.** `f8d92cf` (32 files, about 10,000 lines added) improves the documentation, dashboard and control panel and adds Windows support.

**21 September: the contributor wave.** A series of small, well-explained fixes arrives, each in its own branch and each with a test:

- the Linux release binaries were corrupt because they were compressed with UPX; compression was removed (`6f73688`);
- `phpinfo()` was shown as collapsed plain text; it is now rebuilt as HTML in three steps (`da1a605`, `74bde3f`, `722cc2d`);
- the document root could not be listed (`d36ef6d`);
- scripts run from their own directory (`1c5c155`), report their own path in `SCRIPT_NAME` (`8457079`), keep their autoloaders (`ea59aba`), and carry cookies and binary bodies from the worker to the response (`685d86c`, `32d5b07`);
- idle octane workers no longer die after `default_socket_timeout` (`9fc5c27`);
- `session_id()` is shimmed (`e8cd8d2`);
- the micro SAPI is built before the sources are copied, and the Docker build can pick the PHP version (`a543313`, `449c030`).

`822c531` fixes the Composer package name and the repository is tagged `v0.0.1`.

`509d94b` (the same day) is the first "easy to migrate" commit: migration pages for Apache, Nginx and Caddy, an `Autohost` class (virtual hosts that appear without configuration), a `Watchdog` that supervises the server process, and a larger control panel.

## Smaller points

- The tag `v0.0.2` (21 September) points at the same commit as `v0.0.1` (`822c531`); the next new tag, `v0.0.2.1`, is on 22 September.
- Some fixes appear twice in the ledger under different hashes (`822c531` and `8fe2984` carry the same subject): read them as one change.
- The ledger shows no Exponential-specific code yet; the `exponential` preset arrives on [23 September](2026-09c.md).
