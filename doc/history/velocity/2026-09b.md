# Velocity chronicle: September 2026, 22 September

*Part of the [Exponential Velocity history](README.md). Previous: [7 to 21 September](2026-09a.md). Next: [23 September](2026-09c.md).*

## In one paragraph

22 September is the busiest day of the engine's history so far: 144 ledger rows (66 of them merges), tags `v0.0.2.1` to `v0.0.4.14`. Three things happen at once. The contributor fixes of the 21st are merged (workers, uploads, cookies, redirects). The server learns **HTTP/2** in five waves, with a hand-written HPACK decoder checked against the specification's own test vectors. And the **response cache** is switched on, made fast, and given the behaviour of a real reverse proxy: conditional requests, stale-while-revalidate, negative caching, pre-compressed storage. Every tag of the day is the same loop: change, test, rebuild the committed `bin/qbixserver.phar`, tag.

## The day in order

**Merging the contributor wave.** The `Merge` rows of the day (66 of 144) are the merge of the contributor fixes into the `maintain` branch (see the table below, class "no-user-benefit": the merged commits are classified at their own rows). One extra fix of the day: a raw `Set-Cookie` header was dropped whenever a script also called `setcookie()` (`8dbe533`, then `7655911`); another made TLS requests visible as HTTPS so redirects stop pointing at `http` (`dc3dc45`, tag `v0.0.2.2`).

**Uploads and bodies.** Two linked fixes: `53d6a94` carries a request body that is not valid UTF-8 to the worker (before it, every file upload failed before the application saw it), and `7779b2f` makes `is_uploaded_file()` accept an upload the pool already parsed (tag `v0.0.2.5`).

**Cache and archive.** `e7cd4ee` finally switches on the reverse proxy cache (it had never been enabled); `74e0878` sweeps expired entries; `b5c6f3e` rebuilds `bin/qbixserver.phar` when its sources change; `64bcd25` remembers that a file needs no transform so it is not tokenised on every request. Tags `v0.0.2.6` to `v0.0.3.1` follow in quick succession, each rebuilding the archive. In `v0.0.3.0` a static file can say how long it may be kept (`547b01d`), and in `v0.0.3.1` the access line is configurable and pooled responses are logged when they go out rather than when dispatched (`6385e78`, `b2fbe0d`).

**HTTP/2 in five waves.**

1. `d7ff28e`: HPACK header compression, verified against the vectors in the specification.
2. `2f3d25c`: frames and the connection state machine, answering a real client.
3. `a378de7`: negotiate it on the real TLS listener and answer from the worker pool.
4. `515cf79` / `aadc2de` (same change twice in the ledger): a page instead of a blank window when the browser opens an HTTP/2 URL the server does not serve, and a setting for it (tag `v0.0.4.0`).
5. `00b1578`: compress the body and stop overrunning the flow-control windows (tag `v0.0.4.1`).

The first days of any new protocol need repairs; each of the following has its own row. HTTP/2 responses were never compressed because the test could not load (`53893c2`, `v0.0.4.2`); HTTP/2 cost 800 ms a request because the TLS buffer was read once, not drained (`eac4791`, `v0.0.4.3`); HTTP/2 rendered every page from scratch because it never consulted the response cache (`1b26a58`, `v0.0.4.4`); the TLS handshake waited on a timer (`05d76c9`), TLS sessions could not be resumed (`b0be81f`), the handshake retry used a test that was always false (`73ec5a5`) (all in `v0.0.4.5`); responses were truncated under small flow-control windows (`8b591ed`, `v0.0.4.6`); cookies set by a script were lost over HTTP/2 and the port leaked into `SERVER_NAME` (`a7123dc`, `f815713`, `v0.0.4.7`).

**Safety limits (`v0.0.4.9`).** `85fa820` bounds every resource an HTTP/2 peer can make the server hold; `39be3c1` refuses a header block that lies about its own lengths; `7a7d2a5` adds a unit suite that needs no server and runs it first. The later security days build on this; see [HTTP/2 and security](../../specifications/6.0/velocity-http2-and-security.md).

**Cache behaves like a proxy (`v0.0.4.10` to `v0.0.4.14`).**

- `b553035` stores a cached body outside the JSON that describes it; `4174b60` stores the compressed body so a hit does not compress again (tags `v0.0.4.12`, `v0.0.4.13`).
- `54161e3`: conditional requests. A browser that already holds the page receives headers and `304`.
- `0deca9a`: **stale-while-revalidate** and **negative caching**. When an entry expires, one request renders the new copy while the others are served the old; a `404` or `410` is remembered so it is not rendered again for every caller.
- `d5d3835`: a cached response is recognised before routing runs, the listen backlog is a queue, and every response carries a `Date`.
- `9a32ab6`: optional whitespace collapsing of cached HTML. `0ac79dd`: shared-dictionary compression of stored entries, off by default, with the measurements that say when to switch it on.
- `fdeeca1` (`v0.0.4.14`): the README gains a configuration reference, worked measurement examples, the security posture and how to contribute.

The cache settings and their defaults are in [Response cache](../../features/6.0/velocity-response-cache.md).
