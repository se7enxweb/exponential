# October 2026 (1 and 2 October)

What changed in Exponential on 1 and 2 October 2026, why it matters, and where to read more. Read it if you run the 6.0.15 line: the administration interface moved to jQuery 4, and new tools for operators arrived. The [history guide](../README.md) explains how the month pages, the ledger and the coverage page fit together.

## In short

- 354 changes in two days (1 and 2 October), no release tag; they belong to the 6.0.15 line.
- The administration interface moved to jQuery 4 and Exponential UI, YUI is gone, and a fourth design, admin4, exists.
- New operator tools: an audit trail, the `exp:ini` settings editor, a debug bar, content jobs, repair from the browser.
- TinyMCE 8 is available as a second online editor engine; commands, cronjob parts and views became classes.

The two days brought 354 changes to the root repository, the busiest stretch of the 6.0.15 line. They have four threads:

1. The administration interface was rebuilt on jQuery 4 and Exponential UI, and YUI was removed.
2. Exponential gained the tools of an operator who has to answer questions: an audit trail, a settings editor, a debug bar, background jobs for large operations.
3. A second rich text editor engine, TinyMCE 8, arrived next to the old one.
4. The code of every command, cronjob part and module view moved into classes with the same entry points, which opened a re-implementation point for each.

Every change is in the [ledger of exponential-root](../ledger/exponential-root.md) under "2026-10"; the changes without a story of their own are in [the appendix](#appendix-every-change-of-the-month-by-page).

No release tag falls in this period. Before you update, read the upgrade checklist for these two days, [Behaviour changes of 1 and 2 October 2026](../../bc/6.0/behaviour-changes-2026-10.md), and the [6.0.15 changelog](../../changelogs/6.0/6.0.15.md).

## 1 October: PHP 8.5 on Oracle, a sortable order list, the editor siteaccess, jQuery 4

**Oracle and PHP 8.5.** The day began with a sweep of the debug report of every admin page, the public front
pages and the edit form of one object of each class, on Apache and on Exponential Velocity, on an Oracle database.
Preferences without a name, class attribute categories (Oracle returns an empty string as NULL, and NULL is a
deprecated array key), extension metadata, the template compiler, `eZHTTPTool::redirect()`, the INI setting
datatype, the `ristring` operator and `{if}` without a placement all stopped raising notices. The SQL query cache
learned Oracle's statements (sequences, `SYSDATE`, anonymous PL/SQL blocks, the catalogue), so ezoracle 2.3.2 can
use it. See [database drivers](../../specifications/6.0/database-drivers-sqlite-oracle.md).

**The order list sorts by every column.** The headings of Store > Orders are links; column and direction live in
the address. [Feature page](../../features/6.0/order-list-sorting.md).

**Hidden tabs and the editor.** `HiddenTabs[]` lets a siteaccess take an extension's tab out of the top menu and
node view, which made an editor-only administration possible: `design/editor` and, installed by the setup wizard,
an `editor` siteaccess next to the admin one. The wizard itself got a new look (a white card on a dark page), the
Database field offers only real SQLite files, and Velocity's warm-up no longer takes the wizard's lease (it had
locked everyone out with "The site is being set up" for half an hour after a restart). See
[hidden admin tabs](../../features/6.0/hidden-admin-tabs.md) and
[the wizard and the editor siteaccess](../../features/6.0/setup-wizard-and-editor-siteaccess.md).

**Static cache.** A no-change publish spent 4975 ms of a 6 s request refreshing 24 pages, each fetched twice and
ten of them 404. They are now fetched once, eight at a time, only where they exist: about 0.5 s.
[Section](../../features/6.0/static-cache-generator.md).

**jQuery 4.** ezjscore 1.4.0 ships jQuery 4.0.0 with Migrate 4.0.2 and jQuery UI 1.14.2. The admin's own code lost
the removed shorthands; the collapsing menus, the edit toolbar, the sub-items table, the upload dialogs, the date
fields and the asynchronous publishing status page moved from YUI to Exponential UI, each with the old version as a
fallback for the day. Two real bugs came out of testing by use: the rich text editor's dialogs called `.size()`
and the asynchronous publishing daemon stopped with a type error on PHP 8.
[jQuery 4 and the YUI removal](../../features/6.0/jquery4-and-yui-removal.md).

**SQLite under load.** Transactions started with a deferred `BEGIN`, which SQLite refuses at the first write once
another connection has committed since the read: "database is locked" while publishing next to other writers. They
start with `BEGIN IMMEDIATE` now. The asynchronous publisher also closes its connection before the fork instead of
after it.

**A release round.** A round of commits repinned the extension releases that carry the same ideas (Exponential UI
1.0.0.1, explayouts 1.4.10 with its `exp_component_<type>` blocks, the media theme, ezwebin, ezwt, ezautosave,
eztags, ezmultiupload, ezupdate with an Installed packages view). They are in the
[6.0.15 changelog](../../changelogs/6.0/6.0.15.md).

## 2 October: the day of admin4, the audit and TinyMCE 8

**SQLite transactions queue.** A transaction that did not get SQLite's write lock within the 5 s busy timeout was
still counted as one, so everything after it ran as single statements and the automatic rollback reported "cannot
rollback - no transaction is active" instead of the cause; with 64 processes publishing at once, 6 of 192 failed.
The start now waits `SQLiteTransactionWait` seconds (default 60) in a queue and either commits whole or fails at
its start: 192 of 192 complete. [bc note](../../bc/6.0/sqlite-transactions.md).

**admin4.** A complete admin design in the look of the wizard, light and dark, with 463 files so it needs no other
admin design. Over the day: a dashboard that teaches the two updates that keep an installation secure, a top menu
that wraps instead of hiding items, a calm sign-in page built for phones, a compact node view, sticky edit
buttons, narrower frame edges. The CSS packer had been removing the space before a colon in selectors (`a :hover`
became `a:hover`); that was fixed on the way. [Feature page](../../features/6.0/admin4-design.md).

**TinyMCE 8.** A prototype engine next to TinyMCE 3.5, then, in one day of small commits, parity with the old
one: custom tags, literal tags, links, embed with upload and class filter, tables, the general tag dialog, the
ezxml tag path in the status bar, the o2k7 skin, an engine switch, a page to choose the engine, an engine registry
and a server-side upload type check, 267 PHPUnit tests and browser tests. [Feature page](../../features/6.0/online-editor-tinymce8.md).

**YUI removed.** Admin, admin3, admin4 and standard designs, then the bundled ezjscore (1.5.0). A round of extension
releases was repinned to versions without YUI. [Upgrade guide](../../bc/6.0/yui-removal.md).

**Request rules.** Neither role policies nor `[SiteAccessRules]` could tell `/content/view/full/123` from the same
page at its alias. Rules in `requestrules.ini` decide before the view runs: 25 conditions, 8 actions, three shipped
rules, a command that explains the decision. [Feature page](../../features/6.0/request-rules.md).

**A broken installation can repair itself.** When `vendor/` is missing, a page of its own explains it and, with a
one-time key, installs the libraries from the browser through a queue run as the web server user. Several
follow-up commits made the page answer at once and keep showing its log. [Feature page](../../features/6.0/repair-from-the-browser.md).

**Code moves into classes.** All 198 kernel views, the kernel's commands and its cronjob parts became classes of
`Exponential\Runnable`; copyright notices now name 7x and the Exponential Foundation first; events surround every
run; the extension point survey counts 469 re-implementation points.
[Specification](../../specifications/6.0/runnable-commands-cronjobs-views.md).

**Operator tools.** The sub-items list got 129 columns, presets and CSV export
([feature](../../features/6.0/subitems-table-options.md)); `exp:ini` changes settings line by line in every scope
([feature](../../features/6.0/exp-ini-command.md)); large subtree operations became resumable
[content jobs](../../features/6.0/content-jobs.md); the debug report became the [Exp Debug bar](../../features/6.0/exp-debug-bar.md);
the trash shows [who trashed an item](../../features/6.0/trash-who-and-where.md).

**The audit.** From a design document to an installed, indexed, alerting system in one day: the event
core with hash chains, the console and dashboard, archives in five formats, sinks and alert rules, hooks in the
kernel for content, access, settings, commerce and deploys, tests against the live database. It is on by default.
[Feature page](../../features/6.0/audit-trail.md), [specification](../../specifications/6.0/audit-event-model.md).

**Access tightened.** The dashboard, menus and tabs show a link only to a user who can open it; the debug bar's
controls need `setup/setup` or `setup/managecache`; poll votes, form submissions and the VAT country choice need
`content/read`; the editor's upload checks the file type on the server.
Details: [admin links follow permissions](../../features/6.0/admin-links-follow-permissions.md) and the table "Access
and security" in [behaviour-changes-2026-10.md](../../bc/6.0/behaviour-changes-2026-10.md#access-and-security).

**Remote services.** `extension/expservices`: 1,122 services in dozens of domains, personal API tokens, two
portals, and the same data the admin shows, available to any client.
[Feature page](../../features/6.0/remote-services-expservices.md), [specification](../../specifications/6.0/expservices.md).

## Fixes worth knowing

Removing a draft now removes every one of its image files; a copied object owns its image files; a removed media
attribute keeps a file another row names; removing a subtree that holds every location of an object removes the
object; "Remove timed out sessions" removes the baskets; `clusterpurge` waits 30 days, not 30 seconds; a VAT rule
can be removed again; the PDF export no longer answers 500; Velocity keeps the regenerated cache files in the opcode
cache (the cache served 2.7% of includes against PHP-FPM's 97%, a page cost 644 ms instead of 166 ms of CPU); an
opcode cache profile, off unless `var/tmp/opcache_profile.on` exists, measures it. Both:
[Velocity and the opcode cache](../../features/6.0/velocity-opcode-cache-and-profile.md).
