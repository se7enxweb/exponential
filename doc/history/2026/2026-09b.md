# September 2026, second half (16 to 30 September)

What changed in Exponential from 16 to 30 September 2026, why it matters, and where to read more. Read it before you take these changes into a site: they bring the Velocity web server, the one-command install, a hardening sweep and open package tools. The [history guide](../README.md) explains how the month pages, the ledger and the coverage page fit together.

## In short

- Velocity, a persistent-worker web server for Exponential, arrived on 22 September and became the recommended way to be fast within two days.
- A site can be installed with one command, with logs and seed data you can inspect.
- On 27 September datatypes, login and web server rules were hardened so a default installation is safe.
- On 29 and 30 September the package tools opened up: browse, compare and import single items.

The fortnight brought 666 changes to the root repository, more than any fortnight before it, and no release tag. It has four stories:

1. A new way to run Exponential arrived: Velocity, on 22 September.
2. An installation became something you can do in one command and watch (27 to 28 September).
3. The datatypes, the login and the web server rules were hardened in one long sweep (27 September, 205 changes in a day).
4. The package tools stopped being a sealed box (29 and 30 September).

Every change is in the [ledger of exponential-root](../ledger/exponential-root.md) under "2026-09"; changes without a story of their own are under [Smaller changes](#smaller-changes). The first half of the month is in [September, first half](2026-09a.md). The facts about each feature are on the pages linked below. What to do when you take the changes in is in [Behaviour changes of 16 to 30 September 2026](../../bc/6.0/behaviour-changes-2026-09b.md).

## 16 to 21 September: MongoDB and SQLite install end to end, search indexing

- **MongoDB installs reach the same pages as the reference.** The driver silently
  dropped or mistranslated SQL the kernel issues all the time, so `COUNT(*)` read
  zero (the installer then created 533 duplicate nodes), layout collections held
  truncated queries and date-ordered lists came back oldest first. Fixed on 18
  September, followed on 19 and 20 September by `CREATE TABLE` support, typed
  values (a quoted number is stored as a number when the schema says so), constant
  time id allocation and `find()` instead of aggregation for plain queries. A
  search reindex of the reference content now takes about 21 seconds and indexes
  237 of 284 objects, where before it indexed 14 and reported success. Every link
  rendering as `content/view/full/<id>` and 59 image files going missing on
  install were two further MongoDB-only faults (the URL alias path builder and a
  join-based reference check). See the addendum in
  [MongoDB kernel support](../../bc/6.0/MONGODB_KERNEL_SUPPORT_EXPANSION.md).
- **A SQLite install finishes.** `removeDatabase()` did nothing, so a rerun left
  the previous install in place and every `CREATE TABLE` failed with "table
  already exists"; two MySQL-only statements aborted the surrounding transaction.
  SQLite now drops its objects properly, ignores session `SET`s and understands
  the language-mask update. See [database drivers and installers, September 2026](../../specifications/6.0/database-drivers-2026-09.md)
  (SQLite index names and composite keys, PostgreSQL `pgcrypto`, the setup
  wizard, SQL dump escaping).
- **Search indexing takes the batched path on SQLite and PostgreSQL** (about twice
  as fast on SQLite, identical index).
- The layouts documentation was rewritten as a guide that teaches the editor to an
  editor new to the software, and extension pins were raised for the shared layout
  flag, the title and button link field, tag pages on MongoDB, the layout list
  header on a phone and menu labels (CIE, Tags).
- The web server package was renamed twice in four days (a typo in its own name,
  then the project's own rename) before settling on its final name.

## 22 September: Velocity arrives

One commit added a service layer and a console command, `exp:velocity`, for
running Exponential under a persistent-worker web server, together with the kernel
and library fixes that make the application survive one: guards around functions
and classes that module views declare (ten extensions were repinned to releases
with the same guards), the phar stream wrapper closed for public requests, URLs
that carried the siteaccess name when the site is served on a non-default port,
and system information that works when PHP is not an Apache module. The rest of
the day built the server around it: an engine archive (`exp:phar`, measured to
make no difference to speed and recorded as such), interpreter settings (an opcode
cache is the one change that pays, 18 to 26 percent), HTTP caching for anonymous
visitors (a returning visitor fetches none of a page's 41 assets again), a cache
warmer (`exp:warm`), HTTP/2 and static file lifetime settings, a navigation cache
and the documentation to reproduce the installation. Read
[Velocity: running Exponential in a persistent-worker web server](../../features/6.0/velocity-persistent-worker-server.md).

## 23 to 24 September: Velocity becomes the default way to be fast

- A section in the README explains how Exponential is served and introduces
  Velocity beside Apache, Nginx, LiteSpeed, Caddy, IIS, lighttpd, H2O and Traefik.
- `exp:velocity config list|get|set|unset|paths` writes to the file the server
  really reads, because three look-alike files exist and only one is read.
- **Safety fixes found by using it**: a page carrying a form token could be stored
  by a shared cache (now `private`); the response cache served signed-in pages when
  the session cookie was PHP's own; workers never noticed a rewritten PHP cache
  file; the admin page layout was compiled with the public site's template
  locations; request state outlived its request (function statics became class
  statics the worker resets). See [security defaults](../../specifications/6.0/security-defaults-2026-09.md).
- **Cache clears move directories aside** and a new `cache_cleanup` cronjob part
  removes expired view cache and cache-block files. See
  [Cache clears that move directories aside](../../features/6.0/cache-clear-rename-aside.md).
- **Configuration as a Debian Apache-style tree** (`/etc/vc`, `a2ensite`-style
  enable and disable verbs), `exp:velocity ssl show|renew`, `exp:velocity ext`,
  `@alias` tags for console commands (declared for `exp:vc`; not resolved on the current tree, see [the Velocity page](../../features/6.0/velocity-persistent-worker-server.md#other-commands)) and GNU or BSD option spellings.
- **Permanent order receipts** at `shop/orderreceipt/<token>`, and a fix for the
  basket emptying on Cancel at the confirm step. See [Order receipts](../../features/6.0/order-receipts.md).
- Every command-line script now starts with `#!/usr/bin/env <interpreter>` and is
  executable (66 files). Two private working notes were taken out of the repository.

## 25 to 26 September: more engines, DocBook, error pages

- **FrankenPHP and PHP's built-in server join Qbix as Velocity engines**, runnable
  side by side, each on its own port with its own pid file and logs and each
  serving only the assets the shipped rules list. FrankenPHP serves HTTPS by
  default with a self-signed certificate. `exp:velocity status` shows every address
  as a clickable URL for every engine. Everything Velocity writes lives under
  `var/vc/<engine>/`. See [FrankenPHP](../../bc/6.0/frankenphp.md).
- **Setup > Caches and System information** show the serving engine, OPcache and
  APCu, and can empty both.
- **View templates for the DocBook tags in rich text**, so imported DocBook
  content renders as HTML.
- **Server control commands**: `exp:webserver` (engine-agnostic front end),
  `exp:frankenphp` and `exp:solr`; see
  [Server control commands](../../features/6.0/web-server-and-solr-commands.md).
- **A site error page for fatal errors, uncaught exceptions and failed
  transactions**, 503 when the database cannot be reached ([behaviour changes](../../bc/6.0/behaviour-changes-2026-09b.md)).
- The engine package moved to its new name, `se7enxweb/exponential-velocity`.
- Order e-mail receipt links open from any browser for every order.

## 27 September: the longest day

Two hundred and five changes. In the order a reader will want them:

- **Faster pages**: a role-aware HTTP cache answers whole pages before the kernel
  starts, for signed-in visitors too (off by default); an SQL query cache for
  MySQL, PostgreSQL and SQLite answers repeated `SELECT`s until a write makes them
  stale (on the reference installation the front page renders in about 0.17 s instead of 0.6 s, and a
  rendered page used 303 ms CPU instead of 727 ms once Velocity's PHP got 256 MB of
  APCu); `[ServerSettings] Instances` runs several servers on the same ports so
  cached pages use more than one core; Setup > Caches and System information show
  both caches. See [HTTP cache](../../bc/6.0/httpcache.md) and
  [SQL query cache](../../bc/6.0/sql-query-cache.md).
- **Maintenance mode** (`php bin/php/maintenance.php`, **Setup > Maintenance**),
  used by the kickstarter and the web wizard so a site being installed never
  serves a half-built page. See [Maintenance mode](../../features/6.0/maintenance-mode.md).
- **Installation logs**: `var/log/setup.log` and a readable `error.log` while a run
  goes on. SQLite became the default database system of the wizard and the
  kickstarter; a kickstart no longer ends with a guessable administrator password;
  other primary languages install cleanly. See [Installing in one command](../../features/6.0/install-in-one-command.md).
- **Hardening sweep**: about sixty datatype and helper fixes (arrays posted as
  text, script URLs, directory parts in file names, header injection, INI
  injection), baseline security headers, a safe session cookie, uniform login and
  forgot-password answers, stricter Apache rules and the same static list for
  Velocity. See [Datatype and input hardening](../../specifications/6.0/datatype-input-hardening.md)
  and [Security defaults](../../specifications/6.0/security-defaults-2026-09.md).
- **A refused form is a 403 page, not a 500**: [form expired page](../../features/6.0/form-expired-page.md).
- **Exponential everywhere**: the version class, the example crontab, shipped
  settings, console and log messages, downloads, generated PDFs, outgoing requests
  and mail, translatable strings and the copyright page now say Exponential; old
  names stay as deprecated aliases. See [ExponentialSDK and exponential.cron](../../bc/6.0/exponentialsdk-and-exponential-cron.md)
  and [About and Copyright pages](../../features/6.0/about-and-package-pages.md).
- **Translations**: a finished `eng-US` translation, complete German, every
  visible admin and standard design text a translation string, and valid BCP 47
  `lang` values for twenty locales. See [Translations and languages](../../features/6.0/translations-and-languages.md).
- **REST under a persistent worker**: no "Cannot redeclare", 401 for a missing
  credential and for an unknown OAuth token on every server and on SQLite.
- `exp:cache` runs every Setup > Cache action from the command line, single pages
  of the static cache can be regenerated by path or node, and a siteaccess can use
  another siteaccess's extension settings (`ExtensionSettingsSiteAccess`).
- Velocity workers run as the site's user (`User`, `Group`), the response caches
  pause during maintenance, and Velocity sends the security headers and HSTS on
  every answer.

## Small changes explained

These changes have no page of their own. Each says what it does, why it helps and
how to see it.

- **`./console --version`, `--about`, `--copyright`** (27 September). Before the
  command name the console now answers GNU style: `--version` (also `-version`,
  `-v`, `-V`) prints the program, the Exponential release (for example
  `console (Exponential) 6.0.15stable`), the build and commit date, the
  installation, the Velocity release that comes with it, PHP and the system;
  `--about` and `--copyright` add the copyright, the GPL version 2 licence and the
  warranty text. After the command name the options belong to the command, and
  `-v` stays "verbose" for the scripts. Use it to put the exact release into a
  bug report: `./console --version`.
- **A failed query is logged once** (27 September). One failed statement used to
  give three or four entries in `var/log/error.log` (the driver's with the whole
  statement over a dozen lines, the schema layer's, the caller's, on SQLite PHP's
  own warning; MySQL wrote it twice). `eZDBInterface::failedQueryMessage()` now
  gives `Query failed: <reason>` and `Query: <statement on one line>` (cut after
  2,000 characters) for SQLite, MySQL and PostgreSQL. On SQLite the busy timeout
  is set before WAL mode, so a connection opened while another process held the
  database no longer failed at once with "PRAGMA journal_mode = wal; -- database
  is locked".
- **Absolute URLs keep the port you reached the site on** (22 September). An
  installation served through a front-end web server on 443 and directly on
  another port could only be right about one: switching language on
  `https://host:8080/...` sent the visitor to `https://host/...`, a different
  deployment with a different session and cache. `eZSys::serverURL()` keeps a port
  the request carries and consults `site.ini [SiteSettings] SSLPort` (default 443) only when the request
  names none (the case the setting was written for); the language switcher builds
  its destination from the target's `SiteURL` for siteaccesses that are not
  matched by URI. Check by switching language while browsing the port you use.
- **A saved INI setting stays inside the PHP comment** (24 September). The
  round-trip save (a setting changed in the admin or by `exp:ini set` in an
  `.ini.append.php` file) appended new variables after the closing `*/ ?>` line,
  outside the protected comment, so the value was never read back. The closing
  line is now set aside, new variables go after the block's last non-blank line,
  and the closing line is written last.
- **Imported DocBook content renders** (25 September). View templates exist for
  the DocBook tags in rich text, so content imported with DocBook markup shows as
  HTML. The tags are `emphasis`, `itemizedlist`,
  `orderedlist`, `listitem`, `literallayout`, `para`, `title` and `ezembed`, in
  `design/standard/templates/content/datatype/view/ezxmltags/` (check with
  `ls design/standard/templates/content/datatype/view/ezxmltags`).
- **Image XML that does not parse is no longer destroyed** (30 September). When
  the stored XML of an image attribute did not parse, `eZImageAliasHandler` read
  it as "no image" and at once stored an empty image over the row. That is what
  happened on Oracle when the client returned every CLOB longer than 2,015
  characters cut short: images lost their alias list on the first page view (the
  files stayed on disk). Text that does not parse is now read as no image and left
  in the database as it is.
- **The unique template operator** passes a value that is not an array through
  when compiled (`{ezini(...)|unique}` on an unset setting died with a
  `TypeError`; the uncompiled operator already did this).
- **Faster publish and admin pages** (30 September), all without a setting:
  the admin URL list (`url/list`, Setup > Link management) counts and lists the URLs of published
  content in 0.03 seconds instead of timing out (4,615 URLs took over two minutes
  on SQLite; it is driven from `ezurl` with an `EXISTS` test); a publish loads the
  settings of each cached siteaccess once for the request (112 loads and about
  6,000 INI files for one publish, 12 of its 14 seconds, now about 1.5 seconds);
  a siteaccess's extension settings siteaccess is read once per request (216
  parses saved per publish); the groups of a content class are read once per
  request (68 queries for one admin node view with `content.ini [ContentOverrideSettings] EnableClassGroupOverride=true`, shipped `false`),
  and every method that writes the table empties that cache. The values are kept
  per request start time, so a persistent worker starts every request empty.
- **Smaller fixes**: **Edit selected** and **Create multiple new** in the sub
  items list go to the admin siteaccess; admin error pages show their own error in
  the page title (the admin page layouts key the per-URI head on the error); fonts
  of an extension's design are served by the shipped `.htaccess` and Apache
  example; the default admin design's key files use relative paths; two
  parameters with a null default are typed nullable (no PHP 8.4 deprecation); GD
  image filters raise no `imagedestroy()` deprecation on PHP 8.5; a subtree count
  with a language no longer leaves the language set and finds a start node with no
  translation in it.
