# September 2026, first half (1 to 15 September)

Eighty-four changes to the root repository. The fortnight has one theme: make
the administration interface honest at scale, and give the people who run an
installation tools that show what is happening instead of buttons that claim
success. Every change below is in the complete record,
[ledger of exponential-root](../ledger/exponential-root.md), under
"2026-09"; changes without a story of their own are listed under
[Smaller changes](#smaller-changes).

No release tag falls in this period.

## In short

- Long lists in the administration interface are paged, sortable and sized by settings, so installations with thousands of roles or locations draw again.
- New tools show what is happening: a static cache generator, Preload Sites, a Cronjobs console, a RAD catalogue with wizards, and `expinfo`.
- PDF export, RSS (OPML, podcasts) and the shop basket address were repaired or made configurable; fresh installs no longer create a duplicate language or blank class names.
- Existing installations pick up the 6.0.0 to 6.0.15 database updates; upgrade steps are linked under each change.

## 1 to 2 September: knowing what is installed

- A fatal error when serializing empty relation list items is prevented
  (`00ca6dfbc2`).
- **`expInfo`**: a read-only PHP API and the `expinfo` template operator list the
  active and available extensions and their metadata, and the Setup >
  Extensions page uses it. See [expInfo operator](../../bc/6.0/expinfo-operator.md).

## 11 September: the basket gets a name you choose

The shop basket was hard coded as `/shop/basket/` in twelve places. It is now
`settings/shop.ini [BasketSettings] BasketViewName`, and the whole checkout
follows it (routing, redirects, form actions, breadcrumb, template lookup). A
shop account handler for the US address model (city instead of place, a phone
number kept) was added: `bcusauserShopAccountHandler`. See
[Shop basket view name](../../bc/6.0/shop-basket-view-name.md).

## 13 September: caches you can see, cronjobs you can run

- **Static cache that works.** The shipped `staticcache.ini` could never
  generate anything; its defaults were repaired, pages go to
  `var/<site>/static`, and Setup > Cache gained a crawl-driven generator with
  progress and a stop button. `.htaccess_root_static` and
  `doc/examples/staticcache_offload.conf` let the web server answer from the
  files. Read [Static cache generator](../../features/6.0/static-cache-generator.md)
  and [Static cache defaults](../../bc/6.0/static-cache-defaults.md).
- **Preload Sites** in the Setup module warms every page of a siteaccess with
  live progress, and was then made to stay inside the chosen site. See
  [Preload Sites](../../features/6.0/preload-sites-view.md).
- **Cronjobs console** at Setup > Cronjobs launches a cronjob part from the
  interface and follows its output; a reload no longer relaunches the job. See
  [Cronjobs console](../../features/6.0/cronjobs-console.md).
- **Installs repaired.** A duplicate `eng-US` language was created on every
  install, and every content class seeded by the base data got a blank name
  because it copied an `eng-GB` name that does not exist; both are fixed.
- The kickstarter summary now prints the finish time and elapsed duration, so
  two runs of the same `kickstart.ini` can be told apart
  (see [Kickstarter CLI](../../bc/6.0/kickstartercli.md)).
- `bin/shell/generatefilelist.sh --exclude=<value>` excludes extra paths when
  the file manifest is generated. A plain name excludes it wherever it sits, a
  bare glob such as `*.log` matches file names at any depth, anything with a
  slash or wildcard is a `find -path` pattern anchored at the root. May be
  repeated and combined with `--include`.
- The `expchangeclass` extension became a dependency, so content class
  conversion is available from the administration interface and the command
  line.
- Composer constraints for the theme and layouts packages moved to releases
  carrying the fixes (see Smaller changes).

## 14 September: PDF, RSS and the RAD tools

- **PDF export repaired and given a footer you word yourself.** See
  [PDF export](../../features/6.0/pdf-export.md) and the upgrade note
  [PDF export upgrade](../../bc/6.0/pdf-export.md). The 6.0.0 to 6.0.15 database
  updates for MySQL, PostgreSQL and SQLite were added so an existing
  installation takes the new columns without reinstalling.
- **Cronjobs page redesigned** into one line per cronjob grouped by part, and
  `runcronjobs.php` gained `--script=<file>`.
- **RSS.** The feed list is paged; OPML became an export format
  ([OPML exports](../../bc/6.0/opml.md)); Apple Podcasts became a format;
  output is escaped; feeds publish under the public address; two OPML outline
  faults were fixed (the Browse button answered 404, a chosen node was not
  shown). See [RSS](../../features/6.0/rss-podcast-and-feed-list.md).
- **RAD tools.** A catalogue of every extension point and wizards that write a
  working extension, growing from fifteen points to sixty-four of sixty-four, a
  survey of the extension surface (924, then 1737 points), and a health check
  that found a kernel fault stopping every payment gateway from loading. See
  [RAD tools](../../features/6.0/rad-tools.md).
- **Edit several items at once**: `content/multiedit`, from the sub items list
  and from search results; one form, published item by item. See
  [Editing several items at once](../../bc/6.0/multi-node-edit.md).
- **Locations tab paging and sorting** for items placed in thousands of
  locations, which could not draw at all before. See
  [Locations tab](../../bc/6.0/locations-tab-paging-and-sorting.md).
- **Removing a workflow actually removes it.** The removal branch read a post
  variable no form ever sent.
- **Setup > View settings** offers the commonly read ini files above a
  separator (`site.ini [SettingsViewSettings] CommonINIFileList[]`), because the
  drop-down runs to a hundred entries.
- The file consistency check on the system upgrade page stopped naming
  sixty-two files as altered (`share/filelist.md5` refreshed).

## 15 September: paging everywhere

- The preloader no longer reports a broken link on every page that no editor
  could find, and its report names the pages that link to each broken target.
- **RSS import cleanup** removes what an import created, as a script and a
  cronjob part ([RSS import cleanup](../../bc/6.0/cleanuprss.md)).
- **Paging for roles, policies and many lists**, with page sizes taken from
  `admininterface.ini [PaginationSettings]`. The role list shows the role id and
  sorts. See [Paging, sorting and page sizes](../../features/6.0/admin-list-paging.md),
  [Role and policy paging](../../bc/6.0/role-policy-paging.md) and
  [Where the page sizes live](../../bc/6.0/pagination-settings.md).
- Fixes found on the way: the cronjob page paged the wrong (empty) list; the
  package list drew every package on every page; item view tab counts loaded
  everything they counted.

## What the smaller fixes mean for you

These changes have no page of their own; here is what each one does and how to see it.

| Change | Before | Now | How to check |
|---|---|---|---|
| Relation list export (`00ca6dfbc2`) | Serializing a relation list item that had no related object id, or whose object was gone, ended in a fatal error on a method call on `null` | Such an item is skipped and the rest of the list is written | Code: `kernel/classes/datatypes/ezobjectrelationlist/ezobjectrelationlisttype.php`, the loop over `relation-item` that now `continue`s |
| Duplicate language on install (`615cf3e102`) | The base data seeded an `eng-US` language that the installer then created again, once per install | The seed no longer carries it (`share/db_data.dba`) | After an install, Setup > Languages lists `eng-US` once |
| Blank class names (`e5af863b50`) | Every content class seeded by the base data got an empty name, because the installer copied an `eng-GB` name that does not exist | The name is taken from a language that exists (`kernel/setup/steps/ezstep_create_sites.php`) | Admin > Setup > Classes after an install: every class has a name |
| Workflow removal (`0117d49a42`) | Pressing Remove on the workflow list removed nothing: the removing branch read a post variable no form sends | The branch reads the variable the form posts (`kernel/workflow/workflowlist.php`); two unguarded reads in a wait-until-date event and three hidden fields in the approve event template were tidied | Create a throwaway workflow, tick it, press Remove: it is gone |
| Common ini files (`c414d20dea`) | Setup > View settings offered one drop-down of about a hundred ini files in alphabetical order | The commonly read files come first, above a separator | Setting below |
| Content class conversion (`3e5698ca99`) | Conversion needed the extension installed by hand | `se7enxweb/expchangeclass` is a root dependency (`composer.json`, constraint `~1.0.5` at HEAD) | `grep -n expchangeclass composer.json` |
| US address handler (`90ba6d10a8`) | Only the standard address model | `bcusauserShopAccountHandler` (`kernel/classes/shopaccounthandlers/bcusausershopaccounthandler.php`) reads and writes `city` with a fallback to `place`, and keeps a phone number | See [Shop basket view name](../../bc/6.0/shop-basket-view-name.md) |

The common ini files setting:

| File | Block | Key | Default | Scope |
|---|---|---|---|---|
| `settings/site.ini` | `SettingsViewSettings` | `CommonINIFileList[]` | `site.ini`, `content.ini`, `design.ini`, `override.ini`, `menu.ini`, `contentstructuremenu.ini`, `module.ini`, `template.ini`, and more | global |

A file named in the list that the installation does not have is passed over. Add your own with
`CommonINIFileList[]=myextension.ini` in `settings/override/site.ini.append.php`.

Excluding paths from the file manifest, for example before generating a manifest of an installation with log files
in it:

```bash
bash bin/shell/generatefilelist.sh --dry-run --exclude='*.log'
```

The dry run writes nothing; it prints how many hashes it would write to `share/filelist.md5`. See
`bash bin/shell/generatefilelist.sh --help` for `--include`, `--list`, `--untracked` and `--extensions`.
