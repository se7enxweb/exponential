# admininterface.ini [WindowControlsSettings]

The block `[WindowControlsSettings]` of `settings/admininterface.ini`, with 2 setting(s).

> Settings used by window controls template  

Never edit `settings/admininterface.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/admininterface.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/admininterface.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/admininterface.ini.append.php` in an extension (read when the extension is active).

## HiddenTabs

> Additional tabs the node view leaves out, whatever AdditionalTabs\[\] says: a  
> siteaccess cannot take a tab out of AdditionalTabs\[\] that an extension appends  
> (extension settings are read after the siteaccess's). The editor siteaccess  
> hides the Layouts tab with it.  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/admininterface.ini.append.php
[WindowControlsSettings]
# an empty "HiddenTabs[]" first replaces the shipped list; without it the items are added
HiddenTabs[]
*/ ?>
```

## AdditionalTabs

> List of additional tab identifiers  
> AdditionalTabs\[\]=customtab  
> The audit trail of a node (doc/en/us/bc/6.0/audit.md, "Placement"), only with audit/read  

Default: a list of 3: `roles`, `policies`, `audit`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/admininterface.ini.append.php
[WindowControlsSettings]
# an empty "AdditionalTabs[]" first replaces the shipped list; without it the items are added
AdditionalTabs[]
AdditionalTabs[]=roles
AdditionalTabs[]=policies
AdditionalTabs[]=audit
*/ ?>
```
