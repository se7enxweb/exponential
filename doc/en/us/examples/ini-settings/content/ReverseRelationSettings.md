# content.ini [ReverseRelationSettings]

The block `[ReverseRelationSettings]` of `settings/content.ini`, with 1 setting(s).

Never edit `settings/content.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/content.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/content.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/content.ini.append.php` in an extension (read when the extension is active).

## ProviderClassList

> Classes that report references kept outside ezcontentobject\_link, for the check of \[RemoveSettings\] and  
> \[HideSettings\] ReverseRelationCheck. Each answers the static method reverseRelations( array $paths, int $limit )  
> (see Exponential\\Service\\ReverseRelationCheck::providerReferences()). A class that does not exist is skipped.  
> Extensions add theirs in their own content.ini.append.php, e.g. ProviderClassList\[\]=expLayoutsReverseRelationProvider  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/content.ini.append.php
[ReverseRelationSettings]
# an empty "ProviderClassList[]" first replaces the shipped list; without it the items are added
ProviderClassList[]
*/ ?>
```
