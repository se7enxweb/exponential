# content.ini [HideSettings]

The block `[HideSettings]` of `settings/content.ini`, with 3 setting(s).

Never edit `settings/content.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/content.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/content.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/content.ini.append.php` in an extension (read when the extension is active).

## RootNodeList

> Example:  
>
> RootNodeList\[\]  
> RootNodeList\[\]=2  
> HideDateAttributeList\[\]  
> HideDateAttributeList\[article\]=hide\_date  
>
> List of root nodes where nodes can be hidden.  

Default: an empty list.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/content.ini.append.php
[HideSettings]
# an empty "RootNodeList[]" first replaces the shipped list; without it the items are added
RootNodeList[]
*/ ?>
```

## ReverseRelationCheck

> What content/hide and "Hide selected" of the sub items list do before hiding a node that other objects  
> point at (what the hide takes away entirely, counted as for \[RemoveSettings\] ReverseRelationCheck), or whose  
> object has further locations. The hidecron cronjob is not affected. doc/en/us/features/6.0/reverse-relation-check.md  
>  disabled - no check: the hide is done at once, as before  
>  warn     - (default) a confirmation page lists the references and the further locations first; a hide  
>             without either is done as before  

Default: `warn`.

```ini
<?php /* #?ini charset="utf-8"?
# settings/override/content.ini.append.php
[HideSettings]
ReverseRelationCheck=warn
*/ ?>
```
