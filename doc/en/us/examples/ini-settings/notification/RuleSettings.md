# notification.ini [RuleSettings]

The block `[RuleSettings]` of `settings/notification.ini`, with 5 setting(s).

> IncludeClasses\[\]=article  
> IncludeClasses\[\]=file  

Never edit `settings/notification.ini` itself: an update replaces it. Put the settings you change in an override, which wins over the shipped file:

- `settings/override/notification.ini.append.php` for every siteaccess,
- `settings/siteaccess/<siteaccess>/notification.ini.append.php` for one siteaccess,
- `extension/<extension>/settings/notification.ini.append.php` in an extension (read when the extension is active).

## RepositoryDirectories

```ini
<?php /* #?ini charset="utf-8"?

# an empty "RepositoryDirectories[]" first replaces the shipped list; without it the items are added

## LimitDeleteElements

> Maximum number of notification digest elements removed in one query.  
> This is needed to prevent exceeding DBMS limits

Default: `50`.

*/ ?>
```

## RetryHours

> How many hours a notification that the mail transport did not take is tried again, at every run, before it is given up

Default: `72`.
