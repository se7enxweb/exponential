# Exponential 6.0.15

Not released yet. The 6.0.15 line follows v6.0.14 (2026-06-07); no tag `v6.0.15` existed on 2026-10-02. This page
lists what the line contains on that date.

Read this page if you run 6.0.14 or older and plan to move to the current code, or if you want to know what the
line brings. It is long because the line is: four months of work. Use the sections by period.

## Upgrading

Follow the [Upgrading guide](../../guides/upgrading.md), part C. Then read the checklist of each period you pass,
in this order:

1. [Behaviour changes of July and August 2026](../../bc/6.0/behaviour-changes-2026-07-08.md)
2. [Behaviour changes of 16 to 30 September 2026](../../bc/6.0/behaviour-changes-2026-09b.md)
3. [Behaviour changes of 1 to 2 October 2026](../../bc/6.0/behaviour-changes-2026-10.md)
4. [Upgrade notes: e-mail preferences and the mail gate](../../bc/6.0/mail-preferences.md)

The database update for the line is `update/database/<engine>/6.0/dbupdate-6.0.0-6.0.15.sql`, followed once by
`php update/common/scripts/6.0/createaudittables.php`.

### Updated

### Added

- **Notification status page** (Setup, Notification) with pending events, digest items, subscriptions, the last runs and a
  problem list; **Run now** and a dry-run preview as background jobs; cleanup of handled events, old events and

- **Commands** `exp:notification:status`, `run`, `events` and `subscriptions` (aliases `exp:notify:*`), with `--dry-run`,

- Confirmation pages for adding and removing a notification, and guides for administrators and developers, the
  settings reference and the command reference.
- **Failed mail is kept**: a notification the mail transport refuses stays in the queue and is tried again at every run for
  `[RuleSettings] RetryHours` (default 72); the run record, `exp:notification:run` (exit code 1) and the status page report it, and a message older than
  that is given up and counted.

- Fixes: the digest settings are validated and a user without a settings row can save them, a single address no longer

## 4 October 2026: e-mail preferences and consent

The upgrade checklist is [Upgrade notes: e-mail preferences](../../bc/6.0/mail-preferences.md). The system is described in
[the user's guide](../../features/6.0/mail-preferences.md), [the administrator's guide](../../guides/mail-preferences-administrator.md),
[the developer's guide](../../guides/mail-preferences-developer.md), [the specification](../../specifications/6.0/mail-preferences.md)
and [the law checklist](../../specifications/6.0/mail-preferences-compliance.md) (CAN-SPAM, GDPR and ePrivacy, CCPA/CPRA,
CASL, RFC 8058).

### Added

- **E-mail preferences**: one page (`/mailpreferences/settings`, also in the administration under **My e-mail
  preferences**, and without login by a personal link) where every person turns each optional kind of e-mail on or off,
  chooses how often, turns all optional e-mail off with one button, sees the history of their choices and downloads their
  data as JSON or CSV. Every optional kind is off until the person turns it on. Essential mail (account security, orders,
  legal notices, admin alerts) is listed and always sent.
- **The mail gate** in `eZMailTransport::send()`, for every transport: mail declares a category with
  `eZMail::setCategory()`; optional mail goes only to people who turned it on, one mail each, with a footer (why, one-click
  unsubscribe, preferences, the organisation and its postal address) and the RFC 8058 headers `List-Unsubscribe` and
  `List-Unsubscribe-Post`. Mail without a category is sent as before and counted.
- **Unsubscribe in one click** (`/mailpreferences/unsubscribe/<token>`), also from the mail program's own button; a page
  opened by a link changes nothing until its button is pressed. **Double opt-in** for newsletters, offers and a new e-mail
  address. **Send me a link** for people without an account.
- **Consent log** of every change with the exact text shown, the source, the IP address and the acting user; **suppression
  list** stored as salted hashes; links encrypted with AES-256-GCM under a site secret; export and erasure that keeps the
  proof of a withdrawal; retention by the cronjob part `mailpreferences` (group `infrequent`).
- Administrator's pages under **Setup > E-mail preferences**: status, categories (create, rename, describe), suppression
  list, consent log with filters and CSV export, a user's preferences. Policies `mailpreferences/administrate` and
  `mailpreferences/export`.
- Commands `exp:mail:status`, `exp:mail:preferences`, `exp:mail:suppression`, `exp:mail:consent`, `exp:mail:gate`.
  [Command reference](../../specifications/6.0/mail-preferences-cli.md).
- Unticked boxes for the optional kinds on the registration form; English and German texts.
- Tables `expmail_category`, `expmail_preference`, `expmail_consent_log`, `expmail_suppression`, `expmail_pending` in the
  kernel schema and the database update.
- Tests: `MailPreferencesCoreTest` (20 cases of the core and the gate) and `MailPreferencesComplianceTest` (one case per
  law requirement of the checklist), live style with the file transport and `.invalid` addresses.

### Updated

- Optional mail to several recipients is sent as one mail per recipient (`[GateSettings] SplitRecipients`).
- The profile, the notification settings, the current user box and the menus link to the e-mail preferences.
- The text footer of optional mail keeps its line breaks: each link ends its line.
- Collaboration mail follows the frequency chosen on the preference page: daily or weekly it goes into the digest, which
  now has a collaboration part, and the digest lists its items again (its loops and includes rendered nothing).
- A new e-mail address of an account (user/edit, the administration's edit, the account services) takes effect only once
  it is confirmed from the new mailbox, and the old address gets a notice (`[EmailChangeSettings] Confirm`).
- The downloads of a person's e-mail data, the consent log and suppression list exports and the RFC 8058 one-click
  answer end the request through one helper (`MailPreferencesPage::sendResponse()`). Under Velocity they never answered
  (504) although the change was saved: the loop that emptied the output buffers did not stop at the worker's own buffer.
  The setup views that stream (preloader, static cache, cronjob log) and the Ajax answer of the cronjob console had the
  same loop; all of them now use `eZExecution::discardOutputBuffers()`.
- The history shows a waiting e-mail address change as **E-mail address: New address asked for, waiting for
  confirmation**, no longer as "All optional e-mail".
- The footer and the confirmation and "send me a link" mails name the public site (the siteaccess of the request when
  it is public, else the default siteaccess), never an administration siteaccess, also from a command or a cronjob;
  `OrganisationName` still wins when set.
- Closed gaps of the law checklist: `DefaultOn=true` of an optional category is treated as off and shown on the status
  page unless `[CategorySettings] AllowDefaultOn=enabled`; removing an account erases its e-mail preferences and
  anonymises its consent log (the withdrawals stay as proof, the suppression list stays); optional mail with an empty
  From gets `[MailSettings] EmailSender` or `AdminEmail` (logged, and not sent without either); the footer and the
  preference page link the privacy notice (`[FooterSettings] PrivacyURL`, else the node of menu.ini `[SiteInfo]
  PrivacyPolicyID`); unsubscribe and manage links never live shorter than 60 days.
- Tests: `MailPreferencesHardeningTest` (MPH-01 to MPH-09), including the one-click POST and the downloads over HTTP on
  the site's web server and on Velocity.

## 5 October 2026: PHP 8.0 is the oldest supported version

PHP 8.0, the stock PHP of Red Hat Enterprise Linux 9, runs the kernel and the shipped extensions again (Velocity
still needs 8.1). Details, the full list of findings and the RHEL 9 notes: [PHP 8.0 support](../../bc/6.0/php-8.0-support.md).

### Added

- `lib/phpcompat.php`: `array_is_list()` for PHP 8.0, read by `autoload.php` only on PHP older than 8.1.
- The Quality workflow's job `php80`: `php -l` with PHP 8.0 on every PHP file, a production install with 8.0 and the
  boot smoke test `tests/bin/bootsmoke.php` (every kernel and extension class, the compatibility functions, a
  template with `wash`); `make lint80` and `make lint80-all`.

### Updated

- `htmlspecialchars()` and the other HTML escaping functions get the PHP 8.1 default flags explicitly in 28 kernel,
  library, ezjscore, ezoe and expservices files, the `wash` operator and the simple tags operator included: single
  quotes are escaped on PHP 8.0 as on 8.1 and later. Clear the template cache once after upgrading.
- The CSV export of sub-items writes its `"\r\n"` lines on PHP 8.0 too (`fputcsv()` has no `$eol` there).
- The OAuth authorize view passes `implode()` its arguments in the order PHP 8 requires; the LDAP login no longer
  calls `crypt()` without a salt.
- The checks of pull request #113 test PHP 8.0 instead of 8.1: `phpcs.xml.dist` `testVersion` `8.0-`, the pre-commit
  hook (`EXP_PHP80`), `composer.dev.json` platform PHP 8.0.30.
- README, the PHP 8 page, the console and CI pages state PHP 8.0 as the minimum.

## 5 October 2026: related objects sorted by class name

### Updated

- Fixed: `eZContentObject::relatedObjects()` (and the fetches `related_objects` and `reverse_related_objects`) sorted
  by `class_name` no longer fails on MySQL and PostgreSQL with "Unknown column 'ezcontentclass.id' in 'on clause'":
  `ezcontentclass` is now the last table of the FROM list, the one the class name join can see. SQLite was not
  affected.

## 5 October 2026: database sessions

### Updated

- Fixed: `ezpSessionHandler::setSaveHandler()` no longer calls `session_module_name( 'user' )`, which throws a
  `ValueError` on PHP 8 and stopped every request of an installation with `[Session] Handler=ezpSessionHandlerDB`.
  See bug 4 on [the session handler page](../../bc/6.0/ezpsessionhandlerdb-php8-bugfix-and-tests.md).

## 5 October 2026: view cache files of cache_ttl=0

### Updated

- Fixed: a node view whose template sets `cache_ttl` to 0 no longer stores the whole page in its view cache file. The
  file keeps only the no-cache advice (`no_cache`, `cache_ttl` 0, a few bytes), which the next requests still read to
  generate the page without the cache lock and without storing it. The number of files stays the same: one per cache
  key, as before.
