# Exponential 6.0.0

Released 2024-01-01. Tag `v6.0.0`.

Read this page if you move a 5.4 or 5.90 installation to Exponential 6, or want to know where the 6.0 line starts.

## In short

The first release of the 7x line. Exponential 6.0.0 takes the last open source legacy code base of the former
product forward on current PHP:

- the setup wizard no longer prints PHP 8 errors;
- no page of the wizard points to the closed vendor's servers any more;
- the installation is done with Composer.

## Upgrading

No schema change is needed from 5.4. One update script records the new version in the `ezsite_data` table:

| Database | Script |
|---|---|
| MySQL or MariaDB | `update/database/mysql/6.0/dbupdate-5.4.0-6.0.0.sql` |
| PostgreSQL | `update/database/postgresql/6.0/dbupdate-5.4-to-6.0.sql` |

```bash
mysql -u USER -p DATABASE < update/database/mysql/6.0/dbupdate-5.4.0-6.0.0.sql
```

What the scripts contain: the MySQL script is `SET storage_engine=InnoDB;` followed by two `UPDATE ezsite_data`
statements. They set the row `ezpublish-version` to `6.0.0` and the row `ezpublish-release` to `1`. The PostgreSQL
script holds only the two `UPDATE` statements. The row names keep their historic spelling on purpose; they are
identifiers.

MySQL 5.7.5 removed the `storage_engine` variable in favour of `default_storage_engine`. If your server rejects the
first statement, run only the two `UPDATE` lines. Check your server version with `SELECT VERSION();`.

Check the result:

```sql
SELECT name, value FROM ezsite_data WHERE name LIKE 'ezpublish-%';
```

Expected: `ezpublish-version` is `6.0.0`, `ezpublish-release` is `1`.

A later script, `update/database/mysql/6.0/dbupdate-6.0.0-6.0.15.sql` (and its PostgreSQL twin), exists for the
6.0.15 line. The whole path is in the [Upgrading guide](../../guides/upgrading.md).

## Updated

- The object relation class attribute no longer fails when no default selection node was chosen (upstream pull
  request #40, the first merged change of the fork). (`2ddbc4c624`)
- The HTTP and cookie date helpers in `lib/ezlocale/classes/ezdateutils.php` build the date string without letting
  `gmdate()` interpret the day and month names. This also fixes wrong date and time attributes after a package export
  (`contentobject.xml`). Upstream pull request #41. (`b2af30cd2c`, `8df0f2cd19`)
- The extensions that the distribution installs or suggests changed. See
  [What a new installation comes with](../../features/6.0/default-extension-distribution.md). (`f2e0cc863a`,
  `c39efa3c63`, `45e5c69d15`, `fb9f17ba4c`, `1d5de8bf36`)
- The setup wizard no longer stops with a fatal error on PHP 8. See [PHP 8 support](../../bc/6.0/php8.md). (`06eca74187`)
- `package.ini` names the new package server addresses and vendor. (`12ce4a8168`)
- The default package installation in the setup wizard moves past every step again. (`4233c84a04`)
- The links of the registration templates point to the new addresses, and a typo in one of them is fixed.
  (`c25d9a4386`, `3378ca6176`)
- `eZTemplateForFunction` works on PHP 8. See [PHP 8 support](../../bc/6.0/php8.md). (`d6d7837233`)
- The installer's autoload code no longer prints error text during the installation. (`634f00704a`, `1558406cbc`)
- The footers and copyright of the admin and standard designs carry the 7x links. See
  [The product is called Exponential](../../features/6.0/rebranding-to-exponential.md). (`2a37bcbe2a`)
- The documentation links in the setup wizard point to the new documentation. (`7286590cea`)
- The edition text and version alias name the 6.0 release. (`ab10c96a7e`)
- The dashboard no longer shows the community activity block, which did not work any more. (`0c9d42ba5e`)
- The maintenance dashboard names 7x as maintainer. See
  [The product is called Exponential](../../features/6.0/rebranding-to-exponential.md). (`fcf96edc79`)
