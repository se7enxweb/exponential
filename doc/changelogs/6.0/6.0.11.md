# Exponential 6.0.11

Released 2025-12-30. Tag `v6.0.11`.

Read this page if you move to PHP 8.5, send notification mail, or count page views.

## In short

PHP 8.1 up to PHP 8.5 are covered: return type attributes, declared properties, nullable types, and Zeta Components
that support 8.5. Also new: a default `robots.txt`, notification mail sent to the To field instead of Bcc, and a fix
for the view count cronjob.

## Upgrading

No action needed. If you keep your own `robots.txt`, compare it with the new default; see
[A useful robots.txt out of the box](../../features/6.0/robots-txt.md).

## Added

- A default `robots.txt`, with a block that keeps search, print layout, media and test areas out of search
  engines. See [A useful robots.txt out of the box](../../features/6.0/robots-txt.md). (`f93362f6b4`, `185ddce843`)

## Updated

- Notification mail is sent to the To field instead of Bcc, which some mail servers refuse. (`11dfa2e178`)
- The `updateviewcount` cronjob works in default installations. (`8bffd7b08a`)
- Debug log entries carry more context (`lib/ezfile/classes/ezlog.php`), taken over from a community fork. See
  [Debug output improvements](../../features/6.0/debug-output-improvements.md) for the debug switches. (`881a280153`)
- The admin dashboard logo no longer hides the product name. (`86e0d4988b`)
- PHP 8.1 to 8.5 compatibility. See [PHP 8 support](../../bc/6.0/php8.md).
  - `#[ReturnTypeWillChange]` on the methods of SPL interfaces (PHP 8.1). (`a075afe4d6`)
  - Declared public properties instead of dynamic ones, also in `eZURL` and the SOAP response
    class. (`cb6d3e2435`, `8ad71d8a79`, `d806722a80`)
  - Nullable types for PHP 8.5. (`ea660c8371`, `0d035b6723`)
  - Zeta Components updated to releases that support PHP 8.5; the README documents PHP 8.5. (`4db16d95c3`,
    `27ed271f3d`)
  - `ezldapuser` no longer uses `utf8_decode`, deprecated in PHP 8.2. (`a5199cc8dc`)
  - No fatal error from the `ezmatrix` datatype or the collaboration module view. (`f433a08cf9`, `1ba06942c3`)
  - An empty string is no longer passed as null to `mysqli_real_escape_string` (`ezmysqlidb.php`) or `preg_match`
    (`ezuri.php`), `eZPathElement` declares its properties, and the template compiler and multipass parser no longer raise a chain of warnings when content
    is edited. (`ff023c8e5f`, `569cea280f`, `96ee5aa258`, `dc2440c8da`)
  - Further fixes. (`b13f305ac8`, `7e0a68ee94`)
- The `data_text` of a content attribute is an empty string instead of null (PHP 8 deprecations), and `ezmatrix`
  guards its XML parsing (upstream pull request #54, also merged into the main branch). (`9443fed1d7`, `f821ec15c3`)
